## 二之二、quantdash 五项功能：双轨并存（2026-09-24 派活中）

用户裁定后，这五项**不再是"去重后只留一份"**，而是本轨（自家口径，`analytics.*`）与 **qd 轨**（quantdash 口径，新 schema `qd`）**并排显示**。差异本身就是要给用户看的信息。

契约文档（两份，两边共用）：

| 文档 | 管什么 |
|---|---|
| `数据加工工作指南/09-quantdash逻辑规格.md` | 算什么、怎么算、存哪：全部阈值与公式、输入可行性矩阵、`qd` schema 9 张表的建表清单与主键、**42 处禁止复现的伪造点（带 quantdash 文件:行 出处）**、验收清单 |
| `页面展示工作指南/02-quantdash逻辑双轨展示.md` | 怎么摆：双轨视觉区分、三个 stage 列一起显示、`seal_time_available` 与 `leader_tie_break` 必须暴露、`deviation[]` 原样透出、接口契约 |

三条红线：① **PolyForm Noncommercial → 一行源码都不许抄**，只可重实现算法口径并标注出处；② **口径照搬，缺陷不搬**（42 处伪造点一律写 NULL + 记 `deviation`，全库不许出现常量 `5100`、不许 random 参与计算）；③ **写权限**：YuanShan 只有只读 `ft_reader`，DDL 与写库只能在 FinanceTool 侧。

两个关键实测约束（决定了哪些能算）：

- **封板时间历史不可得**：`market_data.stock_minute` 只有 **2026-09-22 一天**（1 分钟 226 万行 / 5 分钟 45 万行）。所以 `first_seal_time` 除该日外全 NULL，龙头并列时改按成交额排序并落 `leader_tie_break` 字段明示。quantdash 在这种情况下**用哈希函数编造封板时间**（D-28），我们不跟。
- **quantdash 自己有三套互相矛盾的情绪阶段阈值**（前端总览 / MCP / 飞书）。这不是我们要修的 bug，是要如实呈现的事实 → 存 `stage_ui` / `stage_mcp` / `stage_feishu` 三列，都算，不一致时页面打 ⚠。

## 四、四份指南的分工约定

| 指南 | 管什么 | 不管什么 |
|---|---|---|
| 数据获取工作指南 | 每类数据**从哪个源、走哪条代码路径**拿到；源的存活状态 | 字段口径怎么算 |
| 数据加工工作指南 | **口径契约**：判据、复权、分母、未来函数、质量规则 | 从哪取 |
| 系统配置工作指南 | 启停、端口、进程树、依赖与环境、测试基线 | 业务语义 |
| 页面展示工作指南 | 数据到界面上的呈现纪律（可用性/单位/打标/不造假） | 取数与计算 |
