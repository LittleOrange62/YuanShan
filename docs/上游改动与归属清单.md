| 义务 | 原文出处 | 本机现状 |
|---|---|---|
| ① 分发时随附许可证文本 | Apache §4(a)、MIT「shall be included in all copies」 | **已尽**：根 `LICENSE` + `docs/upstream/Research-LICENSE.txt` + `backtest/LICENSE.upstream` |
| ② **改过的文件要带显著声明说明你改了** | Apache §4(b) | **本轮起部分补齐**（见§三），其余待补（见§四） |
| ③ 保留版权/许可/归属声明与 NOTICE | Apache §4(d)、MIT | **已尽**：`backtest/NOTICE.md`、`research_data/NOTICE.md` 未被删改，归属表仍在 |

一句话结论：**用他的代码本身没有法律风险**，风险只在上面这四条没做到；而其中真正缺的只有第②条，补它的成本是加注释，不是重写。

## 四、还没逐个声明的（明说，不含糊）

上游原文件被本机改过、但**还没在文件头写声明**的量很大，粗测：`duanxian/` 106 个 .py 里约一半是上游原文件（其中又有一批接了本机 PG）、`review_agent/` 25 个、`vr/` 其余 15 个模块、`scripts/` 其余 11 个、`frontend/src/pages/` 与 `components/` 里原有那批屏、`tests/` 141 个里的原有用例。

可复跑的清点命令（列出"看起来是上游原文件、但内容里引用了本机子系统"的候选）：

```bash
cd /d/finance/YuanShan
for f in duanxian/*.py vr/*.py review_agent/*.py scripts/*.py; do
  n=$(grep -c -E "analytics\.|duanxian\.pg|ingest\.jobs|/api/quant|LOOP_JOBS|mcp_service|stock_daily" "$f")
```

补声明的动作本身是纯注释，代价只有一条：**改了 `frontend/` 下的文件就会让 doctor 的「安装与源码一致」转红**，需要重跑 `scripts/setup`（含 `npm ci`，慢网要等 8~12 分钟）或"重建 + 落指纹"才复绿 —— 所以要挑没有别的会话在改前端、且不在长跑作业窗口里的时段批量做，一批做完一次 setup，别一天红十次。

## 五、判不出归属时怎么办（重要）

- **mtime 不能当归属证据。** 建档时实测过两个反例：`app/tdx_client/reset.py` 的 mtime 是 09-25，看着像"上游老文件"，其实整目录 `app/` 都是本机 09-26 写的；`ingest/` 139 个文件里 107 个日期"很旧"，同样整目录是本机新增。**任何按日期切出来的"上游占比"都是假数**。
- 唯一能精确切分的办法是拿上游发布包逐文件比对：本仓库不是 git 项目，也没留 v1.1.0 的原始压缩包。要做就一次做干净 —— 下载 `vibe-astock v1.1.0` 的 Release 源码，与本仓库 `diff -rq`，产出「哪些文件同名存在（=继承，可能改过）／哪些文件只在本仓库（=本机自写）」。这是**待办，不是已完成**。
- 在比对结果出来之前，判不出的文件一律按**上游许可**处理，本机那份非商业声明不作扩张主张（`LICENSE.local.md` §四 就是这条）。

## 六、不许破的纪律

1. **新增代码一律落在本机层**（`app/`、`ingest/`、`duanxian/*_view.py` 这类读数层、`frontend/src/components/quant|lib` 新增件、`app/db/sql/`）。上游占比靠"不再往上加"往下走，比一次性重写有效。
2. **不要把衍生文件改成"本仓库整体非商业"**。Apache/MIT 授予下游的权利不会因为我们加了注释就消失；能主张非商业的只有本机自己写的部分。
3. **不要动 `backtest/NOTICE.md`、`research_data/NOTICE.md`、`LICENSE`、`docs/upstream/Research-LICENSE.txt`** 里的归属与版权文本。
4. **商标**：对外只写 YuanShan；上游作者与项目名只出现在许可、NOTICE 与这份清单里（README 末行的"上游作者"署名属于该保留的归属，不是背书）。
5. 改 `frontend/` 下任何文件后，**当场把「安装与源码一致」复绿**（`scripts/setup`，或 `npm --prefix frontend run build` + 重落 `.local/setup.json` 指纹），别把这个红留给下一个启动服务的人 —— `manage.py start` 遇到硬项红会**拒绝启动**。
