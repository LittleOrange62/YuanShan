# 02 · 盘后数据下载与入库

前置：[01-通达信启动与登录.md](01-通达信启动与登录.md) 的完成态全部打勾。

> 本文脚本路径全部相对项目根 `D:\finance\YuanShan`，开跑前先 `cd /d D:\finance\YuanShan`。
> 旧的操作/同步/校验脚本已归档在本项目的 `ingest\legacy\` 下，可以直接跑；
> 入库链是 `ingest/jobs/` 下的模块，跑法 `python -m ingest.jobs.<名>`。

**核心事实**：登录后通达信只**自动**同步指数行情。**个股盘后日线和分钟线必须手动触发下载**，
路径是顶部菜单 `TQ策略` → `TQ数据设置` → `盘后数据下载`。

## 步 2 · 第一趟：下载日线

在 `TQ数据设置` 窗口里：

1. 切到 **`盘后数据下载`** 页
2. 勾选 **`日线和实时行情数据`**
3. 点 **`开始下载`**

### 定位这三个控件

```powershell
# 先拿到 TQ数据设置 窗口的 hwnd（从 list_all_windows.py 的输出里找）
$hwnd = <TQ数据设置的hwnd>

# 递归列出它所有子控件：hwnd | class | text | rect
powershell -File "ingest\legacy\02_通达信操作\child_enum.ps1" -Hwnd $hwnd
```

从输出里找：

- `日线和实时行情数据` → class 通常是 `Button`（Win32 复选框也是 Button 类，靠 style 区分）
- `开始下载` → class `Button`
- 页签 → class `SysTabControl32` 或自绘控件

### 点击控件

```powershell
# 对按钮 hwnd 发 BM_CLICK（推荐，不需要窗口在前台）
powershell -File "ingest\legacy\02_通达信操作\btn_click.ps1" -Hwnd <按钮hwnd>
```

`btn_click.ps1` 支持两种发送方式：`BM_CLICK`，以及 `WM_LBUTTONDOWN` + `WM_LBUTTONUP`（自绘控件不吃 BM_CLICK 时用）。

### 勾选状态要验证，不能假设

复选框是"切换"语义 —— **点一下不等于勾上，可能是取消勾选**。点之前先读状态：

```powershell
# UIA 路线能直接读 Toggle 状态
powershell -File "ingest\legacy\02_通达信操作\uia_dump2.ps1" -TargetPid (Get-Process TdxW).Id
```

Win32 路线用 `BM_GETCHECK`（0x00F0），返回 1 = 已勾选。

**成功标志**：`日线和实时行情数据` 处于已勾选态，且点完 `开始下载` 后出现
标题含 `盘后数据下载` 的进度窗口。

## 步 3 · 等第一趟下载完成

**不要 `sleep 600`。** 用双重判据：

### 判据 A：进度窗口消失

```powershell
python "ingest\legacy\01_数据同步\download_monitor.py" 900
```

它每 5 秒枚举窗口，匹配 `盘后数据下载` / `下载完成`，窗口消失就返回。

**这个脚本的缺陷**：只盯 `sh600367.day` 一只票判文件变化。**该票停牌当天就会误判**。所以必须配判据 B。

### 判据 B：多只票的 .day 最后一条日期 == 目标交易日

沪、深、京各抽 3 只，全部到位才算完成：

```powershell
cd D:\finance\YuanShan
$env:PYTHONIOENCODING='utf-8'
$code = @'
from app import config
from app.ingest.tdx_binary import parse_day
from app.db import engine

target = engine.scalar('SELECT max(calendar_date) FROM reference_data.trade_calendar WHERE is_open')
print('目标交易日（来自 reference_data.trade_calendar）:', target)

samples = {
    'sh': ['sh600519.day', 'sh601318.day', 'sh688111.day'],
    'sz': ['sz000001.day', 'sz002594.day', 'sz300750.day'],
    'bj': ['bj920000.day', 'bj830799.day', 'bj832000.day'],
}
ok = True
for mkt, names in samples.items():
    for n in names:
        p = config.VIPDOC_DIR / mkt / 'lday' / n
        if not p.exists():
            print(' ', n, '文件不存在（跳过）')
            continue
        bars = list(parse_day(p))
        last = bars[-1].trade_date if bars else None
        flag = 'OK ' if last == target else 'OLD'
        if last != target:
            ok = False
        print(f'  [{flag}] {n:16s} 最后一条 {last}')
print('全部到位' if ok else '还有票没更新到目标交易日')
'@
$code | python -
```

**成功标志**：抽样票全部 `OK`。

**为什么用交易日历而不是 `date.today()`**：周末、节假日、以及盘后下载前的时段，
`today()` 都不等于最新交易日。旧脚本 `tdx_data.py check` 用"距今 ≤2 天算最新"，
**周一早上必然误判**。

**失败表现**：
- 进度窗口早就没了但日期还是旧的 → 下载失败且无报错，重跑步 2
- 部分票 OK 部分 OLD → 下载中断了，重跑步 2（通达信是增量续传，不会重复下）
- 出现"通达信信息"弹窗挡住进度窗 → 按 [01 步 4](01-通达信启动与登录.md#步-4--关闭登录后的弹窗) 关掉

## 步 4 · 第二趟：下载分钟线

**必须等第一趟完全结束再开第二趟**，两趟并行会互相抢连接。

回到 `TQ数据设置` → `盘后数据下载`：

1. 选中页签 **`沪深京分钟线:沪深京日线`**
2. 勾选 **`1分钟线数据`**
3. 勾选 **`5分钟线数据`**
4. 点 **`开始下载`**

定位与点击方法同步 2（`child_enum.ps1` 找控件 → `btn_click.ps1` 点击 → 读回勾选状态验证）。

### 等完成的判据

分钟线按扩展名**分两个目录**：`.lc1` 在 `minline\`、`.lc5` 在 `fzline\`（10-18 实测）：

```powershell
cd D:\finance\YuanShan
$env:PYTHONIOENCODING='utf-8'
$code = @'
from app import config
from app.ingest.tdx_binary import parse_minute
from app.db import engine

target = engine.scalar('SELECT max(calendar_date) FROM reference_data.trade_calendar WHERE is_open')
print('目标交易日:', target)
for mkt, name in (('sh', 'sh600519'), ('sz', 'sz000001')):
    for ext in ('lc1', 'lc5'):
        # 目录随扩展名走：写死 'minline' 时 5 分线永远报"不存在"
        p = config.VIPDOC_DIR / mkt / ('fzline' if ext == 'lc5' else 'minline') / f'{name}.{ext}'
        if not p.exists():
            print(' ', p.name, '不存在')
            continue
        bars = list(parse_minute(p))
        last = bars[-1] if bars else None
        print(f'  {p.name:18s} 记录 {len(bars):>8,}  最后 {last.dt if last else None}')
'@
$code | python -
```

**成功标志**：`.lc1` / `.lc5` 最后一条记录的日期部分 == 目标交易日。

## 步 6 · 入库

### 6.1 入 PostgreSQL（权威源，口径正确）

```powershell
cd D:\finance\YuanShan
$env:PYTHONIOENCODING='utf-8'

# 日线（个股 / 指数 / 基金分流，按代码前缀归类）
python -m ingest.jobs.c1_day --dry-run     # 先看统计
python -m ingest.jobs.c1_day               # 正式入库

# 板块日线 + 从成员股回算涨跌家数
python -m ingest.jobs.c3_sector

# 回算派生字段（pre_close → 涨跌停 → 换手率，顺序有依赖）
python -m ingest.jobs.b6_reconcile
```

`c1_day.py` 默认 `ON CONFLICT DO NOTHING`，**只填空洞不覆盖已有行**。要全量刷新加 `--overwrite`。

**成功标志**：脚本末尾的「验收」段落里 `md.stock_daily` 的 `max(trade_date)` == 目标交易日。

### 6.2 入旧 SQLite（兼容旧脚本，可选）

```powershell
cd ingest\legacy\01_数据同步
python tdx_data.py sync --all
```

**注意工作目录**：必须 `cd` 到 `01_数据同步`，`tdx_data.py` 在那里。
`tdx_download_data.py` 里那句 `python tdx_data.py sync` 的工作目录是错的（见
[03-故障排查.md](03-故障排查.md#一键流程脚本路径全错)）。

增量逻辑：逐只票比对 `.day` 里的 `trade_date` 与库里 `MAX(trade_date)`，**严格大于**才写；
写前先 `DELETE` 同键行保证幂等。

**这个库的数据口径已知有偏**，只作旧脚本兼容用，不要当权威源。详见
[03-故障排查.md](03-故障排查.md#旧库口径已知有偏)。
