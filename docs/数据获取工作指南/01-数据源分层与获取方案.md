# 01 · 数据源分层与获取方案

本机可依赖的数据源只有：**通达信本地文件（P0 主源）、通达信 TQ 接口、同花顺本地文件、akshare/交易所网络**。各表归属按"离本地多近"分三圈。

## 三圈划分（实测依据：`config.datasource` 注册表 + `ingest/jobs/c*.py`）

### 第 1 圈：vipdoc / T0002 纯离线文件（主源，精度最高）
| 数据 | 文件 | 入库脚本 |
|---|---|---|
| 全市场日线 | `vipdoc\{sh,sz,bj}\lday\*.day` | `c1_day.py`（配 `c10_catchup.py --date` 补历史缺日） |
| 分钟线 | `*.lc1 / *.lc5` | `c16_minute.py` |
| 板块日线 | `vipdoc\block` + `tdxzs*.cfg` | `c3_sector.py`（板块全集 `c17_tdx_sector.py`，成分 `c18`，都经 `tq_bridge`/文件解析） |
| 除权除息 | `tq`/文件 | `c19_tdx_dividend.py` |
| 代码+名称 | `T0002\hq_cache\{shs,szs,bjs}.tnf` | `app/ingest/tdx_tnf.py`（b2 迁移用过，也可单独补登记 → `scripts/register_orphans_tnf.py`） |

前提：**客户端每晚做过盘后数据下载**（GUI 自动化 `python -m ingest.jobs.p0_tdx_predownload`，见 02 文档）。文件里没有当日数据时，c10 会报缺而不猜。
★ 日线主源只能是这一圈——**同花顺本地不含可用行情**（hd1.0 专有格式，且 history\ 只缓存"打开过的票"）。

### 第 2 圈：TQ 接口（要求通达信已启动并登录，127.0.0.1:17709 本地 RPC）

> **这条依赖是硬的，不是"慢一点"：客户端没在跑（或没登录）时 TQ 直接不可用。**
> 2026-10-06 17:30 实测：客户端关着，`available()` 探不到 17709，所有 T 类作业
> （c12/c13/c15/c20 与逐票画像）一次性全空 —— 报的是"取不到"，不是"取到 0 条"。
> 所以 TQ 那三圈的顺序是 **vipdoc 文件 → TQ → 网络**，而 TQ 这一档能不能用
> **取决于客户端在不在跑**，与我们的代码无关：想让它可用只有两条路 ——
> 要么下载链本来就把它起着（p0 的 prepare 段会启动并登录），
> 要么看护的自愈 `heal()` 去把它拉起来（默认关，见 03 文档那一句可决定的话）。
> 宁缺毋假：TQ 不可用就写 NULL / `available=false` + 原因，不许拿上一场的值顶。
| 数据 | 脚本 |
|---|---|
| 收盘快照估值（pe/pb/市值） | `c15_snapshot.py`（`tq.get_market_snapshot`+`get_more_info`） |
| TQ 日线交叉核对 | `c12_tq_day.py` |
| 个股画像（IPO价/历史高低/主营/beta） | `c20_tdx_profile.py` |

用法上不必手工往 `PYPlugins\user\` 放脚本：`app/tdx_client/tq_bridge.py` 已封装成"临时 snippet 子进程跑完即删"。
**实时行情也走这圈**：`get_market_snapshot`/`get_pricevol` 是即时的，`get_market_data` 当日分钟盘中可得；但它是"按票取数"不是推送流——舒适区是自选池/板块成分的几十到几百只轮询（10~30s），全市场秒级轮询会压垮客户端。项目里 `TQCENTER_TIMEOUT=2s` 探活失败即降级。

### 同花顺本地文件能拿什么（明文 INI/SQLite，免客户端）
概念/行业板块与成分（`BlockUpdate\block_*.ini`）、自选分组（`user\...`）、港股席位表、用户公式——`c13_ths_block.py`/`c14_ths_watchlist.py`/`c20_ths_reference.py`。板块 id 不保证跨版本稳定，入库是整批替换。

## 已知边界与坑
1. **230 个行业板块无涨跌家数**（`sector_daily.up_count` 空）→ ignition 的 breadth 分项算不出，`term_count` 最高 4，永远不判 ignite——设计如此。（列名 10-06 起是 `term_count`，旧文写 `n_terms`）
2. **涨跌停价是回算值 —— 这条已于 10-07 处置**：原先 `reference_data.board_limit_ratio(board, is_st)` 拿**当前** ST 状态套历史，被 ST 之前的行会错算成 5% 档（实测 9/18 前 831+1251 行越界）。现在有了"ST 生效日期"那一维：`reference_data.security_st_period`（**库实测 354 段**）+ `limit_price_daily` + `limit_basis`，唯一写入口 `app/compute/limit_prices.py`，全库按当日档位重刷；读侧仍留一句提醒 —— `security` 表上的 `is_st` 是**快照**（停更），要按日期判 ST 必须查 period 表。详见《加工/08》坑 13 与《加工/03》§一。
3. **`reference_data.sector_member` 有 ~2.7 万基金/指数板块成员**不在主档（质量规则 sector_member_valid 常红的根源），要么登记基金主档，要么规则排除 `TDX_JJ_*`/`TDX_CSI_*` 板块。
4. **`reference_data.security.list_date` 全空**（b2 迁移遗留），新股只能靠 tnf/快照识别。
5. tushare token 有接口级 1 次/分钟限流，只能手动兜底，不进跑批（`.env` 注释实测过）。
