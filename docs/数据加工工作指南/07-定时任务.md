# 07 · 每日收盘定时任务

**先说清哪一个是真的在跑（10-18 现查）**：本项目**不靠 Windows 计划任务跑数据** —— 现役宿主是本进程
的常驻循环第 6 条 `daily-close`，默认 **15:59** 起跑（`duanxian/jobs.py::CLOSE_DEFAULTS`；窗口到 18:59、
重试 5 档 `(0,25,60,100,150)`），Windows 侧只留一条**看护**任务 `YuanShan-KeepAlive8910`（Ready，只把服务
拉起来、不跑数据）。本文下面写的"注册即此形态"那一套是**当年打算做而没做的那条**：
`setup_daily_sync_task.ps1` 在册但从未注册过 `YuanShan-DailyCloseSync`；机器上那条
`FinanceTool-DailyCloseSync`（现 Disabled，入口是**参考项目那棵树里的** python 与 `scripts\ops\daily_close_sync.py`、
日志也写去那边；那边叫什么绝对路径本文不抄 —— 抄一条外部路径就等于给体检留一处"参考项目被删后当场变废铁"的引用，
要查它就去 `Get-ScheduledTask` 看那条任务的 Action 本身）是**参考项目的**，
它 09-24/09-25 各真跑过一次（见下方改正段），一旦被重新启用就会形成双写。
体检里点名的也正是它：「非本项目命名（`YuanShan-*` 之外）且指向行情链的任务」。

## 任务参数（注册后即此形态）

| 项 | 值 |
|---|---|
| 任务名 | `YuanShan-DailyCloseSync` |
| 触发 | 每周一~周五 **16:05**（收盘 15:30 后留缓冲） |
| 运行账户 | 当前用户（Administrator），**Interactive 登录类型** |
| 入口 | `python -m ingest.jobs.daily_close_sync`（`.venv` 里的 python，找不到才退回 PATH） |
| 注册脚本 | `scripts\ops\setup_daily_sync_task.ps1`（`-AtTime` 改时间、`-Remove` 删除） |
| 日志 | `D:\finance\YuanShan\logs\daily_sync.log`（注册脚本会建 `logs\` 目录） |

⚠️ **旧任务 `FinanceTool-DailyCloseSync` 必须保持停用**（2026-09-25 已 `Disable-ScheduledTask`）。
早期文档里"`LastTaskResult=267011`＝从未跑"的结论**是错的，就地改正**：实测它在
2026-09-24 16:05 与 2026-09-25 16:05 **各真跑过一次**，两次都走完"一键追平（PARTIAL：10 步成功 / 4 步失败）
→ c18 板块成分 / c19 除权 / c20 个股档案三步写库成功 → `run_agent --check`"，
结尾 `taskkill /F /IM TdxW.exe` 强杀通达信，所以 `LastTaskResult=1`（非零是收尾那条，不代表没写库）。
也就是说：**它曾经是本库的第二个写入方**。裁定已改口 —— 本项目是 `analytics.*` / `market_data.*` 等
全部 schema 的唯一写入方，不存在"双跑对账期不与旧项目同名双写"这种过渡态；旧任务一旦被重新启用就会重新形成双写。

## ⚠️ 硬约束：必须有"已登录且未锁屏"的桌面

每日同步第一步是**通达信 GUI 盘后下载**、后面 TQ 增强要**登录客户端**，
两者都要求交互式桌面。所以：

- 任务只能在**用户已登录**时跑（不像备份任务能用 SYSTEM 无桌面跑）。
- 触发那一刻（16:05）**屏幕不能锁**、不能注销、不能是 Session 0，
  否则 `run_agent` 会话自检会拒绝、当天同步失败（日志会记，不静默）。
- 非交易日由脚本自身守卫跳过，不会空启动通达信（实测：国庆 10-01/10-02 = 跳过）。
- ⚠️ 2026-09-25 16:05 那次的实况就是反面教材：GUI 下载段 verify 超时（指数停在 09-23）、
  日线骨干没成（当日 0 行），但 TQ 三步照写、通达信照被强杀 —— **退出码非零不代表什么都没发生**。

> 想要真正无人值守，得换数据源（如付费 API / mootdx 直连行情服务器），
> 绕开通达信客户端 GUI。这是通达信本地方案的固有限制，不是脚本能修的。

## 任务每天做什么（`ingest\jobs\daily_close_sync.py`）

1. 交易日守卫（非交易日退出码 2，不启动通达信）
2. `-m ingest.jobs.e1_fill_all` —— 盘后下载 → 日历 → 日线/板块/分钟线 → 份额/两融/龙虎榜/资金流 → 因子/评分计算
3. `-m ingest.jobs.c18_tdx_membership` 板块成分 / `c19_tdx_dividend` 除权 / `c20_tdx_profile` 个股档案（TQ 增强）
4. `run_agent --check` 校验
5. `reset` 关闭通达信

退出码：0 全 OK / 1 日线骨干没成 / 2 非交易日跳过。

## 管理命令

```powershell
# 注册 / 更新（默认 16:05）
powershell -ExecutionPolicy Bypass -File .\scripts\ops\setup_daily_sync_task.ps1
# 改时间
powershell -ExecutionPolicy Bypass -File .\scripts\ops\setup_daily_sync_task.ps1 -AtTime '16:30'
# 删除
powershell -ExecutionPolicy Bypass -File .\scripts\ops\setup_daily_sync_task.ps1 -Remove
# 查看 / 手动试跑 / 看日志
Get-ScheduledTask -TaskName YuanShan-DailyCloseSync
Start-ScheduledTask -TaskName YuanShan-DailyCloseSync
Get-Content -Tail 40 D:\finance\YuanShan\logs\daily_sync.log
# 确认旧那条真的停着（应为 State=Disabled，不要删，留着当"曾经双写"的证据）
Get-ScheduledTask -TaskName FinanceTool-DailyCloseSync | Select-Object TaskName,State
```

> 脚本正文用**纯英文**——Windows PowerShell 5.1 按 GBK 读 .ps1，UTF-8 中文会
> 破坏引号导致解析失败（踩过）。中文说明放这里，脚本保持 ASCII。
