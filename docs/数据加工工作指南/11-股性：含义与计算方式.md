## 一句话

**股性**回答的是「这只票近一年**能不能被资金反复做动**」—— 不是打分、不是预测，是把三条独立慢变量
（涨停基因／摆动性／钱活跃度）各自在**当日全场**排个位，取中位数分**强／中／弱**三档。

---

## 1. 它为什么存在（来历）

- 用户 11-03 点名给「突破信号 · 埋伏票」加两列：「**股性**」与「近 10 个交易日日平均振幅」，
  原话「你看下这个参数怎么定义，最好也要加入每日的数据计算」。
- 「加入每日的数据计算」就是这张表存在的理由：这两个数**不读侧现算**，每天跟着加工链算一次落库，
  屏上读的是落库行（读侧只 join＋出口清洗，不重算分位、不自己定档）。
- 用户 11-04 进一步要求：明日展望（`t10`）两榜**只留股性强**（middle／weak 去掉），并「把股性这个
  参数的含义和计算方式」写清 —— 本文即那一份。

## 2. 三条腿（判据本体，只住 `stock_character.py`）

**不做成一个加权总分**（上次那句"达标后的逐日涨跌幅"就是一个数糊住三件事被点名看不懂，
所以这里拆成三条腿各排各的位，弱腿拉得住档）。

| 腿 | 列 | 量纲 | 判据 |
|---|---|---|---|
| **涨停基因** | `seal_250` → `gene_pctile` | 近 250 场**封住**涨停的天数 | `close ≥ limit_up − SEAL_EPS(0.01)`（与首板分析同一把尺，本体 `app/compute/limit_gene.py`）。`touch_250` 是盘中触过（含后来炸开的）天数，另一把尺、两把都交；`consec_max_250` 只读 `limit_up_pool_daily.consec`，这里不再数一遍连板 |
| **摆动性** | `amp_250` → `amp_250_pctile` | 近 250 场日均振幅 | 逐日 `(high − low) ÷ pre_close × 100` 的算术平均（**未复权**，振幅是比例、复权不改变它） |
| **钱活跃度** | `turn_250` → `turn_250_pctile` | 近 250 场日均换手率 | 逐日 `turnover_rate_percent` 的算术平均 |

> 「近 250 场」≈ 一年，是"股性"这种**慢变量**的最低样本量。250 场不是这只票自己的 250 根，
> 是**全市场**的倒数第 250 个交易日（见 §3 窗口）。

---

## 3. 窗口怎么取（关键纪律）

窗口按**市场场次**取起点，不是按这只票自己的根数。

- 「近 10 个交易日」说的是**全市场**的倒数第 10 场到今天。
- 若按这只票自己的 10 根算，长期停牌的票会拿半年前的 10 根冒充「近 10 场」—— 那一天它确实停牌，
  摆动是「没有可测」，不是「平静」。
- SQL 里用 `dense_rank() over (order by trade_date desc)` 给每个市场场次编号（`back`＝倒数第几个市场场次），
  停牌的那只票就不会被「自己的前 10 根」顶替掉「全市场近 10 场」。
- **真有的行数**一并落库（`bars_10`／`bars_250`）：不足门槛就不给数、并在 `missing` 点名：
  - 近 10 场真有的行 < `AMP_MIN_BARS`（**8**）根 ⇒ 振幅判不了（`bars_10_lt8`）
  - 近 250 场真有的行 < `CHAR_MIN_BARS`（**120**）根 ⇒ 三腿全判不了（`bars_250_lt120`）
- 8/10 与 120/250 的门槛是这么定的：允许少量停牌日（一次临时停牌两三天很正常），
  但**过半缺失**的那只票算出来的「日均」已经不是这 10/250 场的日均了。
- 一只**次新股**可能只有「近 10 场日均振幅」而没有「股性」—— 那一格是 `—`，不是 0，也不是「股性差」。

## 4. 分位怎么算（当日横截面）

- 分位是**当日全场横截面**（0~100）：`x` 的分位＝「有值的票里 ≤x 的只数 ÷ 有值的只数」×100。
- 三条腿各自算自己的分位（`gene_pctile`／`amp_250_pctile`／`turn_250_pctile`），另附 `amp_10_pctile`。
- **同分同名**（并列的几只票在同一个分位上，不因代码顺序被拆开）—— 与 `allocator._pct_rank` 一条规矩。
- **没有值的那只票不进分母也不占号**（它不该被排成「最差」），自己拿 NULL。
- 有值的只数 < `PCTILE_MIN_SAMPLE`（**5**）⇒ 整列全部 NULL：5,500 只票的分位有意义，3 只没有。
- 实现用**排序＋bisect**（`bisect_right`），不是两两比较：全场 5,500 只，逐只再扫一遍就是 3,000 万次比较。

## 5. 档位怎么定（中位数，不是加权）

```
char_mid_pctile = median(gene_pctile, amp_250_pctile, turn_250_pctile)
char_level      =  strong   若 char_mid_pctile ≥ 70
                   middle   若 40 ≤ char_mid_pctile < 70
                   weak     若 char_mid_pctile < 40
                   NULL     若任一条腿分位缺失
```

- 档位门槛（`CHAR_STRONG_MIN=70.0`／`CHAR_MIDDLE_MIN=40.0`）作用在**三腿分位的中位数**上。
- **任一条腿判不了 ⇒ 整档 NULL**。不拿两条腿硬凑一个看起来像的档，也不补 50
  （补 50 会把「判不了」画成「中性」）。
- **取中位数而不是加权**：一条腿特别差要留在结论里。换手极低但老封板的票，加权会把它抬成「股性好」；
  中位数让弱腿拉得住档。
- 中文档名**只住** `CHAR_LEVEL_LABELS`（`strong→股性强 / middle→股性中 / weak→股性弱`）一处：
  读侧原样转交，界面不自己翻译（屏上念的词与库里的键必须一份出处）。

---

## 6. 缺数是 NULL、0 是读数（本仓红线）

这条混了就等于把**缺数排成最差**。

| 值 | 含义 |
|---|---|
| `seal_250 = 0` | 「这 250 场一次都没封住」—— 真实、可排名 |
| `seal_250 IS NULL` | 「那几天档位价没读到，判不了」—— 缺数点名 `hist_limit_up_missing` |
| `consec_max_250 IS NULL` | 这 250 场里没有过可数的连板轮次（含从没封住板）—— **不是缺数**，屏上是 `—` 加一句「这段时间没连板」。另一种情况：涨停池整批读不到库时按「判不了」点名（`missing` 里 `lup_rows_unavailable`），**绝不能**写成「没连板」 |
| 三腿分位 `NULL` | 上市不足 120 场／档位价缺 ⇒ 判不了（`bars_250_lt120`／`hist_limit_up_missing`） |

缺数点名用的短码（进 `missing` 列，jsonb，界面悬停念的就是它）只有一份，全部来自写侧：
`no_sessions`（读不到场次）／`bars_10_lt8`／`bars_250_lt120`／`amp_inputs_missing`／`turnover_missing`／
`hist_limit_up_missing`／`lup_rows_unavailable`。

## 7. 表结构（每票每场一行）

主键 `(security_code, trade_date, spec_version)`；**母体是全场每只票一行**（不是事件表），
一天 5,400~5,600 行是正常量级。换口径是**新写一批行**，不改写历史（写侧每天先删这一场这一版再插）。

| 列 | 含义 |
|---|---|
| `amp_10` / `amp_10_pctile` / `bars_10` | 近 10 场日均振幅 / 其当日分位 / 真有的行数 |
| `amp_250` / `amp_250_pctile` | 近 250 场日均振幅 / 其当日分位 |
| `turn_250` / `turn_250_pctile` | 近 250 场日均换手率 / 其当日分位 |
| `seal_250` / `touch_250` / `consec_max_250` | 封住涨停天数 / 触板天数 / 最高连板（读 lup-1） |
| `gene_pctile` | 涨停基因腿分位 |
| `char_mid_pctile` | 三腿分位中位数（定档的原始值） |
| `char_level` / `char_level_label` | 档位键 `strong/middle/weak/NULL` / 中文档名 |
| `bars_250` | 近 250 场真有的行数 |
| `missing` | 缺数点名（jsonb，键→短码） |

**它是事后描述量**：不进 `ambush_score`、不做预测。读侧（`duanxian/quant.py::ambush`）用 LEFT JOIN
并到埋伏榜行上；整场没入库时出一条 `char_missing_batch`（chip 文案「股性这一场还没算」）。

## 8. 明日展望（t10）怎么用股性过滤（11-04 加）

- 两榜（多指标靠前／趋势最正）在 **SQL 层**各 LEFT JOIN `stock_character_daily`（按窗口最新场次／当日场次），
  加 `AND (c.char_level = ANY(t10_char_keep) OR c.char_level IS NULL)`。
- 判据参数 `t10_char_keep = ["strong"]`（`broadcast_config.json`，改这里即可放宽到含 middle），代码不用碰。
- **为什么过滤住在 SQL 而不是取完 8 只再 Python 删**：事后删会把 `LIMIT` 先取走的 middle/weak 名额
  换成别人，短名单长度语义就变了。SQL 层过滤保证「留下的 8 只」都是 strong（或判不了的新股）。
- **上市不足 120 场判不了档位的（char_level=NULL）**：照留、不删（它不是「差」，是「没判」），
  行尾点名「股性判不了（上市不足 120 场）」。若想新股也不上，说一声把 NULL 一起去掉即可。
- ⚠️ **11-05 搬家**：这两条 SQL 现在住 `duanxian/tomorrow_outlook.py`（两张榜同时要上屏，
  判据不能推送一份、界面一份）；`ingest/jobs/push/t10_tomorrow_outlook.py` 用别名 import 同一份，
  排版与发送那一层没动。上面那句「股性过滤不许退化成 Python 事后删」由
  `tests/test_tomorrow_outlook_view.py::读侧搬过来的两份榜仍把股性判据钉在查询里` 接着钉。

### 8.1 一天里强／中／弱各占多少（11-05 用户点名要数）

现查 `analytics.stock_character_daily`（`stockchar-1`，覆盖 2025-10-23 ~ 2026-11-04 共 251 场），
**按每场各算一次占比再取平均**（不是全史行数直接除——那样会被母体只数加权）：

| 口径 | 股性强 | 股性中 | 股性弱 | 当日判得了的母体 |
|---|---|---|---|---|
| 最近 60 场（2026-08-05 ~ 11-04） | **27.13%**（1,457 只） | **36.35%**（1,952 只） | **36.52%**（1,962 只） | 5,371 只 |
| 全史 251 场对照 | 27.35%（1,461 只） | 36.65%（1,958 只） | 36.00%（1,924 只） | 5,343 只 |

两档差距都在 0.6pp 内 ⇒ 最近 60 场没有偏离常态。分布约 **27 : 36 : 37**，
与设计预期（top 30% 记强、30~70% 记中、底部 30% 记弱）里"弱档比理论值厚 6~7pp"这一条一致：
分位按**有值的票**算、判不了的另列，加上涨停基因那族本身就是右偏（大多数票 250 场封不住几次板），
中位数落在 40 以下的票因此比 30% 多一些。

**这一族是相对的还是绝对的**（同一轮用户问的）：**半相对**。三条腿都是当日全场横截面分位（相对），
定档门槛 70／40 是写死的常量（绝对），但绝对门槛作用在相对分位上 ——
同一只票今天的档位会随母体变，所以「股性强」说的是"今天在这一堆票里靠前"，不是"它过了某条硬线"。
现算的复现命令：

```sql
with per_day as (
  select trade_date,
         count(*) filter (where char_level is not null) as tot,
         count(*) filter (where char_level='strong') as s,
         count(*) filter (where char_level='middle') as m,
         count(*) filter (where char_level='weak')   as w
    from analytics.stock_character_daily
   where spec_version='stockchar-1' group by trade_date)
select count(*) days, avg(s::numeric/nullif(tot,0)*100) 强,
       avg(m::numeric/nullif(tot,0)*100) 中, avg(w::numeric/nullif(tot,0)*100) 弱
  from per_day;
```

## 10. 耗时、链上位置与跑法

- 单场 **12.6 秒**（两条聚合 SQL＋一次 executemany，5,586 行）；回算 250 场与别的作业并发时约 40~50 秒/场。
  超时给 600 秒。
- **必须排在 `fbdaily` 之后**（涨停基因那一腿读 `fbdaily` 写的 `limit_up_pool_daily`）。
- 链参数 `--date target --recent 3`（与 `fbdaily` 同档：晚到的档位价要在第二天补进股性列，只算今天会永久留 NULL）。
- CLI：
  - `python -m app.compute.stock_character --date 2026-11-03`（只算这一场）
  - `python -m app.compute.stock_character --date 2026-11-03 --recent 3`（以该日结尾的三场，每日链这样传）
  - `python -m app.compute.stock_character --recent 250`（最近 250 场）
  - `python -m app.compute.stock_character --since 2025-11-01`（从这一天到库里最新一场）
  - `python -m app.compute.stock_character --recent 5 --dry-run`（只算不写）
- rc：0 全好；3 有场降级（缺日线的场次、或某条腿整场判不了）。
- 250 场回算 11-04 当日跑完，库里现查 **250 场 / 1,374,900 行（2025-10-23 ~ 2026-11-03）**，
  其中档位判不了 39,105 行（2.8%）、近 10 场振幅判不了 4,987 行 —— 这组数是 `verify()` 回库里数出来的。

## 11. 对账与「同一把尺」

- 涨停基因的两种数法**故意并存、有测试钉着**：
  - `limit_gene.seal_touch_counts()`：给一批行、按只数（首板榜只算榜上那几百只）。
  - `limit_gene.seal_touch_market()`：全场一条 `count(*) filter` 聚合（股性表要算 5,500+ 只）。
  - 两种表达式只准成对出现在 `limit_gene` 这一个模块里；
    `tests/test_limit_gene.py::同一把尺的两种写法逐只必须相等` 拿真库最近 10 场逐只比四列，
    改了 eps／缺行处理而忘了改 SQL 那一半 ⇒ 当场红，并报出是哪一只哪一列。
- 「封住涨停」容差 `SEAL_EPS=0.01`（`limit_gene.py`，首板分析与股性表都读它；
  `first_board_daily.LIMIT_SEAL_EPS` 只是别名）。注意它和 `board_span`/`limit_prices` 那些 0.005/0.001
  仍是并存的两类问题 —— 这一族用的是 0.01 那一档，见 [10 号总表](10-每个数怎么算：判据、指标与参数总表.md)「同一个数两把尺」清单。
