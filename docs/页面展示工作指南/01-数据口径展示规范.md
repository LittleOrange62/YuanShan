# 01 · 数据口径展示规范

> 六条硬规矩。都是这轮在四个项目之间来回对数时，被实证证明"违反了就会出错误结论"的。
> 每条给：规矩 / 为什么 / 反例出处。

## 一、`available=False` 必须成对带 `reason`，不许用 0 或空充数

数据取不到时返回 `{"available": false, "reason": "..."} `，页面显示"不可用 + 为什么"。
**不许**：填 0、填空串、沿用上一场的值、按窗口均值补、估一个。

- 正例：YuanShan `breadth.market_breadth()`、`market_facts` 各块 —— 取不到一律 `available=False` + `reason`，且有 `_payload_ok()` 守门，形状不对的缓存直接当没有。
- 反例：TradingAgents `get_hot_stocks()` 全用 `.get(k, "")`，字段漂移后输出 `+%`、`换手%`（**连数字都没有，不是 0**），它的 quality_gate 只查长度和"无法获取"字样，拦不住。

## 二、NULL ≠ 0：这两个状态必须是不同的值

| 情形 | 必须是 | 不能是 |
|---|---|---|
| 板块没有涨跌家数这个数据 | `breadth: null` | `0`（0 分是"板块内没人涨"） |
| 没人触板 | `rate: null` | `0%`（0% 是"全都封住了"，即板最硬） |
| 某票没上机构榜 | `inst_net: null` | `0`（0 亿是"机构对倒"） |
| 停牌/缺行情 | 不可用 | 资产归零 |

本轮 `sector_cycle()` 与 `breadth()` 都按这条实现，并有测试守着。
**反例（同项目内的）**：PG 推导的涨停池 `首次封板时间=""` → `market_facts.seal_quality` 的 `broken_times` 空 → `never_broken_rate=1.0`，界面会显示成"**全市场板最硬**"。这就是把 NULL 塌成 0 的后果。

## 三、口径字符串要随数据交出，不能只写在代码注释里

响应体里带 `up_down_scope` / `dist_scope` / `unit` / `decimals` / `source`。

```json
{"up":1746,"down":3377,"up_down_scope":"沪深 A 股（本地日线自数，不含北交所）",
 "universe":5556,"dist_scope":"全 A 含北交所（本地日线自数）","source":"pg","requests":0}
```

理由：同一页会有"沪深两市"和"全 A 含北交所"两种分母的数，**不同统计范围不能混用分母**；
读者只看到两个数时无法知道它们不是一个总体。`MarketFactsPanel.ratioOf` 就是为强制同分母而存在。

## 四、分母写进字段名，别共用一个名字

本地算的炸板率分母是**触板**，`seal_quality` 的分母是**涨停+炸板池**。两个都叫 `broken_rate` 迟早有人接错线。
→ 本轮命名为 `broken_of_touched_rate`，并在注释里点明不能和谁互换。

## 五、"打标不裁"：脏类别交出去，由界面决定默认展示什么

`sector_cycle()` 里 `昨日涨停/昨日突涨/板块趋势/最近情绪指数` 这类**不是可交易题材**
（"昨日突涨正在蓄势"是同义反复）。处理方式不是删掉，而是：

```json
{"name":"昨日突涨","sector_type":"风格","synthetic":true, ...}
```

同时交出 `sector_type`（概念/行业/风格），界面默认只展示概念+行业、把统计板块收进一个开关里。
**理由**：取数层替界面做主裁数据，会让"为什么少了 3 个板块"变成一个新的不可见差异。

## 六、新鲜度必须可见：值得借鉴的那一个组件

quantdash 的 `DataFreshnessBadge` 思路值得抄（**思路，不是代码** —— PolyForm Noncommercial）：

- 每个卡片标 7 档来源：实时采集 / 代理缓存 / 本地文件 / 模拟回退 / 第二数据源 / 最近快照 / 未知；
- 多源合并时按优先级取最新：`live > cache = secondary > snapshot > local > mock > unknown`；
- 附带"快照回退""缓存命中""更新时间"三个胶囊。

**但必须避开它的两个失效模式**：
1. 它让**本地打包文件优先于实时并短路后续拉取**，且 `source:'local'` 时 `updatedAt` 为空 → 22 个交易日前的陈旧数据**静默胜出**；
2. 快照伪造（下移填白天、哈希编造封板时间）**没有任何标记**。

→ 移植时的底线：任何降级路径都要留 `reason`，任何非实时数据都要带时间戳。YuanShan 自己那句
"夜间、午休或过期行情不能冒充当场的有效盘中快照"就是这条纪律的原文。

## 九、首页连板榜「封板强度」：判据只住后端，页面悬停显示那一份（2026-10-09）

用户两条点名：① 同连板的按**首封先后**排；② 加一列**封板强度**（首封后开过几次板、封单占流通市值等加权），
并且"算法方法在页面上要地方可以查看（比如鼠标放到标题上）"。

**代码地图**：判据 `duanxian/seal_strength.py`（权重、三张档位表、`spec_text()` 现拼说明）→
接法 `vr/market.py::_emotion()`（逐行分数 + `seal_note` + 榜单默认序 + `seal_spec`/`seal_spec_version`）→
列 `frontend/src/components/home/MarketPanorama.tsx`（表头悬停吃 `emotion.seal_spec`，
格子悬停吃这一行的 `seal_note`）→ 钉 `tests/test_seal_strength.py`（45 条）+
`frontend/test/sortKeys.test.ts`。**前端没有第二份分档**（抄一份就会和后端走偏，而读者看到同一个列名）。

**数据现实（2026-10-08 场实测，判据就是照这个定的）**：东财涨停池 43 行里 2 板+ 有 10 行；
`fund`/`zbc`/`ltsz`/`fbt` 四列 **43/43 有值且非零**；封单占流通实测 0.10%~14.9%，
开板次数 5/10 为 0、其余 1~8，首封 `92500`(集合竞价)~`131309`。⇒ 三条输入都用得上，不需要降级。

**公式与阈值**（`seal-strength-1`，改分档就升号，页面跟着显示是哪一版）：
`强度 = 45·封单÷流通 + 35·开板次数 + 20·首封时间`，各档 0~1，满分 100。
封单占比 ≥3/1/0.5/0.2/0.05% → 1.00/0.85/0.70/0.50/0.30，不到 0.05% 记 0.15；
开板 ≤0/≤1/≤2/≤3/≤5 → 1.00/0.70/0.50/0.35/0.20，≥6 次 0.05；
首封 09:25/≤09:30/≤09:40/≤10:00/≤10:30/≤11:30/≤14:00 → 1.00/0.95/0.85/0.70/0.55/0.40/0.25，更晚 0.10。
**为什么不用当日分位**：连板股常只有十来只，分位在 n=10 上会跳，今天的第一名和昨天的第一名不是一回事。

**三条不许破的纪律**：
1. **缺数不按 0 参与**：某项缺就从分母里摘掉、权重在其余项上归一；**有数的少于两项就不给分**
   （显示 —），否则只看首封时间就能撑出满分。按 0 算会把"池子没给这栏"排成"最弱"。
2. **默认序说的是秒，显示只到分钟**：排序键用池内原始 `fbt`（`92500` 与 `92502` 会分先后，
   而两行都显示 09:25），第三键才是强度。这件事必须写在那行小字与「首封」列头悬停里，
   否则读者会以为页面排错了。首封缺数（`_num(None)=0`）**排到本档最后并显示空**，不当 00:00 封的。
3. **悬停内容只有一份**：页面显示的是后端 `spec_text()` 从档位表现拼的那段（含口径版本号），
   每格另给"这一行为是这个分"的三个输入。

**「几天几板」那一列（用户 2026-10-09 追加，回溯 30 个交易日）**：判据只住 `duanxian/board_span.py`
（`span_from_sealed` 纯函数 + `boards_by_code` 取数），页面显示的是后端 `days_boards_rule` 那段口径文字。

- 为什么不用东财池自带的 `zttj`：2026-10-08 实测 10 只 2 板+ 的票 `zttj.days == zttj.ct == lbc` **逐只相等**
  （那天没有一只中间断过板），照抄就等于把「连板」那一列再画一遍。本地按 30 场窗口数才出得来「5天4板」。
- 三条会写错的口径：**轮首之前的空日不算"几天"**（不剥就会把 4 天说成 5 天）、
  **只空 1 天仍算同一轮**（写成"必须连续"就永远出不来这个形态）、
  **今天没封住就没有这一轮**（交回 `None`，不退回上一轮的历史值）。
- 封住 = `close >= limit_up − 0.001`（`market_data.stock_daily` 的 `limit_up`/`limit_basis` 已是当日档位收口结果）；
  **触板又炸掉的那天不算板**。
- 慢查询坑：同一条查询 `left(security_code,6)=any(...)` 实测 2.63 秒，先经 `reference_data.security`
  展开成全码再 `security_code=any(...)` 是 0.25 秒（10 倍），这一列在首屏读 ⇒ 必须走后者；已钉进测试。
- 真数据里的分歧实例（同一套规则往前扫，封板日 ≥ 09-20 共 12 例）：`001317 三羊马` 09-24 是 **5天4板**
  而当天连板只有 1、`601579 会稽山` 09-21 **5天4板**/连板 2、`600418 江淮汽车` 09-28 **4天3板**/连板 1。
  今天这一场没有这种票（全是纯连板），所以那一列今天与「连板」同值 —— 这是数据的样子，不是列坏了。
- 数不出来时：池子说今天封住而本地数不到 ⇒ `days_boards_warn` 点名是哪几只、并说"是没读到当天那行，
  不是没有板"；整批读不到时是另一句话。两句话不一样。

**验收复现**：
```

.venv/Scripts/python.exe -X utf8 -m pytest tests/test_seal_strength.py -q          # 45 例
```

浏览器实测（2026-10-09 08:5x，首页「短线情绪 · 2026-10-08」）：默认序 8板→4板(09:25、09:31)→3板(09:25:00、09:25:02、09:35、10:05)→2板(09:30、09:36、13:13)；
「连板」列头亮着降序箭头；点「封板强度」→ `100,97,93,92,90,90,80,43,26,20`（降序单调），
再点升序单调，第三次回到后端序；表头悬停显示完整分档说明（含口径版本号）。

## 十、跨屏引用另一张表的读数：同场、缺数不补 0、分母写清（倍量榜 2026-10-09）

用户要倍量榜（`/volume-double`，后端默认 `limit=150`）加两块：一列**四维象限得分**，
一张把这些票的**概念板块反过来按出现次数**排的新表。两块都不是本页自己算的，所以规矩是同一套：

| 要守的 | 做法 | 为什么 |
|---|---|---|
| 同一天 | 三个 left join 全部钉 `sc/xq/yv.trade_date = v.trade_date`，参数只有 `(目标日, min_count, limit)` | 参数多一个就说明有一处的日子是自己填的 ⇒ 跨日凑数；测试 `test_象限三条join都钉在同一场` 就数这个 |
| 键的唯一性要实测 | `analytics.score` 一天一票一键（2026-10-08 实测 5,557 行 = 5,557 个代码）⇒ 三条 join 不会把榜炸成重复行 | 这是**实测性质**不是假设；score 口径变了要复验 |
| 缺数交 None | 没有 `oper_score` 行的票：`quadrant/oper_value=None`，界面 —，并进 `quadrant_missing` caveat 点名是哪几只 | 0 会被读成"中立"，而它其实是"那天没这根分数" |
| 分数不是百分 | `oper_value` 是带符号原值（当日 Q1 均 +8.2、Q4 均 −36.9），列头悬停必须带 `score_note` | 只写"得分"两个字，读者会按 0~100 理解负数 |
| 轴语义只有一份 | 合成式 / 四档含义 / 人读标签由后端 `quadrant_axes` 一并交出，页面用 `d.quadrant_axes` 现拼悬停；前端 `doesNotMatch(/oper_score = 0\.40/)` | 前端抄一份，改一处就两边不一致 |
| 反向聚合要写分母 | 概念榜的母体是**本榜交出的 150 只**，不是全市场：`concept_pool={size,covered,concepts_total,single_stock}` 一起交出，行上写"上面那张倍量榜交出的 150 只（不是全市场）" | 不写就会被读成"全市场 100 只融资融券倍量股" |
| 只数会冒充热点 | 除了只数还必须带 `members_total`（该概念全市场成员）和 `lift_pctile`（只数÷成员）——第一名永远是 `融资融券`（3,872 只）这种通道标签 | 只看只数=把宽概念读成题材共性；点「集中度」才是"这批票往哪挤" |
| 读不到 ≠ 没有 | `concept_rollup` 分三种：查询失败(`failed=True`)、真的一条归属都没有、缺的那几只没覆盖 —— 三句不同的话 | 混成一句就是"把没比过报成比过且一致" |
| 不做同义合并 | `sector_alias` 只做跨源板块码映射（THS_↔TDX_），**不合并概念名**：「新能源车」(1,083) 与「新能源汽车」(1,064) 是两行 | 替他合并就是替源站做决定 |

**口径位置**：聚合 SQL 只住 `duanxian/pg_sources.py::concept_rollup`（与 `concepts_by_code` 同一套成员口径：
`sector_type='概念'` + `out_date` 未出 + **按概念名去重**）；接法在 `duanxian/quant.py::volume_double`；
列与新表在 `frontend/src/pages/VolumeDouble.tsx`。

## 十一、连板榜「首板日大盘情绪」：每行按**它自己的另一个日子**去读另一张表（2026-10-10）

用户 2026-10-10 在首页短线情绪那块点名加一列：这一轮第一次封板那天，大盘是什么情绪。
和第十节是同一类活（跨屏引用），但多一条：**母体日子是逐行不同的**（每只票的首板日不一样），
所以整批一次查询、按日子取回，不许逐行打库。

| 要守的 | 做法 | 为什么 |
|---|---|---|
| 主读数选覆盖好的那张 | 档位取 `analytics.market_sentiment_daily`（宽度五档 + 题材四档，近 30 场实测 30/30 不缺），**不取 `analytics.score` 的 `market_mood`** —— 后者从 2026-06-29 起才有、最近 30 场缺 5 天（09-03/09-04/09-07/09-15/09-16） | 拿注记当主读数 ⇒ 整列时不时空掉，读者以为"那天没情绪" |
| `market_mood` 降为注记 | 仍带在悬停末尾，缺就是缺 | 它才是四维象限 Y 轴那根分量，读者要能对上账 |
| 缺数 ≠ 0 | `mood` 缺 → `None`，悬停写「那天没有这个分」；**绝不写 0** —— 0 在这把尺子上是「中性」 | 「把没比过报成比过且一致」的一个具体形态 |
| 整行没有就只说这一件 | `first_board_view` 遇到该日无行：只交 `首板日 X 在…里没有行`，**不再拼**「涨停 — 家」「宽度 缺」 | 那串缺字堆在一起会被读成"那天什么都没涨" |
| 三种空要分开 | ① 这一轮封板日没数出来（原因在「几天几板」那一列，这里不重复报）② 那一天档位表没行（点名是哪个日子）③ 整批没读到（`failed=True`，链路坏了） | 三句不同的话，对应三个不同的下一步 |

## 十二、倍量榜末尾「当日涨幅 / 15 日涨幅」：一屏里两把尺子必须说清是哪一把（2026-10-10）

同一张表里，`bars / ma60_days / dev_med / ma60_chg` 全都算在**40 日窗口**上，
而新加的两列涨幅算在**16 场**上。所以这一节的规矩不是"怎么算"，而是**怎么让读者不把两把尺子混成一把**。

| 要守的 | 做法 | 为什么 |
|---|---|---|
| 词的诚实 | 列名写「**当日**涨幅」并在悬停第一句给出「当日 = 本页基准交易日（现在显示的是 2026-10-09）」；**不写「今日涨幅」** | 这一屏锚在库里那一档；周末或复盘时"今天"根本没有行情，写"今日"就是一句假话 |
| 两列同尺 | 两列都用后复权价 `close × adjustment_factor`（定义在 `app/db/repo/quote.py:444`），**不读 `stock_daily.pct_change`** | 那列是未复权比值：实测 000155 在 2026-09-22（除息日）记 −2.77%，复权口径是 −0.60% —— 把一次派息报成一根大跌 |
| 跨度按市场场次 | 窗口 = `row_number() over (order by trade_date desc)` 的前 16 场（目标日 + 往前 15 场） | 按"这只票自己的第 16 根 K 线"取数会把跨度悄悄拉长：实测榜上的 601238.SH 窗口里只有 6 根，自己的第 16 根落在 **08-27**，比正确基期 09-10 早 10 场 —— 而格子上看不出来 |
| 缺行不冒充 | 基期或目标日那天没有行 ⇒ 交 `None`（界面 —），**不拿更早的一天顶**、不写 0% | 0% 的意思是"平盘"，是一条与"算不出"相反的结论 |
| 自证材料同屏 | 行悬停给出 `基期 2026-09-10 → 2026-10-09｜窗口 16 场里它真有行 14 场` | 读者能自己数一遍，也一眼看出这段停过牌 |
| 口径只住一处 | 判据、SQL、口径文字全在 `duanxian/day_returns.py`；接法在 `duanxian/quant.py::volume_double`；页面 `title` 逐字透出 `d.pct_rule` | 前端抄一份复权公式，改一处就两边不一致（测试 `doesNotMatch(/收盘价\s*×\s*adjustment_factor/)` 就钉这个） |
| 整批一次查询 | 传**全码**（`security_code = any(%s::text[])`），150 只 / 16 场实测 0.25s | 逐行打库＝150 次；对每行套 `left()` 会退化成全表扫（同 §几天几板 那条教训） |
| 读不到 ≠ 没涨 | 三种话：整批 `failed`（pct_failed）、个别缺行（pct_missing 点名代码）、真平盘（0%） | 混成一句就是"把没比过报成比过且一致" |

**实测（2026-10-09 场，榜上 150 只）**：`GET /api/quant/volume-double?limit=150` 两次 2.91s / 2.04s，
响应过 `json.dumps(allow_nan=False)` 不抛；缺当日 0 只、缺 15 日 1 只（605577.SH：窗口 16 场里只有 14 根，
缺 09-10 那天的行 ⇒ 交 None）。榜上有两只窗口内不足 16 根（605577 14 根、601238 6 根），
601238.SH 基期那根正好在，所以数仍然算得出（+2.53%），悬停把"6 根"如实带出来。
数值抽查 000678 襄阳轴承：当日 +3.10%、15 日 +38.68%（9.10 → 12.62 复权价，与逐行手算一致）。
窗口行数不足 16 的两只都实测过：605577.SH（14 根，缺 09-10 那天的行 ⇒ 交 None）；
601238.SH（6 根，基期那根正好在 ⇒ 数仍然算得出 +2.53%，悬停老实写"16 场里真有行 6 场"）。
浏览器逐列点击：「当日涨幅」降序 `+24.12 … +2.97`、升序 `−8.06 … +1.21`；

## 十三之二、caveat 按"性质"分流：解释可折、缺数绝不折 —— 一处 `lib/caveatKind.ts`（2026-10-21）

> 编号写成"十三之二"是故意的：这一条**改的就是 §十三 那句「`Caveats` 本体一律不许收」**，
> 放在它后面才对得上；§十四（颜色）被五份文档按号引用，不为了排序去动它。

用户 10-21：「类似的问题到处都是，你全部查一遍页面上的展示，把**描述性内容全部收缩起来，避免过多的占屏**」
（先点名四维象限那三块：九条 caveat + 字段义 + 覆盖 + 出处，字比表长）。

这直接把 §十三 那条「`Caveats` 本体一律不许收」**改成按性质分流**——一刀切要么满屏灰字、要么把
"这一场只取了前 200 行"折进看不见的地方，两个方向都说过谎。现在的规矩是**一处实现、两条同时生效**：

| 件 | 位置 | 管什么 |
|---|---|---|
| code 分类 | `src/lib/caveatKind.ts` | ① **白名单制**：只有点过名的 code（`quadrant_design`/`entry_quadrant`/`zero_axis`/`rank_direction`/`coverage`/`universe`/`note`/`y_axis_levels`… 共 31 个）允许折；**后端随时能加的陌生 code 一律留在屏上**。② 第二道闸：名字里带 `truncat/empty/missing/unread/fail/stale/no_/partial/gap/mismatch…` 的，就算被塞进白名单也不折。③ **同名两用的一律不折**（见下面那条"第二轮验收"）。④ `note` 是通用兜底 code，对它再加一道**句式闸**（句子里出现 失败/读不到/取不到/截断/凑不满/点数不足/不一致/超时/已陈旧/回退 就不折）；句式闸**只管 `note`**，别扩到全部 code——那会把 `coverage`「短历史是 caveat 不是缺数」这类正常解释也顶回屏上，收缩白做一遍。 |
| 折叠块 | `DataPanel.tsx` 的 `CaliberFold` | 收 `caveats`＋`definitions`＋`coverage`＋`provenance`＋`notes`（后端散文）。它自己分流：`<Caveats items={visible}/>` 渲在 `<details>` **之前**（渲染顺序＝源码顺序，所以缺数类不可能被折），解释类进框；summary 必须报每一类的条数，并写「另有 N 条缺数／截断类声明没有折，在上方」 |

**仍然不折的**（比省屏幕优先，和 §十三 一样）：`popHint`、`role="status"`、`text-warning`/`text-destructive`、
"已达取数上限/只交前 N 名/不是全部/全场实有 N 只"、数值读数行与控件；**整屏就是说明文的卡不算密度问题**
（`/coverage` 那张「这些缺口会直接决定哪些页面永远是空的」——里面全是缺数声明，一个字都不折）。
另一条这次新增的取舍：**单行「出处：pg」不折** —— 折起来省不了一行高度，只多一次点击（`Quality`/`Datasource`/
`DataProcess`/`System` 各一处就按这条留着）。

**闸**（三条，都在 `frontend/test/`）：`caveatKind.test.ts` 5 条 —— 陌生 code 不折、缺数族不折、解释族才折、
**白名单里不许有对不上后端的死条目**（打错一个字母就永远匹配不上，测试还全绿）、拆分保序且空句子两边都不进；
`explainBox.test.ts` 新增一条钉 `CaliberFold` 的结构（visible 那份必须在 `<details` 之前、折叠体里不许
`text-destructive`/`role="status"`、唯一的 `text-warning` 只能是 summary 那句指路牌）；
再加各屏那条「尾巴块确实走这一处」。

**改动代价要记账**：本轮把 pages 那侧的尾巴块（`SectorHeat` 12 处 / `Confluence` / `VolumeDouble` /
`VolumeBreakout` / `Spike` / `Grouped` / `Screen`）与四维象限三块改走 `CaliberFold`，
于是有两条 10-19 写的 per-screen 断言（钉 `<Caveats items={d.caveats} />` 与 `<Provenance bits={…}/>`
的字面量）**必须跟着换**——换的是"这屏的 caveat 交给谁"，不是"这屏的告警还能不能看见"，
后者由 `caveatKind` 那条闸统一管，比每屏钉一句字面量更强。这类断言的改动一律在回报里点名，不许悄悄放宽。

**第二轮验收（同日，浏览器逐屏实测）查出四处，全部是本改造自己的问题**：

1. **折叠套折叠**。`CaliberFold` 里嵌的 `Definitions` 自带一层 `<details>`，于是同一份 25 条字段解释
   在 `/quadrant` 摆出**两行摘要**（外层「25 个字段解释」＋内层「这些字段是什么意思（25 条…）」）。
   修法：`Definitions` 加 `bare` 形参——字典的 markup 仍只有这一份，`bare` 时只交内容、不再套框；
   `CaliberFold` 传 `bare`。闸在 `explainBox.test.ts`（`<Definitions map={definitions} bare />` 必须在，
   不带 `bare` 的那种写法必须匹配不上）。**判据是浏览器里 `details` 的嵌套数**（`nested=0`），源码看不出来。
2. **白名单按名字收，收错了五个**。第一版是照 code 名字判的，逐条回后端读文案才发现
   `short_window`／`thin_window`／`min_bars`／`axis_weight_drift`／`group_series` 名字像口径解释，
   实际是后端**按当下这批** `caveats.append(...)` 出来的（「这些票的可用 K 线不足 40 日…：000001、000002…」
   「这一批里有 N 行凑不满 10 根倍数」「说明式轴权重与 `config.view_effective_binding` 不一致」
   「成员快照累计 N 天，M 日窗口需要 M 场」）——折起来就是把「屏幕上这几行的数不能和别的行横比」藏掉。
   ⇒ 入白名单的资格不是「名字像解释」，而是**这条 code 只出现在 `_NOTE`/`_caveats` 那种固定散文里，
   不带着当场的计数**。最险的一对：`entry_quadrant_null`（`_NOTE` 里那句「为空不代表斜率算不出」，可折）
   与 `window_entry_quadrant_null`（后端按本次行数 append 的「这 N 场的入口象限为空」，不可折），
   只差一个 `window_`。这条已经做成**机械闸**：`caveatKind.test.ts` 从后端扫 `append({…'code': 'X'` 的 code 集合，
   与白名单求交，交集只允许点名豁免（`note`/`future_function`/`y_axis_levels`，每条例外必须写理由），
   并且反过来要求豁免项仍在白名单里（撤了 code 却留着理由＝死条目）。白名单 36 → 31。
3. **每屏都重复的那两句挂在右侧 AI 栏头上**（`AiAnalysisPanel.tsx`：逐条点了才跑/只存本机/风险自担、
   带的是哪一份材料/本产品不校准不负责）。它们不在任何一屏的尾巴块里，所以第一轮全站改一遍也没碰到；
   现走 `ExplainBox`，并把 **caution 留在 summary 上**（「风险自担」「不校准、不负责」收起也看得见）。
   同栏那两句「这一屏没有登记可带的本页材料……持仓永远不登记」与空配置区的「还没有配置项」**仍摊着**——
   它们解释的是「这里为什么没有输入框/没有按钮」，折起来会被读成栏坏了。

## 十三之五、一张表不止交数，还要交「这一列叫什么、什么意思、跟谁比色、分母是谁」：列描述符一份出处（2026-10-22）

用户 2026-10-22 对着「交易体系榜」下面的历史分布说：
**「除了次日均值，再加几列 2日均值、3日均值、4日均值、5日均值」＋「后面那几列分别是什么意思，做个说明，说明默认收缩」**。
加列是表层，真正坏掉的是**那张表的中文列名手抄在前端组件里、说明写在后端 `calibers` 里** ——
两处各说各话，加第五列就必然漏改一处。收成一份：**列描述符随读数一起交出，页面只按它渲染**。

| 一份描述符里的字段 | 界面上变成什么 | 为什么不能留在前端 |
|---|---|---|
| `key` / `label` | 列头文字与格子取值同源 | 前端抄中文列名 ⇒ 与后端说明分叉（`systemEntryBoard.test.ts` 现在 forbid 组件里出现任何中文列名字符串） |
| `note` | 列头 `title` ＋ 默认收起的说明框里逐列一行（`<Definitions map={notes} bare />`） | 说明写在 `calibers`、列头写在组件，加一列就要改两处 |
| `signed` | 带不带正号（收益类带，占比/分位数不带） | 前端按列名猜正负号，新列一进来就猜 |
| `versus_base` | 只有点名的列与基线比色，**相等不着色** | 全列比色＝把"高低都算好"念成结论 |
| `denom_key` | 列头挂一枚 `N≥最小分母`，每格 `title` 给自己那一档的分母 | 见下面第二条 |

三条推论，与 §十三、§十三之二、§十三之三 并列：

1. **描述"列"的东西也是数据**。以前只把阈值（`thresholds`）和口径句子（`calibers`）单源化，
   列这一层漏了——它同样是"后端算出来的东西长什么样"的一部分。
2. **一个均值型读数必须带自己的分母**。`avg_2d…avg_5d` 要求"未来 N 根一根不缺"，
   窗口越长样本越少（实测基线 1,347,867 → `n_5d` 1,325,576），**四列不是同一批样本**；
   只交均值，屏幕上就会被读成"同一批票持有越久越赚/越亏"。分母落库、随读数交出，
   并在落库前自验单调不增（`check_stats`，不过就 `⚠️` ＋ rc=3，坏数不许安静进库）。
3. **"这一列没数"要自己念出来，而且不许折**。加列之后旧批次那几列是 NULL，整列 `—` 会被读成
   "持有 N 天一根都没凑齐"——那是两件事实。读侧按 **值与分母同时为 NULL** 判定"这一窗没跑过"
   （`0.0` 是合法读数，不算没数），发一条 caveat，code 带 `missing` ⇒ §十三之二 那道模式闸保证它留在屏上。

三行读数齐全（基线 −0.01/−0.02/−0.03/−0.04/−0.04，全过档 −0.08/−0.10/−0.23/−0.29/−0.66）；
