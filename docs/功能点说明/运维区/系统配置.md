## 13. 消息推送·渠道与定时计划（`NotifyPanel.tsx`，`System.tsx` 里挂在 `<LoopSwitchboard />` 之后）

标题原句：「消息推送（渠道与定时计划）」。**这一块管的是"把已经算好的东西送到手机/群里"**，
不参与任何计算：正文一律复用各屏现成读数（共振榜 / 筛选结果 / 自选明细 / 个股档案 / 持仓 / 市场概览），
所以"手机上看到的"与"页面上看到的"必然同源。判据细则在
[系统配置工作指南/14-消息推送渠道与定时计划](../../系统配置工作指南/14-消息推送渠道与定时计划.md)，
本节只管屏幕上这些格子的读法与动法。

### 13.1 抬头那一行汇总

`总开关开｜可用渠道 1/1 条｜ 就绪计划 1/1 条（在册 N）` —— 四个数都来自 `GET /api/notify` 的
`counts`（`usable_channels` / `plans_sendable` 是**每请求现算**的，不落库）：
渠道被停用或密钥变量不见了，`可用` 会当场掉下去，不需要等谁去改状态。
「在册」比「就绪」多出来的那几条，就是配了但发不出去的，逐条原因在它自己那行上。

### 13.2 渠道区（只有这四种，其余本程没有执行体）

| 屏幕上的东西 | 读哪个字段 | 动它会发生什么 |

### 13.3 定时计划区（发什么、什么时候发）

一行计划给三句话 + 五个按钮：

- 第一句 `09:05 每天（只交易日）｜发往 …` 由 `scheduleText` 拼自 `run_at` / `run_freq` / `weekly_days` /
  `trade_days_only`。**选了每周却没勾周几会反着提醒**（"实际会天天发"）—— 因为宿主 `freq_allows`
  是"判不了就放行"，写入面比它严、但旧配置还是这个形状。
- 第二句 `内容：…` 由 `scenesText` 拼：`策略共振榜≥2（只发其中 2 个策略）、个股量化档案`。
- 第三句 **`今天：…`** 整段来自后端 `today_label`（八档 `today_state`：
  `off/bad/not_today/not_trade_day/sent/waiting/in_window/missed`）。判据与执行同住
  `notifyconfig.slot_state`，**前端只决定颜色轻重、不重写句子**；这条是 10-15 补的，
  专门堵"到点却没发，而这件事在界面上不存在"。
- 按钮：**编辑 / 预览正文 / 立刻发一次 / 删除**。`预览正文` 打 `POST /api/notify/preview`，
  不发任何东西，交标题＋整段正文＋`会发给：…`＋逐条 `blocked` 原因；
  `立刻发一次` 走**与循环完全相同**的执行体（`force=True` 只绕过"今天发过了"，**不绕过**渠道不可用）。
- **保存这一格必须会说话**（10-17 用户点名「点保存计划，没反应，也没生效配置。也没有推送」）：
  表单里三处必填都当场标出（`计划名字（必填…）`、`＊必选至少一档`、`＊必选至少一条`）；
  「保存计划」**永远点得动**（原本名字空着就 `disabled`＝点了什么都不说），点下去若还差东西，
  屏幕中间列一张"还差这几样，所以这条没保存"的清单（判据 `missingParts` 与后端 `validate_plan` 前三条一字对应），
  并且**不发那个注定被拒的请求**；保存成功那句后面接的是
  「保存不等于立刻发：到点是后台每 60 秒一轮自己判的，今天发不发看这一行的『今天：…』，
  要现在就验一次点『立刻发一次』（那是真发到群里，也会进『最近发送记录』的账）」——
  休市日 + 「只在交易日」本来就一条都不会发，界面不解释就长得像坏了。
- 徽标（`planHealth` 七档）：不合法 / 没选渠道 / 渠道已删 / 渠道都不可用 / 部分可用 / 就绪 / 空正文 ——
  三种"发不出去"各有各的修法，不许合成一句"未就绪"。

每一档内容**自己有一套参数**（勾了哪档就多出哪几格；10-17 按用户"再多一些、再具体一点"从 6 档扩到 **17 档**，并把参数收成目录驱动）：

|---|---|---|

三条读法：① 数字框的**默认值、上限、单位、候选清单都从后端 `catalog.scenes[]` 来**（`fields` 那格就是这一档的参数描述符；前端不抄一份，抄了就会两处各说一遍「最多能发多少条」）；② **留空＝用后端默认**，不写进配置；填了才落 `scenes.<档>.<参数>`；③ 列表那一行的摘要（`倍量形态榜（倍量≥8，限定 1 个象限，2 只）、异动筛查（往回 5 场，偏离榜 3 只，2 只）`）**逐字由后端那句模板拼出**，重开编辑器读回的也是这些值。

**以后加一档内容、或给某一档加一格参数，只动后端**：`duanxian/notify.py` 加 `_blk_*` 并登记 `SCENE_BUILDERS`（＋三张条数表 `DEFAULT_LIMITS`/`MAX_LIMITS`/`SCENE_LIMIT_UNITS` 各一行）、`notifyconfig.py` 的 `SCENE_KEYS`/`SCENE_HINTS`/`SCENE_FIELDS` 各加一条 —— 界面自动多出勾选项、条数框与参数格，校验与摘要也自动跟上（少登记一处就会被 `test_六张登记表必须还是同一批人` 与 `test_描述符里登记的键执行体必须真的读` 判红；⚠️ 参数格必须是**那份读层接口自己接受的参数**，阈值归各页改，推送这一侧不新造判据）。

另：`min_hits` 共振门槛 + **策略多选**（`sources`，一个都不勾＝全部策略；
⚠️ 语义是"被勾中策略命中过的票"，票的其它命中策略照样列出，所以正文标题必须写"且必须有 X、Y 之一选中"）；
筛选规则多选 + 票池（自选池/全市场）；自选分组；**重点个股代码**

3. **三态：null＝没探到，不等于 false**：通达信看护四项、`is_trade_day`、`ready`、doctor 逐项 ok
   全按三态渲染（`tdxWatch.ts:36-40`；`jobsboard.py:626-628/691-693`——没有记录必须给 null，
   不许回退成"在跑/正常"）。`available` 也三态：**缺失＝没表态**——200 但没交 `available:true`
   判成 `200?`「不能算可用」（`probeVerdict.ts:32-34`）。**不可用时只交 `{available:false, reason}`
   不许带 rows**：日志白名单拒收、归档号不在当场名单、阶梯模块导入失败——三处都是 available:false＋
   reason＋空/无 rows（`logtail.py:80-99`；`jobsboard.py:868-878`；端点兜底 `vr/app.py:1519-1520/1691-1693`
   也只给空表）；面板端 `!available` 就只显示那一句原因、不渲染行（`CloseChainPanel.tsx:69-71` 等）。
4. **一次只改一件事**：所有写端点共用 `_job_patch_guard`（`vr/app.py:1405-1411`，多键 400 点名）；
   `set_setting` 先整体校验再落盘，一个键非法**整笔不写**（`duanxian/jobs.py:319-344`）。
   改完必须回新状态——后端没回就按"读不到"处理，「别在页面上假装成功」（`closeChain.ts:130`）。
5. **页头按钮管不到所有块**：它只重取 4 个 useProbe 驱动的格；其余块要各点块内「重新读取」。
6. **星号不许上屏幕**：后端散文字段（note/reason/explain/warnings/detail）渲染前一律 `plain()`
   （`datastate.ts:33-40` 注释点名 10-07 首页泄漏事故）；数据值不包 `plain()`。
7. **探测清单不带 `/api`、行文案拼回 `/api`**（见 §16 path 规则）；`slow` 只是文案，不改 45 秒超时。
8. **CAPABILITIES 行里 `where` 是路由不是端点**：`/api/pipeline` 404 那一行是**清单在探一个
   从未存在的端点**（`vr/app.py` 全仓没有 `@app.get("/api/pipeline")`），屏幕如实显示 404 未实现——
   这不是链路总览屏坏了（它读 `/review/expected-date` 等四个端点，`Pipeline.tsx:31-35`）。
   要改这行的语义，改 `System.tsx:67` 一处，别去造一个空壳端点把红字糊掉。
