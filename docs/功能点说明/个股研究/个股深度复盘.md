## 1. 这一屏是什么，因而它一定不是什么

**母体：地址里的 `symbol`——一只票。** 全屏凡是按票的块都读它，没有第二份"当前票"。

| 是 | 因此**不是** |
|---|---|
| 一只票的读数集中屏（本机判据 + 公开源 + AI 生成） | 不是另一套算法：凡是按票的块都没重算判据，读的都是各自那条链已经落库/已经实现的接口 |
| 可从别处**双击**带代码打开、也可从导航裸打开 | 不是"进来先给你看一只"：没有 `symbol` 就明说没选一只（§2） |
| 一份实现、多处调用的**宿主屏** | 不是把 `/stock-data`、`/grouped` 的代码复制过来：`StockData`/`DeepDive` 是原两屏的组件本体，撤掉的只是它们各自的页面外壳（大标题 + 自己的选票框） |

**实测数据现实（2026-10-16 上午起，本机）**：全市场 5,577 只，一发约 0.57~0.90 秒 ⇒ 一遍约 50~78 分钟；
回填跑到 3,500 只用了 73.6 分钟（预算 80 分钟到点自停，剩 1,774 只）；失败率前段约 10%、修完 NaN 那一刀后约 4%。
**11:08 收口**：那 1,774 只补完，库里现在 **5,577 只 / 192 期 / 627,294 行**（累计 331,579 + 单季 295,715），近 5 年单季有数 5,576 只。
三写真缺陷（都有测试或 DDL 注释钉住）：① 源里的 `NaN` 被 `json.dumps` 写成裸 `NaN` ⇒ PG 的 jsonb 拒收，
**整只票全部行写不进去**（实测 313 只折在这里）；② 预算用完那条返回缺 `seconds` ⇒ `main()` 汇总 KeyError，
"按设计收工"被读成"跑到一半崩了"（rc 1 而不是 4）；③ **一个天文数字的同比把整只票带走**：源在基期接近 0 时
给出的同比能到 1e6~1e8（库里现存绝对值最大 9.78e7），而百分数列当时是 `numeric(12,4)`（天花板 1e8）⇒
upsert 整批回滚，实测 11 只票（000408/000586/000776/000892/000901/000936/301131/301379/600201/600867/688197）
每只 ~170 行全部没落库，日志里就一句 `numeric field overflow`。修法：DDL 41 里加了一段**可重复执行**的放宽
（12,4 → 20,4，只在未来仍需要时发 ALTER），八列实跑回验过精度，再补跑这 11 只（17 秒 1,839 行，成 11 败 0）。
**没有**在解析侧把这个数抹成 NULL——源镜像就存源给的东西，"能不能当增速读"是读侧的事，
而读侧本来就没用它做外推（`financial_forecast` 自己按同季重算同比，源那一列只当"源是怎么说的"念出来）。
第四条是设计修正：`--only-stale` 原先只查"表里有行且过期"，
那 313 只一次没写成 ⇒ 永远进不了补跑名单，现在 union 上"主档里有、表里一行都没有"的代码。
第五条是**读侧的尺子**（同一天现查发现，不是防呆洁癖）：源那一族的比率在基期接近 0 时会给到天文数字
—— `002670.SZ` 近 20 期里有 **16 期**净利率超 1000%（现存绝对值最大 3.89e7）、`920575.BJ` **20 期全超**。
库里照源存（源镜像不删数），读侧按「率 >±1000%、源同比 >±1 万% 就不是这把尺子的读数」交 null，
并**必须报数**（caveat `source_ratio_absurd`，句子里带这一只被挡掉几格）——挡了不报名字等于静默藏数。
外推从来没读这一列（`financial_forecast` 自己按同季重算同比），所以这一刀只影响那几格显示，不影响任何预测。
**第六条不是数据缺陷，是处置方式的问题**（10-16 傍晚用户点名）：那 11 只最初是我手工补跑的，而"缺不缺"这件事
当时**根本没有一道判据**——旧 `verify()` 拿表自己当分母，缺 11 只照样印「100%」，于是补完也不知道明天会不会再缺。

**C. 量价走势（日 / 周 / 月，三块并排）**

| 步 | 内容 |
|---|---|
| ① 只读一处 | **只有 `market_data.stock_daily` 这一张表**：周线与月线由日线聚合，不另找源、不建新表。理由是本项目在涨停价、breadth 上犯过"三方不一致"——建表就有两份真相 |
| ② 复权口径 | 逐根按 `价 × adjustment_factor` 折算后再取本期极值（**一根日线的高/低只在它自己那一天有效**，跨除权日不会被互相拉成假影）。因子在最新一场为 1、越老越小 ⇒ 图上那是**以今天为基准的前复权形状**，不是名义成交价；每根同时交 `close_raw`，悬停两个都给。这一条在 `caliber`、`HARD_CAVEATS[adjusted_shape]`、悬停第三行各说一次 |
| ③ 期间归组 | `_grouped` 在升序序列上按"相邻同键"分桶：周线用 **ISO 周**（跨年那周不会分裂成两根）、月线用 `YYYY-MM`；标签交**期间起点**（周线给周一、月线给 1 号），所以三块的 `date` 含义不同但都是"这根代表哪一期" |
| ④ 区间涨跌 | `pct` 用**本期复权收 ÷ 上一期复权收 − 1**（不是与本期开盘比——按开盘会把整根实体读反）；第一期没有基期给 `null`，页面念「—」而不是 0% |
| ⑤ 上屏 | `GET /api/stock/price-volume-trend?code=&days=&weeks=&months=`（502 风格与同类判据页一致）→ `PriceVolumeTrend`：`md:grid-cols-3` 左日中周右月（**不是 `lg:`**：这一屏中间列最宽只有 1024px，`lg` 在常见宽度下永远不触发，用户看到的就是竖着叠成一列），每块上图（K 线 + 两根均线）下量柱，`partial` 那根**虚线描边**；判读（单位、缺数、两个收价、未走完）只住 `lib/priceVolumeTrend.ts` 一处 |

三处不硬凑：日线 60 根、周线 60 根、月线 48 根是**要的根数**，各块自己报"画了几根 / 本机一共几根"；本机日线最早 2021-08-02 ⇒ 月线最多约 63 根，次新股拿不到 48 根就少交几根；不足 6 根（`MIN_BUCKETS`）的那一块**只列读数不画线**（3 个点连出来的"趋势"是骗人的）。均线用整段可用历史算完再截断，所以最左边那根也有 MA——先截断再算会把窗口前 n−1 根画成缺口。

## 3.2 「个股信息」那一格里的 AI 公司说明（10-22 新增）

用户 2026-10-22 原话：「把 个股深度复盘 里面的 **个股研究（行情 · 估值 · 研报 · 新闻 · 财务 · 公告 · 资金面）**
喂给 AI，告诉 AI 总结成 400 字以内说明这家公司是干什么的，核心竞争力是什么，想象空间在哪，当前的基本面情况如何。
然后在 个股信息——这一只是什么 · 最近一场什么价 中 把 ai 的结论放过来。」
三个岔路口当场定了：**结论落库一张小表**（不是只留浏览器）／**只在按钮点了才跑**（不自动跑）／
**材料取"标题＋摘要片段"这一层**（8,000 字硬顶之下的取舍）。

| 件 | 位置 | 说清了什么 |
|---|---|---|
| 材料边界（唯一一处） | `duanxian/stock_brief.py::SEGMENTS`（19 段：profile、valuation、quote、percentile、financials、reports、news、announcements、blocks、conceptTags、hotConcepts、margin、blockTrade、holders、dividend、lockup、dragonTiger、fundFlow、investorQa） | 每段取几条（`cap`）、单条截多长（`clip`）、**这段是怎么读的**（`note`）。段序＝优先级：超上限时从最后一段往回削，被削的段自己带 `truncated`／`dropped` |
| 材料组装 | 同文件 `compose()`（纯函数：不碰库、不出网） | 交出 `material`＋逐段**取舍回执**（`taken`／`total`／`truncated`）＋`missing`。认不出的形状（含 FastAPI 的 `{"detail": […]}` 错误体）一律算"没读到"，**不写一行看起来像读到了的话** |
| 写入侧唯一的闸 | 同文件 `check_brief_text()` | 空正文／出现交易动作或点位（复用 `review_agent/product_policy.has_trade_recommendation`，不另写第二套正则）／超过契约 1.2 倍 ⇒ 拒收并把原因交回屏幕。**浏览器交回来的文本在这里重新过一遍**，不因它已过 AI 通道那一档就免检 |
| 落库 | `analytics.stock_brief`（`app/db/sql/50_stock_brief.sql`，主键 `(security_code, spec_version)`，`spec_version='brief-1'`） | 成功与失败**分字段**：`record_failure` 只写 `error`/`failed_at`，**绝不动 `brief`** —— 一次网络抖动不该抹掉上一次已生成的结论。`generated_at` 与 `input_fetched_at` 是两个时刻（材料是那一刻抓的，公开源会变） |
| 端点 | `POST /api/stock/brief/material`（组材料）、`POST /api/stock/brief/result`（成功/失败都走这一个，回库里那一行或 `saved:false`+原因）；读侧**并进 `GET /api/stock/facts` 的 `brief` 键** | 结论跟着那一卡一起出来 ⇒ 「双击带 symbol 开新窗」与「从导航进来」看到同一份。没这一行时 `brief` 是 **null**，界面说「还没生成过」，与"生成出来是空的"分开 |
| 话术 | `duanxian/prompt_slots.py` 新增类型 `stock_brief`＋内置槽位 `stock_brief`（四问、400 字契约、材料没给就写「材料未给出」、不给交易动作/点位） | 系统配置页可以改这份、也可以自建（`TemplatePicker` 已接在这格头上，屏上直接能看到用的是哪一份）。**这一档刻意没有 `{material}` 占位符**：材料走这条通道的 `context`（硬顶 8,000 字），话术走最后一条消息（硬顶 4,000 字），塞进同一个模板会让两个上限互相挤 |
| 页面 | `components/stock/StockBriefBox.tsx` ＋ 判读层 `lib/stockBrief.ts`（叶子，`node --test` 直接跑）＋ 出网那半份 `lib/stockBriefRun.ts` | 走**红线档**（`chatStream(...)` 不传 `taskKind` ⇒ `page`），不是右侧「AI分析」那档允许给价位的 `analysis`；缺数与失败摊在框外，只有"看了哪些材料/这一格口径"进折叠框；按钮被拦时列出「还差哪几样」且**不发注定被拒的请求**，不静默 disabled |

**一条本机数据现实（10-22 现查 600519，别再按"研报正文"设计）**：东财研报那个源**只交标题、机构、评级、预测 EPS/PE 与 pdf 链接，正文与摘要不在返回里**（200 条 × 每条 1,355 字符，字都花在那些数字字段上）；akshare 新闻的「新闻内容」那一栏实测是别家代码的盘后数字串（`300403 汉宇集团 8.58 0.35 …`），不是这只票的叙述 ⇒ 这两段喂的是**标题**。所以"标题＋摘要片段"这一层里，摘要只有财务/估值/资金面那几段真有，研报与新闻给的是题名。

## 8. 不许破的纪律

1. **一只票一个真源 = 地址里的 `symbol`**。任何一块自己再存一份"当前票"，就会复现 10-14 在 `/grouped` 抓到的
   事故（高亮的行与档案不是同一只）。打字的内容（`draft`）与已提交的（`symbol`）必须分开——半截代码不许发请求。
2. **打字不写地址**。只允许"选中/提交"那一刻改 URL（`:37-44 commit()`）：每个字都换 URL 会让个股研究
   拿半截代码出网，还会塞满浏览器历史。
3. **不带传参就不替你挑**。不许写死默认代码、不许用界面状态把"上次那只"自动种进来当默认值。
4. 老地址 `/stock-data`、`/agent/deepdive` 只做跳转，**不再各自是一份页面**（两个入口指同一份内容会让人以为
   库里是两套数）。代价：`Navigate` 不保留查询串，带 `symbol` 的老书签会落到空 picker——屏上老实说没选一只。
5. **开新窗只有一份实现**（`lib/openStockReview.ts`）。弹窗被拦的告警不折进默认收起的说明框。
6. 每一块都走各自的只读接口，本页**一个判据都不重算**；中文标签一律念后端交出的那一份。
7. 出网/付费那一步（多空辩论）必须由人点发；进页只读本机最近一份报告。这一屏没有把"自动跑"扩大到花钱。
8. 那一格 AI 说明（10-22）跟着同一条：**只有点按钮才发起**，页面里没有任何 effect 会去抓材料或调模型。
9. 这一格走**红线档**（`chatStream` 不传 `taskKind`），不许改成右侧「AI分析」那个 `analysis` 档——
   那一档按设计允许给参考价位与止损，而这一格只放"这是一家什么公司"；入库前写入侧还有一道
   （`check_brief_text`：空正文／越界／超契约 1.2 倍都拒），浏览器交回来的文本不免检。
10. **材料边界只住 `duanxian/stock_brief.py::SEGMENTS` 一处**：哪几段进、每段几条、单条截多长、
    以及「源本轮共几条 / 实际喂进几条」的回执都在那一处算。页面只把各段**原始返回**交过去，
    不替模型挑、不自己数一遍——数了就成第二份真相，"研报 200 条只喂了 8 条"这件事没人能核对。
11. **成功与失败分字段**：重跑失败只写 `error`/`failed_at`，不动 `brief`；库里没这一行 = 「还没生成过」，
    与"生成出来是空的"是两句话，界面上必须是两句。缺数与失败声明摊在框外，不折进任何默认收起的说明框。

## 9. 可疑点（本轮撞到、写文档时保留屏幕原样）

1. **`ys.ui_pref` 的 `grouped.dossier_code` 成了没有写入方的键**：随分组自选那个手输框一起退场
   （`duanxian/ui_pref.py:32` 仍登记着、库里那行也还在）。要不要撤登记，等用户定——撤登记要动后端＋改
   `tests/test_ui_pref.py` 里那三条相关断言，且得重启 8910，本轮没做。
2. **`StockPicker.tsx` 没有换成共用控件**：它只被 `pages/Scores.tsx` 用，而 `/scores` 的路由 10-14 已撤
   （孤儿页）。给一个进不去的页面接控件没有意义，留原样。
3. 本机名单那一叠现在在两屏都出现（`/grouped` 与 `/my-stocks`）。是同一个组件、同一个
   `vr-watchlist` 键，加删互通；但"两处都能改一份数据"这件事用户如果觉得重复，撤一处只需删掉调用点。
4. 「个股研究」那一块自动出网取数（十来个 GET），所以从别处双击开新窗时**会有几秒白等**；
   这是 `StockData` 原有行为（10-14 记在《个股研究.md》），不是新页引入的。要不要给这一屏加"公开资料要点一下才取"
   的开关，属于性能/敞口话题，未动。
5. **右侧「AI分析 · 本页上下文」这一屏有五个登记方在抢同一个槽**（`lib/workspace/pageAskAiStore.ts` 的规矩是
   "一次只有一屏在册"，那是**按页面**设计的）：`StockFacts` / `FinancialPeriodBoard` / `PriceVolumeTrend` /
   `VolumeSimilarityBoard` / `StockData` 各自都登记一份材料，谁的数据**后到**谁就覆盖前面的。
   10-16 实测：全部加载完后栏里念的是「个股研究 · 600519」（`StockData` 最慢，所以它赢）。
   后果不是崩，是**你想要哪一块的材料由加载顺序决定**，界面没有选择入口。
   本轮只把量价走势按同一形状接进去（没新增机制），要收口得先把登记表改成"一屏多份、栏里可选"，
   那是共用层的地基改动，牵动 `/grouped`、`/quadrant` 等八个调用点，未动。
   登记文本本身老实（写明"带的是哪一块的读数"），所以不会读成假话。
