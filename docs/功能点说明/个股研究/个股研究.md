## 1. 这一屏是什么，因而它一定不是什么

**母体：一只手输进去的代码。** 整屏只有一个标的，所有卡片都是它的公开数据切面。

由此推出四条读法，任何一条被页面打破都算缺陷：

| 是 | 因此**不是** |
|---|---|
| 单票详情聚合 | 不是榜单：全屏**没有一张 `<table>`、没有 `SortHeader`、没有 `useTableSort`、没有 `useTableCellHighlight`**（10-14 现读 `grep -c` = **0**）。所以「逐列点击实测排序」这一整套验收对本屏不适用，也没有 `sortKey` 死键风险 |
| 抓公开源 | 不是「库里算好的判据」：与「量化选股」那一组屏本质不同。别把它读成一叠量化结论 |
| 原始读数 + 公开事实 | 不加权、不评分、不给买卖。唯一的机械分档是「财报速览」那几张标签，且**阈值硬编在前端组件里**（§6 #4） |
| 无日期/窗口控件 | 没有「选哪一天」「取几场」这类开关；连「重新取数」按钮都没有——**换代码或刷新页面 = 重取**（§2） |

## 7. 与相邻屏的分工（为什么这一屏和 `/grouped` 都在，不是重复）

| | `/stock-data`（本屏） | `/grouped`（分组自选） |
|---|---|---|
| 母体 | 任意一只票（手输代码） | **你自己那一组票**（库里 48 组 / 1,333 条成员行） |
| 取数域 | 17~18 个**在线公开源** ＋ 1 个本地库接口 | **全部读本地库**（这一叠不新算任何指标） |
| 口径层 | **原始读数**（35 项指标，不含权重）＋公开事实 | **已加权的判据与榜单归属**（象限/八分量/倍量/启动/埋伏/突破/交叉，档案八块 ＋ 该支票的趋势量化计算） |
| 缺席措辞 | `gaps`（只有「取数失败」被点名）＋ `available:false` | 三分法 `read_failed / not_computed / not_on_board`（`duanxian/stock_dossier.py:13-17, 87-100`） |
| 交互 | 无表、无排序、无格子高亮 | 明细表 15 列 14 个 `SortHeader` ＋ 行列交叉高亮 |

分工句钉在共用组件里，双向指认：`IndicatorGrid.tsx:57-62`「八项能力加权分与它的窗口斜率在分组自选——选中一只票后，量化档案下面那一叠就是；**35 项技术指标一直在 `/stock-data`**」，对应 `Grouped.tsx` 那段（10-14 撤 `/scores` 后写的 `router.tsx:58-62` 注释也指回这里）。

`IndicatorGrid` 现在**只有本屏在用**（另一个 import 它的 `pages/Scores.tsx` 已不挂路由，10-14）。抽成共用组件的理由写在 `IndicatorGrid.tsx:9-11`：端点曾 200 可用却零页面调用，验收标准是「这些字段真看得见」。

## 8. 不许破的纪律

1. **别把这一屏写成量化结论屏**。它交的是公开源事实与原始读数；加权分、象限、形态榜在 `/grouped`。
2. **空 ≠ 没查到**：本屏目前确实把两者混在一起（§9 #2）。在补上「取到空列表」的点名之前，文档与界面都不许说成「该票没有这项数据」。
3. **单位换算本应在上游**。本屏的多处「亿/万」是前端除出来的（§3 #9），已知违例；新增块时不许再往这个方向加，要改就改后端交什么量纲。
4. **A 股接口只收 6 位纯数字**（`_validate`，`vr/app.py:67-71`）。前端已经去后缀，别再往这些接口发 `000001.SZ`。
5. **别承诺实时**。多数接口有 15~30 分钟服务端缓存（§4），点「查询」不保证拿到最新；只有 `quote/valuation/reports/news` 每次都打在线源。
6. 这一屏的接口全部只读 GET。**别给它们加写语义**（写界面状态走 `/api/ui-pref`，写账本走 `/api/review-note`，各自有闸门）。

## 9. 可疑点（本轮实测撞到，写文档时保留屏幕原样）

1. **P0：北证票被一个接口的 404 拖垮整屏。** 10-14 实测 `/stock-data?symbol=920627`：屏上只有导航、页头、一条黄字「本次取数失败：行情。」和一条红字「未取到 920627 的行情」，**正文 innerText 全长 386 字符**，「财报速览／技术指标／估值历史／近期研报／龙虎榜／板块归属」**全部为 false**。而同一时刻 `/api/stock/indicators?code=920627` 是 200、`count:34`（当日换底后为 35），`/api/financials`、`/api/dragon-tiger`（9 条记录）、`/api/blocks`（12）都有数——**库里明明有这只票的指标（当日 34 项、同日换底后 35 项），屏上看不见**。成因是 `{val && ( … )}` 这一整段闸门（`:332`）。要修就把 `aShare` 那几块（含 `:361` 的指标块）搬出闸门，或让 `val` 为 null 时仍渲染「其余有数的那几块」。
2. **P1：「取到空列表」静默消失，只有失败被点名。** 实测 `920627` 的 `fund-flow` 返回 200 空数组：不进 `gaps`、卡片整块不渲染，屏幕上没有任何一句说「这一路取到了但没记录」。与仓库「read_failed / not_computed / not_on_board」三分规矩不一致（那是 `/grouped` 档案独有的措辞体系）。
3. **P1：这一屏不在系统自检清单里。** `System.tsx` 的 `CAPABILITIES`（10-18 现读：`const CAPABILITIES` 在 `:52`，**现数 42 条**；10-14 那版写 29 条）里**没有 `/stock-data`、也没有 `/stock/indicators`**。后果正是那条老话：接口在跑却没人验。修法：补一条 `{ path: "/stock/indicators?code=000001.SZ", label: "35 项技术指标（本屏唯一读本地库的接口）", where: "/stock-review" }`——这是代码改动，本轮只登记，不动。⚠️ 顺带记一条**屏幕上真正会说谎的一格**（10-18 现读 `System.tsx`）：那条质量闸的 label 曾写「质量闸（**24 条规则**）」，而 `config.quality_rule` 现查是 **30 条（23 error + 7 warning）** —— **同日已改代码收口**（改成"条数由接口现算，这里不抄"，六处注释/文案一起去数 + `npm run build`，浏览器实测 `/system`、`/quality` 里 `24 条` 0 命中），详见 `数据链路/质量闸.md` §数据现实。
4. **P2：`investor-qa` 会混进别家公司的问答。** 实测查 `920627` 返回的 30 条里出现「水羊股份」的问答，`company` 字段与查询票不符；是源站返回体自带的脏值，不是前端拼装。用这一格之前先对 `company`。
5. **P2：模块内标题三名并存**——卡片/页头「个股研究」、平铺映射「个股数据」（`modules.ts:72`）。不影响功能，但会让人以为有两屏。
