## 不许破的纪律

1. **五接口白名单是双层硬闸**（`deepdive.py:17-19` + `public_worker.py:17/:25-26`）。给这一屏加任何新数据入口＝同时改两处；
   任何入口若指向本地持仓/笔记/提醒表，直接违红线（§10），先补 `TestPersonalDataNeverReachesPrompt` 同族测试再说。
2. **失败不覆盖旧报告**：三份索引只在全部闸通过后一次写（`deepdive.py:99-112`）；不许改成先清 latest 再跑。
3. **同 `request_id` 重放不重付**：恢复路径必须带原体（`deepdive.py:57-62` + 前端 pendingKey）；
   前端任何「重试」按钮若新造 request_id，等于重复烧钱。
4. **回环转换层不许把真密钥交给引擎**（`responses_bridge.py:5-7`；`runtime.py:686-690`）；引擎只拿一次性令牌，会话 TTL 2h/上限 8（`:22-23`）。
5. **422/错误不回显请求体**（`api.py:136-139` 注释原句：验证错误默认会把含 API key 的整个 llm 对象吐回来——「Never echo it」）。
6. **缺数是空，不是 0，也不是 false**：idle ≠ 失败；`{}` ≠ 报告坏了；`ai_source` 缺 ≠ 没接 AI。每个分支的屏幕句子见 §2.3。
7. **本屏无日期闸是设计**（资料锚在「此刻」：实时快照 + 最后已收盘 K 线，`data.py:66-98`），但屏幕必须继续显示行情自带的时间声明
   （「行情时间…」「已收盘K线截至…」），不许前端把 `generated_at` 改写成「今日行情」。
8. **上限要说出口**：追问上下文 7500 字截断必须带那句声明（`DeepDive.tsx:130/:233`）；`max_rounds=1` 意味着这是**一轮**辩论，
   界面与文档都不许称「多轮交锋」。
9. **话术只有一份**：深挖口径改动只能改 `prompts.py:55-65`/`schemas.py`（模型侧）与 `agents.py`（结构），页面不许自写句子；
   本屏也不经 `prompt_slots` 的配置通道（§10 行 2）。
10. `POST /api/deepdive/run`/`/chat` 的 409 封条（`server.py:1529-1531/:1588-1590`）不许回滚成可执行路径——那是烧钱的旁门旧入口。

## 可疑点（如实记录，不当结论）

1. **触发无二次确认**：本仓库 §5.3 纪律（`Jobs.tsx:313`）要求触发前看得见「向哪些域名出网 + 写哪里」；
   这一屏按下去直接 POST 付费，屏幕上只有含糊一句（§4）。是缺口不是实现。
2. **问财在深挖通道疑似恒缺**：取数子进程 env 白名单只在 `name in DAILY_CALLS` 时才注入 `IWENCAI_API_KEY`
   （`public_worker.py:32-33`），深挖五接口不在 DAILY_CALLS ⇒ `data.py:182` 的 `os.environ` 检查在子进程里恒假
   ⇒ 题材卡的「概念/题材（问财）」一段大概率永远显示「未取到」。真烧一次才能定论，本文标**未实测**。
3. **深挖任务的重启收尸句写着「复盘已中断」**：基类共用文案（`daily.py:177`），深挖档案恢复时用户看到错的主语。
4. **「从没跑过」与「latest.json 坏了」屏幕同形**：`{}` 两种成因不分（`server.py:1567-1573`），都不出声。
5. 空态「约 2-3 分钟」无实测支撑（硬上限 20 分钟；7~14 次调用）。
6. `state_warning` 路径下「查看最近完成报告」按钮带回旧版（§1 行 6），新版本要靠轮询里已捕获的 job_id 走接口⑤——
   若用户刷新前没捕获到 job_id，这一版报告在界面上没有入口（文件仍在 `versions/`）。
