## 1. 页头（`Journal.tsx:1719-1758`，外壳 `export function Journal()`）

### 1.1 三个 tab 为什么是 `?tab=` 而不是三条路由

- 一级模块「交易日志」的 `pages` **只有一条**（`modules.ts:48-50`）。`modules.ts:44-47` 的注释原话：
  复盘笔记与提醒**不另开一级模块**——「同一件事的三个视图挂在这一页的三个 tab 上（`pages` 只有一条，
  所以 tab 用 `?tab=` 而不是路由 —— 挂两条导航条目会指向同一路由，而那条测试要求
  “每个导航条目都有注册路由”）」。这条测试就是 `frontend/test/modules.test.ts:69-85`
  （导航↔路由双向覆盖＋模块入口路由不得重复 `:58-59`）；挂两条同名 `to: "/journal"` 会让侧栏高亮
  判定（`moduleFor()` `modules.ts:59-61`）变成三选一。外壳注释（`Journal.tsx:1706-1712`）另给一层
  理由：09-28 用户裁定「笔记挂在页面内」，查询参数可分享、可书签。
- 解析：`raw = params.get("tab") ?? ""`，认不出的 `?tab=` **落回流水**不给白屏（`Journal.tsx:1720-1722`）。
- 点 tab 按钮 = `setParams`（`replace: false`，`:1740-1743`）——**切换本身不发请求**；被挂上的
  tab 组件自己 mount 时发首拉（下面三节各列各的）。会话/恢复用的稳定标识是 `chatPageFor('/journal')='交易日志'`
  （`modules.ts:71`），与界面标题是两套词。

### 2.2 「自我体检 · Self Check」（`:1490-1553`，`stats.available` 为假整段不渲染）

- `Caliber` 气泡（`:1494-1506`）钉死口径：胜率＝盈利÷(盈利+亏损)、**持平不计入分母**、全持平显「—」不显 0%；
  平均/最好/最差按盈亏**百分比**与仓位无关；净盈亏只汇总**填了成交明细**的已实现金额、样本数常小于总笔数；
  **所有盈亏都是净额已扣佣金印花税过户费**；百分比与金额是两个口径；「全站胜率口径一致」（journal `_bucket_stats`
  与 `modes._stats` 同算法，由 `tests/test_core_logic.py:4824-4831` 钉住）。
- 头部读数（四/五格）：平均每笔（`signed`±x.xx%、按 `pctColor` 着色）、胜率（`rate`＝四舍五入整数百分比）、
  最好一笔（绿）、最差一笔（红）、净盈亏（仅 `overall.net_pnl != null` 时出现第五格，「净盈亏（元，N 笔有明细）」）。
- 底句：「共 N 笔（M 笔填了盈亏）。⚠️ 这是对你自己历史行为的统计，不预测市场、不给下一笔建议。」
- 五组 `BucketRows`（`:45-67`）：按情绪环境/按打法/按是否按计划/按当时板位/按持有周期，每桶一行
  「桶名 ±均值 胜率 N% `scored/count 笔有盈亏`」；`0 < scored < 10` 带黄字「· 样本少，别下结论」；
  全桶 `count=0` 的组**整块不渲染**（`:47`）。分组判据在后端 `stats()`（`journal.py:645-692`，
  板位＝首板/2板/3板及以上/非涨停；持有桶按自然日，「同日买卖(底仓待核)」桶 hint 原话「按自然日分组；
  同日买卖不等于已核实可执行的做T」）。

## 6. 不许破的纪律（红线优先）

1. **⛔ 复盘笔记/提醒/交易日志（含风控、模式卡、费率）绝不进任何 AI 提示词**。规矩逐处写在代码里：
   `duanxian/journal.py:9`（源头）、`review_notes.py:18`（笔记与提醒继承）、`server.py:972` 与 `:1237`（两段端点各一句）、
   `vr/app.py:1699`（两张表的 HTTP 外壳）、`risk/at_risk/inbox/excursion/attribution/modes/positions` 各自 docstring
   末行。可执行闸：`tests/test_core_logic.py:1063-1098`（`TestPersonalDataNeverReachesPrompt`：
   10 个喂 prompt 的模块 `synthesizer/reflection/prompts/structured/emotion_metrics/market_facts/stats_context/
   verification/theme_tree/intraday` 源码里不许 import `journal/risk/attribution`；复盘产物字段泄漏词根扫描）、
   `:6558-6567`（同一批模块不许 import `positions`）。**这一屏没有任何 AI 按钮是刻意的**：右侧「AI分析」栏的
   「问 AI · 本页上下文」只读登记表（`AiAnalysisPanel.tsx:33`），登记方只有首页盘面数据/个股研究/自选股三页
   （`test_ai_rail_reads_the_page_registry` `:6536-6556` 点名钉这三页＋断言旧抽屉组件已删）；
   `Journal.tsx` 全文 0 处 `usePageAskAi/chatStream/llm`（grep 证实），所以这一屏那一格显示的是占位原句
   「这一屏没有登记可带的本页材料，所以这里不放一个点了没反应的输入框。……持仓（重点关注）**永远不登记** ——
   成本与盈亏不接入任何 AI」（`AiAnalysisPanel.tsx:114-120`）。持仓页禁令的钉法：
   `test_portfolio_page_feeds_nothing_to_ai`（`:6520-6534`）在 `Portfolio.tsx` 源码里禁 `AskAiButton/AskAiChat/usePageAskAi/
   pageAskAi/aiContext/pageMaterials/chatStream//chat` 八个标识符。AI 预设材料的白名单只有
   `/quant/sector-heat`、`/market/emotion`、`/qd/board-ladder` 这类行情接口（`aiPresets.ts:29-43`），无一个个人记录端点。
2. **草稿不联网；落盘必带 `_DEFAULTS_BUILDER` 版本戳**（实现与后果见 §3.4）。改判据不改版本戳 ⇒ 缓存命中把旧草稿
   发回界面（09-28「巴西央行行长」实测，`review_notes.py:283-286`）；当天落盘 ⇒ 把"数据没进来"的样子骗到明天
   （`:421-428`；测试 `test_review_notes.py:279/:285`）。
3. **`machine_baseline` 只增不改**（`_merge_baseline` `:187-193`；SQL `:15-18/:70`；测试 `:129/:136`）；
   只有"存进去与机器草稿一字不差"才留痕（`:210-211`）。覆盖它＝「未改/已改」永远翻面。
4. **到期日由后端按交易日算，界面只转述**（`Reminders.tsx:14-18`；预览与入库同一个 `due_on()` `:57/:177`）。
   界面自己"今天+7天"＝把第 7 个交易日算进国庆假期（SQL `:20-23`）；日历超期不冒充（`calendar_covered` 一路传到
   `due_label` 后缀与条目黄句）。含当日与否：到期＝起算日**之后**第 N 个交易日、**不含当天**（SQL `:95`）。
5. **13 列全 text 不许定长**（实测 6186/1231 字，SQL `:11-13`）；`FIELDS` 是唯一真相源，界面不许抄中文列名
   （`ReviewNotes.tsx:11-17`；`test_review_notes.py:47-49` 钉注册表与 DDL 逐字同序）。
6. **账本损坏必须 500 出声，绝不交空表**（`journal.py:135-146`、`server.py:981-984`；空表会被读成"记录丢了"，
   下一次写入就真的覆盖整本——测试 `test_core_logic.py:4468-4473`）；schema 不匹配先迁移＋备份、迁不动拒写（`:149-157`）；
   NaN/Inf 进账本前当场拒（`:470-474`）；读-改-写串行锁（`:130-132`）。
7. **缺数是空不是 0**：未设止损＝「未知」不是 0 风险（`at_risk.py:9-20`）；持仓中≠未填明细（三态注释
   `Journal.tsx:1615-1617`）；版本样本不够的胜率/中位不补 0；持平不计胜率分母；MFE 可为负不许硬 `+`；
   `bars_inner=0` 是「仅上界」不是「0 日可靠」（`:647-649`）；缺数行恒排最后（`useSort.ts:70-74`）。
8. **默认值≠推荐值**：费率初值与风险宪法初值都必须在界面上自证「不是推荐值」（`Journal.tsx:866-867/:1238-1239`、
   `journal.py:48-51`、`risk.py:38-40`）；「还在用初值/默认阈值」徽标不许摘。
9. **只统计自己、不给建议**：页脚、各面板脚注的「不是对下一笔的预测/这是你自己的历史」句式是产品边界
   （`journal.py:8`、各面板原句见 §2）；计划止损必须下单时写、事后改留痕 `planned_edited_at`（`journal.py:576-579`）。
10. **tab 用 `?tab=` 且 `pages` 只有一条**（§1.1）；认不出的 tab 值落回流水不给白屏（`Journal.tsx:1721-1722`）。

## 8. 可疑点（照实记下，不替后端说话）

- **笔记 tab 的「七件事」与实测不符**：`ReviewNotes.tsx:252` 标题句写死「七件事」，但 chips 数＝后端
  `question` 非空的字段数，实测 **5**（plan_market/plan_stock/view_market/view_news/view_stock）。
  `tests/test_review_notes.py:63` 只断言 `>= 5`，测试名却叫「七个自问」——句子、测试名、数据三者对不齐。
- **红线闸的词表比声明窄**：`test_core_logic.py:1077` 的 import 扫描只查 `journal/risk/attribution` 三个词，
  `review_notes`（笔记/提醒）、`modes`、`inbox`、`excursion`、`at_risk` 不在被禁词内（现状干净：全仓 grep 显示
  10 个 prompt 模块没有任何一处 import 个人族）。也就是说「笔记/提醒不进 prompt」目前靠**文档＋界面句子＋
  复盘产物字段扫描**兜着，import 闸本身还漏着这几个名字。
- **Excel 历史未导入，屏幕上零交代**：`ys.review_note` 实测 0 行，历史卡因 `rows.length===0` 整卡不渲染，
  界面没有任何一处说「2026-09-28 之前有 132 行真实笔记在桌面 Excel「做与直觉相反的事」里、未导入」
  （这个事实只存在于 `review_notes.py:3-4`、`19_review_note.sql:4/:55`；前端源码 grep `Excel` 0 命中）。
  下一个读屏的人会把"库空"读成"没写过"。导入工具/一次性搬运：未在册。
- **`AtRiskPanel` 在 `available=false` 时连后端 reason 都不显示**（`Journal.tsx:311` `return null`）——
  与「个人风控」面板"没数也要把规则编辑器摆出来"的处理不一致；后端明明给了「当前没有未平仓的持仓…」那句解释。
- **`view_stock` 同格并存"草稿有字"与「这次没取到」**（实测 §5）：`missing` 是先写的、`put` 后有字也不回收
  （`review_notes.py:577-604`）。语义上没错（封板质量缺、晋级率在），但一格里同时出现两种标记容易被读成矛盾。
- `/api/journal/list` 的 `limit` 上限 1000 但界面写死 200/页；`update` 端点只接 `fills/note/as_planned/planned_*`
  五类字段，**日期与代码改不了**——界面没有明说这一条（想改只能删了重录，而那会丢 `created_at` 证据链）。
