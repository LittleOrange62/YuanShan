# 功能点说明 · 每屏一份（按系统目录命名）

用户 2026-10-11 点名：「把每个功能点都写成文档存 docs 里面，命名规则按照系统目录来；
比如 量化选股：倍量形态 —— 把里面的每一个功能点和展示内容全部详细写下来。」

2026-10-14 晚用户又点一条：**「功能点和一些参数指标的说明内容，尽量再写的都更完善一些，
因为很多功能点我也不太清楚是怎么做出来的」** —— 所以这一套文档的合格线不是"屏幕上写了什么"，
而是**"这个数是怎么来的、哪个参数能动它"**能不能不看代码就答出来。下面骨架里新加的两小节就是为此。

## 目录规则

```
docs/功能点说明/<一级模块>/<页面标题>.md
```

- `<一级模块>` 取导航里的模块名（`frontend/src/lib/workspace/modules.ts` 的 `MODULES[].title`）；
  侧栏底部运维区那三条不进 MODULES，单独放 `运维区/`。
- `<页面标题>` 取该模块 `pages[]` 里的 `title`（**不是** `CHAT_PAGES` 那个稳定标识 ——
  那是会话/恢复用的，与界面标题两套词，例如 `/backtest` 界面叫「历史统计」而标识是「涨停样本统计」）。
- 文件名与导航文字**逐字一致**，这样"导航点进去的那一屏"与"文档里的那一份"能一对一找到。
  有斜杠的标题（`重点关注（持仓）`）保留括号，不替换成下划线。

## 不是"功能点"的文档怎么命名（用户 2026-10-12 裁定）

我先把一份公用组件用法放成了 `frontend/docs/表格筛选与高亮组件使用指南.md`，用户改口：
**「这个不属于功能点。命名按类型去分，前面加个类型，比如《公用组件：表格筛选与高亮组件使用指南》」**。

- 规则：`<类型>：<标题>.md`。冒号用**全角 `：`**（文件名里 ASCII `:` 是非法字符）。
- 这份目录（`docs/功能点说明/`）**只放逐屏功能点**，文件名逐字等于导航文字；
  跨页面复用的东西（组件/Hook/交互纪律/口径契约/运维手册）属于**别的类型**，按上面那条加前缀，别混进来。
- 这类文档现有的两份：
  `frontend/docs/公用组件：表格筛选与高亮组件使用指南.md`（交互组件：筛面板、交叉高亮 hook）；
  **[公用组件：一份实现多处调用的读数块清单](../../frontend/docs/公用组件：一份实现多处调用的读数块清单.md)**
  （2026-10-14 用户点名"遍历功能点、把重复的收成一块、让两屏互相调用"之后的**台账**：
  每一块只写一处实现、每个调用点点名到行，并列出还没收的重复）。
  ⚠️ 这类文档必须写清**接到调用点的有哪几屏**，不能只写"提供了哪些组件"；组件搬家时它的测试
  （`frontend/test/*.test.ts` 里那几处 `readFileSync` 断字符串的）要一起搬，不许删断言。
- **判据与参数的主表不在这一目录里**，在
  **[数据加工工作指南/10-每个数怎么算：判据、指标与参数总表](../数据加工工作指南/10-每个数怎么算：判据、指标与参数总表.md)**：
  同一个判据（倍量、埋伏分、集中度、操作分…）往往两屏以上在读，逐屏各写一遍公式必然漂。
  所以**公式与阈值只写在总表那一处**，每屏的《功能点说明》用一行链过去 + 只补"这一屏多出来的那一步"。

## 每份文档的骨架（照样板写，别自创小节名）

样板：**[量化选股/倍量形态.md](量化选股/倍量形态.md)**（用户给的那个例子，先把它写完）。

| 小节 | 必须回答什么 |
|---|---|
| 0. 坐标 | 导航位置/卡片入口/路由（`router.tsx` 行号）/页面组件文件/接口与参数上下限/视图函数/读哪些表/谁写库（每日链第几步的 `id` 与模块）/系统配置自检在册与否/字段含义的出处（库注释在哪一行） |
| 1. 页头 | 标题、副标题、每一个控件（复选/下拉/输入/按钮）的默认值、点了会怎样、是前端过滤还是重新发请求 |
| **这个数是怎么来的**（缺这一节就不算写完） | **链路五步，一步都不许跳**：① 原始来源（哪个渠道/哪张源表/什么时候由哪个作业写）→ ② 落到哪张表的哪一列（主键、`spec_version`、谁写）→ ③ **判据与公式**（阈值、窗口、权重各住在哪个文件哪一行；本文档不复述数值，指过去总表）→ ④ 读侧怎么组装（默认参数、上下限、缺数怎么变 `NULL` 而不是 0、`limit` 截断在哪一步）→ ⑤ 屏幕上哪一格读它（标签、单位、悬停、缺数显示）。**每步都要能一句话复述给不写代码的人**，并且给出一个带真数的算例（§算例） |
| **参数表** | 这一屏每一个能动它的数：名称 \| 默认值 \| 允许范围 \| 在哪里改（屏上控件 / 系统配置那一格 / 只有代码里那个常量）\| 改了立刻影响哪几格 \| 要不要回算（改了判据要不要换 `spec_version`、旧行留不留）\| 改错的后果（被拒、静默忽略、还是屏幕说假话） |
| **算例** | 拿**一只票 + 一个真交易日**把上面的公式走一遍：给的取数命令（curl 或 psql，可粘贴直接跑）→ 屏幕读数 → 中间量 → 为什么是这个结果（含"缺数所以是 `—`"那种）；日期与实测方式写在旁边，超过两周没重验就标「待重验」 |
| 2..N 每一块 | 面板 `note` 原句 → 头部读数行 → **caveats 全码表**（`code`、触发条件、这句话是谁写的）→ `definitions` 键清单 → **逐列表**（列名 \| sortKey \| 格子读什么 \| 口径出处 \| 缺数怎么显示 \| 悬停原文 \| 颜色/灰显规则）→ 表下那几句边界声明 |
| 数据现实 | 带实测日期与实测方式（curl/psql/浏览器三选一），包括基准交易日、覆盖起止场数、行数是否被 `limit` 截断 |
| 不许破的纪律 | 判据只住哪一处、缺数是空不是 0、上限要说出口、页面不许自写口径……凡"改了就会让屏幕说假话"的约束都列出来 |
| 验收与复现 | 可直接粘贴跑的 curl/pytest/node --test 命令 + 浏览器逐列点击清单 |
