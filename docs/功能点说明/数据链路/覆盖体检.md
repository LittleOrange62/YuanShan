# 数据链路 · 覆盖体检（`/coverage`）

> 本文件按《功能点说明》的模板逐格写：这一屏**有哪些功能点、每格显示什么、口径从哪来、缺数怎么显示、
> 哪句话是谁写的**。代码是唯一真值，本文件只指路（`文件:行`＋函数名），不复述代码逻辑。
> 数据现实类数字带实测日期（**2026-10-11 本机实测，服务在 127.0.0.1:8910，同一发打两次取第二发**）。
> 样板见 [量化选股/倍量形态.md](../量化选股/倍量形态.md)，模板小节名见 [README.md](../README.md)。

一句话定位：这一屏的主角是**缺**，不是量。它不生产任何指标，只把库里每张表"覆盖哪段、区间内缺哪几个交易日、
停在哪个交易日、这场条数够不够"摆出来，回答"**今天的数据到位了吗、缺的那几天是本来不是交易日还是根本没采**"。
判据只认**数据日期**（`trade_date`/`dt`/`published_at`），不认写入时间戳、不认文件时间、不认状态栏（本项目铁律，
`duanxian/coverage.py:19-20`、`vr/app.py:529`、`Coverage.tsx:23-24`）。

## 2. 「逐表覆盖」Panel

面板标题「逐表覆盖」（`:70`）。

**Panel `note` 原句**（`:71`，逐字）：
> 「应有 / 实有」的分母是交易日历从该表最早日期到今天的场次数；快照表没有日期列，所以不参与这一对比。「本场 / 基线」是条数判据：一场里应该有 N 只（或 N 行）的那几张表，本场条数必须 **≥ 前一天登记的条数减去偏离值（默认 30 条、分钟线类 200 条，两个数在系统配置里改得动）** —— 新股只会让条数往上走，所以条数变少就是半截下载，日期齐了也不算全；偏离值给的是退市/停牌那几天的正常回退留的口子。

**Panel `slowHint` 原句**（`:70`，仅在 `kind==="loading"` 时显示）：
> 这一屏要扫全库逐表统计，实测冷跑过 53.6 秒（命中缓存时不到 0.1 秒）。没有进度可依，所以只说在跑；跑完会把「算于几分钟前」一起交出来。

> ⚠️ `53.6 秒` 与 §数据现实本轮实测的 **73.16 秒**不一致（且这句 `slowHint` 只有请求真正进入 loading 且超过渲染时机才被读到；命中缓存时用户看不到它）。以实测为真值，`53.6` 是更早一次的读数，已过期。

### 2.4 `CacheLine` 新鲜度自证（`DataPanel.tsx:121-141`）

缓存/预计算与新鲜度就是靠这几行在屏幕上自证清白：

- 「本屏生成于 `<generated_at>`（`<ageText(cache.age_seconds)>` 前）」——`generated_at` 是**算出来那一刻**，不是"现在"（`coverage.py:433`、`:455/:517`）。`age_seconds` 缺失时退化为"（后端未给 age_seconds，无法判断有多新）"（`DataPanel.tsx:129`）。
- 「结果出处：`source` · `<fresh_within_seconds>` 内算新鲜」——`source` 为 `disk`（命中磁盘缓存）或 `live`（本轮现算）；`fresh_within_seconds=600`（`FRESH_SECONDS` `coverage.py:361`）。
- `is_stale===true` ⇒ 黄字「已超过新鲜窗口（这是上一份结果，不是刚刚算的）」；`very_stale===true`（年龄 > `STALE_WARN_SECONDS=20*3600` `:362`）⇒ 红字「已明显过期：这一屏可能读不到今天的变化」。

新鲜度双保险：`_serve_cached()`（`coverage.py:429`）对**过期缓存也先用**（绝不让页面为全量重算现场等 73 秒），同时后台 `_kick_refresh()`（`:403`）起一条 `coverage-refresh` 守护线程重算，下次刷新即拿到新的。常驻循环 `coverage-precompute`（`jobsboard.py:45`；`server.py:2383/2430`，`_lifespan:3240` 接线）每日 18:20 主动重算一次，把缓存预热好——**这正是这条循环存在的理由**（关掉它的代价：`jobsboard.py:46`「首屏那 50 秒要现场等；数据本身不受影响」）。

### 2.5 条数判据那一行（仅「一天应有 N 只/行」的 6 张表有；`Coverage.tsx:117-132`）

渲染条件 `entities_latest != null`（`:117`）。这一行把"日期齐≠数齐"的判据摆到状态格里：

> `本场 <entities_latest 千分位>／基线 <entities_baseline>（<baseline_date>，<隔 N 场，中间那些没登记 | 前一天>）允许少 <entity_deviation> 条（<deviation_from | 出处后端没说>）`

悬停 title（`:120`，逐字）：「『一天应该有 N 只/行』的表才给这一行。判据是本场条数 ≥ 前一天登记的条数 − 偏离值（条数，不是百分比；默认 30、分钟类 200，在『系统配置 → 收盘链 → 条数完整性』改得动）。基线由系统每天登记下来的条数自己长，只有判为『全』的那些场才进池」。
`entity_partial===true` 时该行黄字，并在下方渲染 `coverage_note`（`:130-132`，后端 `completeness_why` 原文）。

## 5. 不许破的纪律

1. **判据只住一处**：
   - 缺口/停更只算在 `coverage.py::_probe` 的 `gap` SQL（`:310-324`）——只在 `[min_date, max_date]` 区间内算缺、扫到 `current_date` 算停更，两类分开交（`missing` vs `stale`），**不许合并**（`:307-309`）。
   - 五种状态 `ok/gaps/no_data/missing_table/no_access`（外加 `error`）**不许互相掩盖**（`coverage.py:9-15`、`vr/app.py:540-542`）。
   - 条数完整性判据只住 `duanxian/completeness.py::judge()`（`:262`）；`coverage.py::_entity_day_check` 只发一条"这一场多少条"的 SQL 然后交给它（`:182-215`），**页面不许再写一套 `>=`**。
2. **偏离值阈值不许住两处**：默认只住 `jobs.py::COMPLETENESS_DEFAULTS`（`:286`），生效值只经 `completeness._read_deviation/deviation_for`（`:143/178`）读作业配置；页面/CLI 改的是同一份。`completeness.effective_deviations()`（`:166`）注释明确"不许退回模块常量"（曾实测到读常量导致"改了配置页面还印 30"）。
3. **缺数是 `—`，不是 0**：`dash()` 只在 `null/undefined/空串` 时给 `—`，`0`/`false` 是有效值绝不吃掉（`datastate.ts:59-66`）。本屏所有格子走 `dash`；唯一的 `?? 0`（`Coverage.tsx:139`）只喂颜色布尔、不喂显示。后端查询失败交 `None`＋`reason`（"不当成 0"，`coverage.py:264/271/354`），条数没数出来 `entity_partial=False`＋`completeness_why` 说"没数出来…不当成 0 也不当成全"（`:212`、`completeness.py:282`）。
4. **新鲜度不许被缓存隐掉**：走缓存也必须显示 `generated_at`（算出来那一刻）+ `age_seconds` + `is_stale`/`very_stale`（`vr/app.py:538-539`、`coverage.py:429-446`、`DataPanel.tsx:117-141`）。过期缓存宁可先用+后台补算，也不许让页面现场等 73 秒回退成"未接入"。
5. **估算行数要标出来**：大表 `rows` 走 `pg_class.reltuples` 并含分区求和，必须 `rows_kind='estimated'`＋界面" 估"（`coverage.py:225-232`、`:258`、`Coverage.tsx:154`）；小表才给精确 `count(*)`。绝不拿估算当精确条数、也绝不用统计视图（分区父表 `n_live_tup` 恒 0 会得出"日线是空表"，`coverage.py:23-26`）。
6. **快照表不参与"缺哪天"**：`date_semantics==='snapshot'`（无交易日期列）时 `min/max/missing/stale` 一律 `None`→`—`，界面加那句"不许当时间序列用"（`Coverage.tsx:106-108`、`coverage.py:274-277`）。
7. **半截数据比缺数更坏**：只数不够 ⇒ `entity_partial` + `coverage_note` + 点亮 `thin_coverage` ⚠；只有判为"全"的场才进基线池（`completeness.judge:319-323`），半截那天进了就等于把基线拉低、次日连 200 只都算全（`:26-31`）。
8. **本页无占位数字**：接口没交的字段格子就是 `—`，不编示例值（`datastate.ts:4-5`、`README.md` 规矩）。
