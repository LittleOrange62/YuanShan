# 数据链路 · 数据加工（`/data-process`）

> 本文件按《功能点说明》的模板逐格写：这一屏**有哪些功能点、每格显示什么、口径从哪来、缺数怎么显示、
> 哪句话是谁写的**。代码是唯一真值，本文件只指路（`文件:行`＋函数名），不复述代码逻辑。
> 实测日期 2026-10-11 01:1x–01:2x（本机，服务在 8910；基准场 2026-10-09，10-10/10-11 是周六/周日）。
>
> 先把一句话摆在最前面：**这一屏不显示加工段的步骤、不显示链状态、不读任何一层运行台账。**
> 它只回答一个问题——「加工段写出来的那些派生表，每张**算到哪一天**、缺几个交易日、被哪个页面消费」。
> 加工段的 28 步逐步结果、单步补跑、失败重试阶梯、收盘链两段的健康度，全部住在
> `/system`（`ChainStepsPanel` / `LoopSwitchboard` / `CloseChainPanel` / `LogTailPanel`）与 `/jobs`。
> 本屏与它们的分工写在第 4–8 节，每一句都指到代码行，不凭印象。

### 4.2 一步的结构（不是抄一个数字，而是这几样）

一个步骤由三段信息定义，加/挪一步必须三处都动：

| 结构件 | 住在哪 | 内容 |
|---|---|---|

### 6.3 加工段自己的超时与归因口径（读任何"没成"之前必须知道）

- 单步硬超时：默认 1800 秒，逐步覆盖见 `STEP_TIMEOUTS`（`e1_fill_all.py:103-152`，第 4.3 节那一列）。
  为什么不能用 `proc.wait(timeout=)`：读 stdout 的循环本身会阻塞，"一行都不吐地卡住"到不了那一层——所以是 `threading.Timer` 看门狗按**进程树**收（`:311-326`、`_reap()` `:316-322`），收完写 `rc = 124` 并留一句「这一步超时：超过 N 分钟未完成，已被看门狗收掉」（`:339-341`）。
- 失败归因成一句人话：`classify_failure()` `:346-369`，**从上往下命中即停**，顺序有讲究（`daily` 的 2 是"按设计停下"必须最先挡住，`:350-355`）。归因五类：按设计停步（非故障）/ 超时 / 接口无权限或额度不足 / 网络故障 / 数据不全，兜底「脚本异常（退出码 X）」。
- 证据是输出末尾：`TAIL_LINES = 60` 行留在内存（`:85`、`:332-335`），台账每步只带末尾 180~240 字（`:667`、`:835`）。
- 退出码语义见第 8 节；「哪些退出码不值得重试」在 `_retryable()` `:237-249`（`daily` 的 2、`tdxdl` 的 2/3 重试一百次也不会变好）。
- 目标交易日怎么算：先同步日历 → 收盘线 **15:30** 之前退到昨天 → 取 `is_open` 且 ≤ 上限的最大那天（模块文档 `:10-19`，实现走 `app/orchestrator/tradeday.py` 的 `CLOSE_HHMM = (15, 30)` `:31`、`closed_cutoff()` `:45-49`、`target_date()` `:52`，调用点 `e1_fill_all.py:507`；判据只住一处，`/jobs` 页面上那个目标日读数也来自它，`:77-79`）。⚠️ 这个 15:30 是**"该拿哪一天的数"**的切线，与 15:59（`daily_close.run_at`，`duanxian/jobs.py:264`）**不是同一件事**。

## 10. 不许破的纪律

1. **判据只认数据日期**。`last_touched`（写入时间）、文件 mtime、状态栏都不参与"缺不缺"（`coverage.py:17-20`；屏上 `Row label="判据"` + 表下那句 `DataProcess.tsx:146-150`）。把"昨天被写过、内容停在 09-17"的表读成新鲜，就是这一屏存在的反面。
2. **这一屏不许长出一个重跑按钮**（用户 2026-10 裁定，写在 `DataProcess.tsx:157-166`）。它读的是覆盖统计，没有 `job_key ↔ 执行体` 的对应关系；在这里摆按钮＝让人盲猜。触发入口在 `/jobs`（按 `available` 决定摆不摆）与 `/system`（按 `STAGES` 名单决定补跑哪一步）。
3. **步数不许手抄在屏幕上**。`STAGES` 是唯一清单，界面与 API 都动态读（`jobsboard.chain_steps()` `:859`、`rerun_step()` `:891`）。屏上那两处手抄（`DataProcess.tsx:161` 的「第 17 步」、`LoopSwitchboard.tsx:130-132` 的「36 个步骤 / 加工段 26 步」）**已经过期**，加步骤时按第 4.1 节的清单一起改；`docs/系统配置工作指南/05`、`12` 那两处由 `tests/test_volume_ratio.py:155-167` 钉住。
4. **加一步 = 同改 `STAGES` + `plan` + 文档**，且 `STAGES` 名单与 `plan` 键必须一一对应（`tests/test_volume_ratio.py:80-89`）。只加一处会得出两种坏形状：少键＝链跑到那步 KeyError 断在半路，多键＝那步永远不被跑到、库里天天少一天。
5. **缺数是空，不是 0**。「缺」为 `null` 时必须写「算不出（不是零缺口）」而不是涂一个 0（`:124`）；「行数」查失败交 `null`；`rows_kind=estimated` 必须带「估」，不许把估算当精确值比（`:130`、`:147`）。
6. **五枚举状态不许合并**（`ok/gaps/no_data/missing_table/no_access`，`coverage.py:9-15`）。本屏**没有状态列**，所以这四态在屏幕上同形——这不是允许"当作一种"的许可：要说清是哪一种就去 `/coverage`（`Coverage.tsx:87,113-116`）。同一份 payload 在别屏必须留得下这些区别。
7. **缓存身份必须跟着数据走**。`generated_at` 是算出来那一刻，`age_seconds`/`is_stale`/`very_stale` 一起交（`coverage.py:429-458`、`DataPanel.tsx:121-141`）；拿昨天的覆盖说今天比没缓存更坏。
8. **上限与截断要说出口**。后端 `TARGETS` 只登记 34 张表（10-11 实测；10-15 起 37 条登记／36 张不同表）（实测 35 行、派生 21 行），本屏只列派生层；加工段真实写的另外 4 张 analytics 表**根本不在这张清单里**（第 4.4 节），不许读成"加工只写这些表"。`CONSUMERS` 是手抄的 15 条映射，对不上就写「未见页面消费」，**不许猜**（`:41`）。
9. **不自己解释后端的话**。`known_issue`/`note`/`reason` 一律原样转述，只过 `plain()` 剥粗体标记（`lib/agent.ts:62-66`），页面不重写、不改写；`**` 不许出现在渲染后的文本里。
10. **两条收盘链的 `rc` 不许合并成 `rc in (0,3)`**（`jobs.py:437-439`）；段超时不许小于段内单步预算（`jobs.py:418-422`）。
11. **NaN/NaT 不许出门**：`pg.fetch_df` 把 NULL 读成 float NaN（`is not None` 恒真），记录一律过 `_records`/`_text`（`jobsboard.py:157-179`）并整包 `_json_safe`（`:182-190`）。本屏的 `TableX` 全部字段按 `?: string | null` 声明（`:26-33`），显示走 `dash()`，0 与 `false` 是有效值不许吃掉（`datastate.ts:59-66`）。
