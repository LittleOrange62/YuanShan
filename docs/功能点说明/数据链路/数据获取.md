**与判据页的风格差异（必须写清）**：`/api/datasource`（`vr/app.py:2278`）与 `/api/system/doctor`（`:1663-1673`）
用 `try/except → 200 + available:false + reason`；而判据类端点用 `raise HTTPException(502, …)`
（例如倍量形态 `vr/app.py:656`、覆盖体检 `:549`、质量闸 `:921`，全仓 60 多处）。
原因是这两种屏回答的问题不同：**判据页"取不到数"就等于那一屏没有内容，必须炸出声**；

两种风格在 `/system` 那一列被合并判定：`probeVerdict.ts:24-37` 把 `error`（含 502）算 `broken`、

### 2.4 逐列（7 列：6 个 `SortHeader` + 1 个不可点的 `<th>`）

默认序：`useTableSort()` **不传 initial**（`:68`）⇒ `sort=null` ⇒ 吃后端行序。
后端序是 `order by health, display_order, datasource_key`（`sysboard.py:90`）＝ **`health` 字典序**
（实测顺序 broken → down → no_permission → ok → unknown）。
⚠️ 这与 `03_registry.sql:394-398` 那条索引注释「页面按「层级 → display_order」分组显示，这是唯一的列表顺序」
以及 `registry.list_sources()` 的 `ORDER BY CASE layer …`（`:230-231`）**不是同一套**：本屏用的是前者。
以实测为真值。

排序键必须等于格子里读到的字段名；`SortHeader` 的悬停 = 自写 `title` + 统一追加句
「点一下按「X」排序，再点翻向，第三次取消；缺数的行始终排在最后」（`components/ui/SortHeader.tsx:22`）。
缺数永远在后：`useSort.ts:71-74`（`isMissing` 那一档**不乘升降序符号**，`:41-47`）。

## 4. 三态怎么交：在册 / 可用 / 最近成功 / 连败，以及 `null ≠ false`

**这一屏的状态是三列而不是一个徽标**：`health`（登记的状态）＋ `last_ok_at`（最近成功）＋ `last_probe_at`/`probe_stale`（那个状态多久没刷新）。
三个都得读，只看 `health` 就会把 16.9 天前的结论当成今天的事实（页头那句黄字就是拦这个的）。

| 问什么 | 屏幕上的字段 | `null` 与 `false` 的区别（本项目实测过的三条） |
|---|---|---|
| 在册吗 | 一行存在 = 在 `config.datasource` 里有这行；`is_active` | `is_active` **只有 `=== false` 才显示「未启用」**（`:145`）。`null`（后端 `sysboard.py:110`：`bool(x) if x is not None else None`）= 库里这一列读不出来 ⇒ **屏幕上什么都不加**，既不写"启用"也不写"未启用"。绝不能读成"没启用" |
| 可用吗 | `health` 那一档 | `health` 不会为 `null`：后端空值回 `unknown`（`sysboard.py:102`）。**`unknown`（没判出状态）≠ `down`（判过、判成不可达）**：实测 `tushare_mcp` 是 `unknown` 且 `last_probe_at` 为 `null`（压根没探），而 `ak_concept_em` 是 `down` 且有探测时刻（探过、探到不可用） |

| 新鲜吗 | `probe_stale` | 后端这个字段**永远是布尔**（`sysboard.py:112`，`age is None or age > 阈值`），所以前端 `=== true` 的写法安全；但 TS 接口把它声明成 `boolean | null`（`:30`），`null` 那一支是留给"后端没交"的，届时徽标不亮、而整屏的 `stale_now` 已经把它算进去了 |
| 多久没成 | `last_ok_at` | `null` = **从未成功过**（实测 9 行），显示 `—` 并排到列表最后；不是"成功过但时间没记" |

## 7. 不许破的纪律

1. **新鲜度和状态同等重要**：每个源必须同时交 `last_probe_at` + `stale_seconds` + `probe_stale`，整屏再交一组 `probe{}`
   （`sysboard.py:5-7` 那条硬规矩）。只报"上次探测于"而不报"多久没说话"，整屏就是假新鲜。
2. **`no_permission` 不许并进 `down` 的灰**（`sysboard.py:8-9`、`Datasource.tsx:44-46`）：动作完全不同，一个是去配 key，一个是源死了。
   新出现的档位**原样显示字符串、落中性档，不猜语义**（`:47`）。
3. **缺数是 `null` 不是 `0`**：`_age_seconds()` 算不出给 `None`、**不折成 0**（`sysboard.py:56`：0 = "刚刚探过"，是完全相反的事实）；
   `never_probed` 单独一个数；`row_count=0` 照实显示 0（0 行也是信号，`03_registry.sql:368`）。
4. **NaN/NaT 不许出门**：`_records()` 把 NULL 读成 NaN 后统一换 `None`（`sysboard.py:36-43`），出口再过 `_text/_int_or_none`；
   整包必须能过 `json.dumps(allow_nan=False)` —— 这条由 `tests/test_sysboard.py:30-46` 钉着。
5. **密钥永远不出门**：接口只交 `auth_env_name` 变量名（`sysboard.py:116-118`、`03_registry.sql:355`、`05_seed.sql:984-985`），
   `_probe_env` 也只报"在不在"（`probe.py:112`）。屏幕上出现 token 值就是事故。
6. **「30」这个数不许写死在前端**：现在有三处字面量（`Datasource.tsx:73` 副标题、`sysboard.py:137` basis、`System.tsx:65` 标签）。
   屏幕上真正的数来自 `counts.total` / `probe.sources_total`。**改这一屏时优先让这三处随接口走**，
   否则库里 30→31 行，三处同时撒谎而 `counts` 是对的。
7. **不许摆一个点了没反应的按钮**（`Datasource.tsx:23`、`:185-186`）：没有 POST 端点就不摆"重新探测"。
   真要加触发端点，必须同时把 §3 那两件事（`probe_spec`、`history[]`）一起补上，
   并按 `/jobs` 那一屏的规矩在二次确认里交出 `run_preview{outbound_hosts, writes, touches_db, est_seconds}`
   （`vr/jobsboard.py:209-210`、`:520-522`）—— 探测 30 个源会真的向 `push2.eastmoney.com`、
   `vip.stock.finance.sina.com.cn`、`gpt.cn` 等出网并 **写 `config.datasource` + `operations.datasource_probe`**，
   这两件事必须写在同一句确认里，不许只写"确认探测？"。
8. **`health` 与 `layer` 是两栏，不许混**：层级是"该先用谁"的口径，不是状态（`registry.py:34-35`、`05_seed.sql:1120-1122`）。
   一次网络抖动把主力源降成辅助源，下次谁都不知道原本该先用谁。
9. **`health` 不在页面可改白名单里**（`registry.py:198-204`）：手改 `health` 会掩盖真实状态；
   真要改，改的是探测代码。
10. **粘性结论不许被一次抖动覆盖**（`registry.py:321-336` `keep`），但屏幕必须同时说出它有多旧 ——
    `probe_stale` 逐源标，不合并成一句"大多过期"（`Datasource.tsx:192-195`）。
11. **本屏默认行序是 `health` 字典序**（`sysboard.py:90`），与 `list_sources()` 的层级序（`:230-231`）不同。
    谁把它"顺手统一"成层级序，§2.4 那句"实测顺序"就要一起改。
