## 2. 提交一次复盘：入参与前置闸门（引擎侧全链）

### 2.1 前端组包（`AgentReview.tsx:321-360 generate()`）

1. 防重入：`running || polling.current || !date || loadingReport` 直接 return（`:322`；`polling` 用 ref 是因为 React state 同一轮渲染读到旧值、双击能穿过去，注释 `:188-190`）。
2. 跨日期恢复闸：sessionStorage 里还挂着别的日期的未确认请求 → 拒绝，「请先切回该日期核对任务，当前不会生成其他日期」（`:323-326`）。
3. 来源闸：`loadAgentConnection()`（`frontend/src/lib/agent-sources.ts:132`，本机 localStorage `astock-agent-sources` 多条来源按优先级/自动切换选一条）没有 → 「请先在设置中完成「复盘与追问 AI 接入」并保存来源。」（`:328`）。source 指纹 = `{provider, model, baseURL}` 的 JSON（`:329`，**不含 apiKey**）。
4. `request_id`：`randomId()`（uuid v4 去横线 = 32 位 hex，`frontend/src/lib/random-id.ts`）；先把 intent 写进 sessionStorage 再发请求，写不进就**不启动**（`:332-333`）。响应丢失后用同一 `request_id` 恢复同一请求，不重复生成（`:356` + 引擎侧幂等 §2.3）。
5. `POST /api/review-agent/daily` body：`{date, llm:{provider,model,baseURL,apiKey}, force, request_id}`（`agentRequest` `frontend/src/lib/agent-api.ts:27-40`，走 `apiUrl('/api/review-agent…')` + `authHeaders()` 的 `VR_API_KEY` Bearer，`frontend/src/lib/api.ts:36-39`）。
6. 响应分类：`already_done` → notice + 就地读报告（`:345-348`）；成功 → `pollOnce()` 3 秒轮询 `GET /api/review-agent/daily`（`:295-319`）；4xx 拒绝类清掉 pending 并把后端原句摆 `err`；其它错误（断网/超时）**不清 pending、转去轮询核对后台**（`:351-358`）。
7. 任务成败顺带回报 AI 来源健康：`SUBMIT_PATH` 只观察本会话真提交过的任务（`agent-api.ts:12-25`），失败原因匹配 `SOURCE_FAULT` 才累计一次，连续 2 次（`FAIL_LIMIT`）才把该来源标不通并让位（`agent-sources.ts:7-8,102-112,143-152`；上下文超限/本机存储/后端密钥类**不换来源**，`NOT_SOURCE_FAULT`）。

## 4. 正文闸门与引用核对

### 4.1 契约：模型只许写定性中文

### 4.3 引用核对：`line` → 每段 `ref` 的来龙去脉（`grounding.py:239-254 cite()`）

- 目录怎么生成：每路冻结输入按行切成 `input_excerpt` 记录（每行一条、带 `line` 行号，`grounding.py:92-94`），程序读数切成 `metric` 记录（`:99-112`），涨停池家数两日比较切成 `comparison` 记录（`:114-132`）；每条 id = `ev- + sha256[:20]`（`:74`）。
- **为什么换编号**（docstring 原句摘要，`grounding.py:241-248`）：裁判曾要求模型逐字抄 20 位十六进制 id，2026-09-26 复盘 2026-09-23 那轮实测两种失败都出在“抄”上——一次把目录里的 `line`（材料行号）当引用号写成 `ev-20`，一次把 `…9962d6966177` 抄成 `…9962d3066177`，差一位整段被拒。修法：喂给模型的那份投影换成**每段重新编号**的短 `ref`（`ev-1…ev-N`，`:250-254`），`line` 从投影里剥掉（`:252`——宿主从来不读它，全仓只有生成它的那一行，它唯一的作用就是被模型当编号）；跨段引用自然落空，这正是「只能引本段材料」的边界。落盘、页面与追溯仍用原 id（`:247-248`）。同段事故还催生 `_unfence` 的“只漏收尾围栏”宽容（`:194-216`）与 `_surplus_closers`（`:219-236`，2026-09-27 实测第三种形状：正文引用全对、收尾多敲 `]}]`，白烧一次付费调用）。
- 回换：`_citations` 收 ref 或完整 id，只认唯一命中；报错分型（“ref 是编号不是行号”/“截断改写过的 id 不接受”），从**不猜相近证据**（`:257-283`，docstring：把无依据的解释洗成有依据比拒稿坏得多）。
- 各分项只许引本轨材料：`ROLE_SOURCES` 按分析师过滤目录（`:24-29`，`generate_grounded` `:524` 每角色单独 `cite`）。
- 屏幕上的核对出口：`EvidenceReferences`（`ReportEvidence.tsx:27-58`）拿 citations 在 `report_grounding.records` 里还原依据卡；一段引用全落空时给那句「本段依据未能读取，请重新生成后核对。」（`:30`）；比对类读数把 `inputs` 两条原始记录一并列出、不做模型算术（`:32-33`）。口径尾注 `NOTE`（「输入片段与引用已核对；数据源正确性及 AI 推断是否成立，未据此得到证明。」）是**后端原句**，住在 `grounding.py:30`，随 `report_grounding.note` 落盘并进依据卡。
- 双轨角标：`track` 字段（own/qd）缺失时按 label 前缀 `【…口径】` 摘出，两条都认不出就**不显示角标，绝不默认算本地口径**（`ReportEvidence.tsx:6-24`，契约 `docs/页面展示工作指南/02-quantdash逻辑双轨展示.md`）。
- 回归测试：`tests/test_grounding_citations.py`（docstring 直接记录这次事故与两种被重放的形状）、`tests/test_daily_grounding.py`、`tests/test_review_output_face.py`（真冻结材料 + 合成裁判验产出面；其 docstring 记录了“本机至今零份成功复盘、`reviews/` 只有 `_rejected/`”的状态——与本文 §7 实测一致）。

## 8. 不许破的纪律

1. **红线：复盘笔记/提醒/交易日志的内容绝不进任何 AI 提示词。** 判据逐模块写在文件头上：`duanxian/review_notes.py:18`、`duanxian/journal.py:9`、`duanxian/positions.py:16`、`duanxian/risk.py:15`、`modes.py:22`、`inbox.py:19`、`excursion.py:33`、`at_risk.py:29`、`attribution.py:29`、`vr/app.py`（`/api/review-note` 那一族，属交易日志屏，行号见《交易日志》那篇）、`server.py:972,1237`。本屏的全部取数口（`review_store`、`verification`、`/api/review-agent/*`）不碰这些表；追问通道的白名单在 `evidence.py:258-345`（未知字段绝不跨边界 `:281-282`），生成通道的白名单在 `grounding.py:18-23 SOURCES` + `public_worker.py:15-19` 的调用名单。屏幕上的自证句：「只读取公开市场快照，不读取个人持仓或交易日志」（`ReviewAgentChat.tsx:176`）。
2. **持仓页禁止任何 AI 入口**：右侧「AI分析」的本页上下文登记表**永不登记持仓页**（`frontend/src/lib/workspace/pageAskAiStore.ts:16-18`，实测 `usePageAskAi` 只有首页/个股研究/自选三处调用）；面板原句「持仓（重点关注）永远不登记」（`components/workspace/AiAnalysisPanel.tsx:118`）；回归闸 `tests/test_core_logic.py:6521`（持仓页不该有 AI 入口或上下文拼装）。本屏没有指向持仓的通道。
3. **本屏唯一的 AI 出口带出去的字段清单是白名单制的**（§6.2）：市场级指标读数、行业分组名 + 涨停代码/名称、旧 AI 叙述、qd/选股/热度三轨当日聚合——没有一个个人记录字段。话术模板通道的字段白名单住在 `duanxian/prompt_slots.py:67-93 SCOPES`（lianban/firstboard 两型，缺字段一律渲染 `未提供`、不填 0 `:325-346`）；**本屏没有一键话术按钮**（那是首页连板行与首板分析页的槽位）。
4. **正文闸门三道（逐字段校验/保存/出口）改一处必须同轮改全族**，红线判据只住 `product_policy.py:44-66` 一处；“放开一条通道、红线不动”的裁定由 `tests/test_analysis_lane.py:27-45` 钉（`policy_for` 默认产品红线，只有 `analysis` 档换研究边界）。
5. **引用核对不做相似匹配**：截断/差一位的 id 照拒（`grounding.py:257-283` docstring——“猜一个相近的证据会把无依据的解释洗成有依据的，那比拒稿坏得多，这条是既有裁定，不改”）。`ref` 每段重新编号是**边界**不是便利（`:245-247`）。
6. **缺数是空不是 0**：三态 `available/reason`、`verified=null` 不算判错、分位样本不足不画、`null ≠ false`（“覆盖未确认”≠“未覆盖”）。取数超时/缺日不许被写成 0 继续推理（`evidence.py:53-55` QD_SCOPE 原句、`compare_metric :395-396`）。
7. **没收盘不跑复盘**：判据只住 `trade_calendar.is_settled` + `preflight`（`daily.py:250-251,288-291`）；「盘前点一下」产出的是一份看着可信的假报告，历史事故两处记录（`preflight.py:3-13`、`server.py:528-534`）。
8. **模型不许写数字、宿主独占数值展示**：正文里的任何阿拉伯/汉字数量都是闸门事故现场（`grounding.py:37-42,151-178`）；页面上印的每个数都来自程序读数（§5）。
9. **生成入口唯一**：老 `POST /api/review/run`、`POST /api/review/chat` 在新引擎在册时保持 409 挡死（`server.py:520-523,901-903`），不许接回任何自动化调度——复盘生成只许人点。
10. **API 密钥不出门**：422 不回显被拒内容、validation.json 里 key 一律 `[redacted]`、`source` 落盘只留公开身份（`api.py:134-139`、`daily.py:150-158`、`runtime.py:121-130`）。
11. **AI 叙述是线索不是证据**：追问包里的 `focus_md` 带“不能据此引用新的市场数字”的 note（`evidence.py:326-328`），裁判 prompt 里前序分析标 `prior_inferences`/“待评估解释”（`grounding.py:541,546-547`）。
