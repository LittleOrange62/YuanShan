用户 2026-11-04 点名：「推送任务，单独在『个股研究与回测』这个板块下建一个页面，用于汇总推送任务的，
推送配置从系统配置里面移动出来。」这一屏就是那次搬家的结果 —— **内容没变，入口变了**：
原先它住在「系统配置」那一长屏的第 ⑮ 块，与十七八个互不相干的格子并列，既看不出"保存这一格会动机器"，
改完也要来回滚动核对。系统配置那一屏现在只留一行跳转（见 §五）。

## 一、这一屏管什么、不管什么

管三件事：**什么时候跑、发到哪些渠道、这一路还开不开**，并把三样东西并排给你看：
配置说的 / 机器上真注册的（`Ready`、`Disabled`、`未注册`、下次时间）/ 今天库里真发出几条。

**不管判据与正文**：判据在各作业脚本里，措辞在 `app/intraday/templates.json`。
也不管"渠道机器人本身"与"本进程内的定时计划"（那是系统配置 ⑬ 与 ⑭ 两屏，本屏下方有指路链接）。

## 二、九行分别是什么（序号 = 屏上从上往下的行序 = 文件名前缀）

每行右侧那格 `<code>` 直接印着作业脚本路径（`ingest/jobs/push/tNN_*.py`），改哪一行去找哪个文件不用查表。

| ② | `YuanShan-AuctionReport` | `…/t02_auction_report.py` | 09:25:30 | 采集即入库即发（竞价数只在那一瞬存在） |

①⑥ 两行屏上写「只落库不发送（发送归「…」那一行）」，不写"发 0 条"（那读起来像坏了）。

## 三、保存这一笔会发生什么（顺序固定，不可跳）

1. 校验：**一个键非法就整笔不写**（时点形状、间隔区间、渠道是否在册、`heat_times` 这类已作废的键）；
   错误原话经 `saveBroadcast` 的 `detail || reason` 上屏，不折成"保存失败"。
2. 写配置：作业配置 `jobs/config.json` 的 `intraday_broadcast`（35 个键，盖章 `_changed_at`/`_changed_by`）。
3. **动 Windows 任务计划程序**：开着的覆盖式注册，**关掉的那一路直接注销任务**
   （不留"每天空跑一次然后不出声"的任务）；每行按钮因此叫「保存并重注册」，不叫"保存"。

时点只有两格可改：`auction_times` 与 `push_times`。③④由 `push_times` 推导（④各自 +10 秒），
所以 ④ 那一行只有开关、没有时点格 —— 界面会不会出现"改了推送点忘了改热度"这种不一致，
就靠这一格结构堵掉。谁给输入框由后端那一格 `tasks[].times_field` 决定，前端不自拼 `${key}_times`。

## 四、数据与接口

- 端点：`GET /api/intraday/broadcast`（读数）、`POST` 同一路径（改 + 重注册，体 `{settings, reregister}`）。
- 真源：`app/intraday/tasks.py`（一份 `SPEC` 在册表同时喂着 CLI、接口与任务 XML 生成）。
- 留痕：`analytics.intraday_broadcast`（几点发了什么、送达与否按**渠道业务码**判，不按 HTTP 200）；
  每行末尾那格「今天 N 针 · 发 N 条」是 `store.fold_ledger` 折出来的。
- 两处读数上的坑已在屏上处理：`Get-ScheduledTaskInfo` 的时间**秒位不可信**（本机实测秒==分），
  那两格只到分钟；从没跑过的任务回 `1999-11-30` 零值与 `LastTaskResult=0`，屏上落成「没跑过」，
  结果码与它同一个闸（`267011`＝还没跑过，不是成功）。

## 五、系统配置那一屏留了什么

原位置一行跳转：「盘中播报…已经搬到 推送任务 那一屏」。`IntradayBroadcastPanel` 只挂载一次
