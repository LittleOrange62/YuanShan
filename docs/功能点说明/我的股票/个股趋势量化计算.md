## 8. 不许破的纪律

1. **公式与判据只住一处，页面逐字透出**：分量权重实发值住 `analytics.score_detail`、注册表住
   `config.view_effective_binding`/`config.capability`（驱动 `app/compute/scoring.py`）、说明式合成式住 `QUADRANT_AXES`、
   趋势统计量住 `app/compute/score_trend.py`（唯一一份 `CORE_SQL`，落库与现算共用，两处各写一份迟早漂移）、
   新高判据住 `duanxian/quant.py::new_high()`。前端**不重写公式、不自算新高、不自减百分比、不做单位换算**。
2. **缺数是空，不是 0**：`weight=None` 不许 `or 0` 混进权重和（`quant.py:569-573`）；percent_rank 缺 ⇒ 括号不出现；
   sparkline 缺 ⇒ `—`；`pct_from_peak` 缺 ⇒ 「距峰算不出」；指标 NULL ⇒ `—`。0 与 false 是有效值不许吞。
3. **不写 000001、不借邻近场次**：代码默认值由五级播种回落且以库里为准；库里没那场就是没那场（`_fail` 原句「不回落到邻近交易日」`quant.py:249`）。
4. **没选票不发单票请求**：`useProbe(skip)` 的 `idle` 不许被 `error`/空表冒充（`Scores.tsx:67-69` 注释）。
5. **窗口不凑数**：`window_days` 请求与库里不符 ⇒ 明说实有窗口并拒绝代答；行数被 `sessions`/前端 40 行/`limit 300` 任何一层截断都必须在屏幕上说出来（Caliber【截断】、取出/截断行、`new_high_in_rows` 是"本页"口径）。
6. **库内新高≠历史新高**：标题、`caliber`、caveat、`hist_truncated` 四处同判据；`list_date` 全表 NULL 之前不许改成"历史新高"字样（用户点名的就是这个原话，屏幕按数据现实答）。
7. **两类"象限"不许对齐**：当日象限（`quadrant`）与窗口入口象限（`first_quadrant`）是两个问题的答案（`_NOTE['entry_quadrant']`）。
8. **缓存必须自己声明自己**：`cached_aggregates` caveat 与 `cache_age_seconds` 读数不许被省略；刚在同一请求里算出的不列（`_cache_caveat` 只报 >1s，`quant.py:330-333`）。
9. **NaN/Infinity 不许出门**：整包必须过 `json.dumps(allow_nan=False)`；本轮 11 份响应复核为净。
10. `params 里"没记过"不报"存于"`：值为空时时间与"没记过"两句不许同时出现（`StockPicker.tsx:114-118` 注释，09-29 实测踩过）。
11. **屏幕念中文，机器码只做对账**（2026-10-22，用户「完全看不懂」之后立的）：caveat 徽标读后端 `label`
    （`duanxian/quant.py::_CAV_LABEL` 一处，构造只走 `_cav()`），能力名/分量名读注册表
    （`config.capability.name`、`config.view_effective_binding.script_name`，兜底 `config.script.name`）。
    前端**不许**自己按 code 猜一个中文词、也不许写死一张机器键→中文的映射表 —— 名字有两处出处时改一处必有一处慢半拍。
    没登记 label 的 code 照旧念 code（宁可难看也不编），这是"漏登记"的信号，不是让它蒙一个。
12. **名次先问"这一场这一项能不能排名次"再念**：判据只住 `duanxian/quant.py::_rank_view`
    （阈值 `_RANK_COARSE_SHARE`），分布由 `_RANK_SPREAD_SQL` 现数；写侧那两列（`rank_in_market`/`percent_rank`）
    在全场同值时恒给 1 与 50.009，屏上必须念 `—` 而不是「全市场第 1（前 50.0%）」。
    页面只转述 `rank_kind`/`rank_note` 与计数（`lib/ranking.ts::scoreRankCell` 一份实现，两屏共用），
    **不许**在组件里自己判"几个取值算粗"或自己写那句为什么。
