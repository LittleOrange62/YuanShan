**③ 操作分是什么（现算核对过）。** `oper` = `analytics.score` 当日 `capability_key='oper_score'` 的 `value` 原值，保留 1 位：


## 7. 不许破的纪律

1. **名单只有一个真源**：`stockblock.ini` → `ingest/ths_local.py` 解析 → `watchlist_sync` 写 `config.watchlist_*`；页面与读层**永不写**这三张表。
   本机名单（localStorage）与库里名单是两套数据，界面上并排展示但**不许互相折算、不许做"假导入"**（`Grouped.tsx:314-318`）。
2. **自选与持仓不混算**：这一屏的分母永远是 `config.watchlist_*`；持仓在交易日志聚合那一侧（§5.4）。包含关系**只点名（持仓页）、不兜底（不改 ini、不造"本机补充"行）**。
3. **缺数是 `—`，不是 0**：`dash()`/`num()` 判 null 与空串（`lib/datastate.ts:59-66`、`:117`）；`_plain()` 把 NaN/±Inf 折成 None（`duanxian/watchlist.py:39-50`）；
   成本空 ⇒ 不填 0（`ingest/ths_local.py:104-106`）；趋势不足 10 场 ⇒ NULL 不补 0；`up_ratio` 分母 0 ⇒ None。**合法 0 只有"真 0"**（如某组当日 0 只下跌），别顺手把 `—` 改 0、也别把 0 读成缺。
4. **判据与口径只住一处，页面逐字透出**：日均≠区间（caveat/note 原样）；单位随后端（`unit` 的 `bp/日` 不许页面自己写成 `%`，`Grouped.tsx:206-209`）；
   聚合只住 `duanxian/watchlist.py`；同步模式默认值只住 `duanxian/jobs.py:298`；模式含义措辞只住 `vr/jobsboard.py:95-100`（`watchlist_sync.py:521-524` 引用同一份）。
   页面上那三处「45 组」写死数字（`Grouped.tsx:21`、`:298`、`duanxian/watchlist.py:103`）已经过期——**改的话改措辞并改成当场算，不许把票数继续焊在文字里**。
5. **上限要说出口**：前端渲染截 150 行必须带那一句（`Grouped.tsx:282-284`）；后端 `limit` 默认 2000 是按全库条数定的、不许悄悄调小（`vr/app.py:876-879`）；
   「本批 N 只没有指标行」那句只在真缺时才在场（动态拼接，`duanxian/watchlist.py:164-168`），不许改成常量句。
6. **is_focus 与 note 不许被同步抹**：ini 里没有这两个字段，按名接续（`watchlist_sync.py:18-20`、`:285-289`）；页面也不许"没有焦点组就造一个默认组"（`duanxian/watchlist.py:17-19`）。
7. **空组要说是空组**：接口只聚合有成员的组（实测 44/48），空组那格措辞是「本组没有成员，接口不聚合空组」，不是"当日无行情"（`Grouped.tsx:197-204`）；库里那 4 个空组的组名是用户真起的，`隔夜持股法：` 的截短正是解析坑 ②-续行丢弃的**已计数**后果（6 行续行在场）。
8. **点组名＝重发请求**（不是前端过滤，`Grouped.tsx:169`）：谁要把它改成本地过滤，得先回答「limit 2000 之外将来超库怎么办」。
   ⚠️ 这条的**后半句 10-14 作废**：组级聚合现在**默认就取**（用户点名要把那一屏搬进本页最上方、先看清分组），
   代价改由那块表自己的 `slowHint` 与出处那一格的 `elapsed_ms` 明说，而不是靠「默认不取」省下来。
   取而代之的新纪律是**一次进页只许一发聚合**：页面里 `"watchlist/group-analytics"` 只出现一次（`Grouped.tsx:215`），
   顶部那张表、折线、口径与卡片那 6 格共用同一个 `DataState`（两处各发一发＝每次进页多等 4 秒，还会拿到两个 `generated_at`）。
9. **一份实现**：组热度表／折线／口径只有 `components/quant/GroupAnalyticsBoard.tsx` 那一份；
    两个调用方（`pages/Grouped.tsx:285` 与薄壳 `pages/WatchlistAnalytics.tsx`）都只喂 `got`，组件自己不许发请求
    （`frontend/test/watchlistGroup.test.ts` 钉住）。要加列、改口径，只改那一份。
10. **手输的那只：草稿 ≠ 已提交**（`Grouped.tsx:175-176` 两份状态）。合成一份时会出真事故 ——
    敲到半截「6005」时档案立刻拿它去发请求，屏上出现「这只票的量化档案 · 6005」（10-14 实测抓到并改掉）。
    档案永远吃 `focusCode`（`:205`）＝已提交的那只 或 点中的那一行；两个入口互斥，任何一处绕过它就是
    「高亮的行与下面档案不是同一只票」那一类错（同 §7 第 12 条与 `useTableCellHighlight` 那份行序纪律）。
11. **NaN 不许出门、星号不许上屏**：整包过 `json.dumps(allow_nan=False)`（本轮实测无 NaN）；`Measured/CaveatText/Panel note` 出口都走 `plain()`，
   但 `indicator_meaning/unit` 两行是**裸拼**（§9 #5），新增同类拼接记得走 `plain()`。
12. **档案那一叠不重算判据，也不合并缺席**（2026-10-13）：八块只读各自那张表已经落好的行，
    八分量走 `quant.scores()`、概念走 `pg_sources.concepts_by_code()`、类型标签走各模块的 `TYPE_LABELS`、能力名从 `config.capability.name` 读；
    谁要在这里"顺手算一个综合分"就先回答"那个分和 /quadrant 的分叉了怎么办"。
    缺席的三种（`read_failed`/`not_computed`/`not_on_board`）不许合并成一句「没有数据」——
    「它没进这一榜」与「这一榜还没算到这天」是两件不同的事（`tests/test_stock_dossier.py` 三家各钉一条）。
