### 判据（全部住后端，界面一个数字都不写死）

`duanxian/quant.py:835-850` 那四个常数是唯一一份，随返回体的 `thresholds` 交出、由 `rule` 说成原句：

1. 窗口固定 **最近 6 个有名次的交易日**（`STEADY_SESSIONS`，共 **5 步**）；交易日不是日历日；
2. **6 场每场都有这个名次**才进榜（`sessions_used = 窗口场数` 写在 SQL 的 `where` 上，不是页面筛的）；
3. **前进一步 ≥ 3 步**（`STEADY_MIN_BETTER`）、**后退 ≤ 1 步**（`STEADY_MAX_WORSE`）；
4. **净前进幅度 ≥ 首场名次值的 10%**（`STEADY_MIN_GAIN_FRAC`，按「÷ 首场序列值」算 ⇒ 两档尺度可比）；
5. `xy` 档额外要求 **X 与 Y 两轴各自都净前进** —— 只看合名次的话，一轴一次跨 2,000 名能完全盖住另一轴的恶化，
   屏幕上却还写着「稳步前进」；
6. 排序：**前进幅度比例降序**，并列时先比最近一场的名次（更小者在前）、再比代码。
   `xy` 档的序列是 `X 名次 + Y 名次`（最小 2、最大约两倍全场只数）—— 它**不是「全场第几名」**，
   只是把两轴位置合成一个可比数，这句话写在 `definitions.first_series` 里。

**门槛是量出来的，不是拍的**（2026-10-19 现跑现查，最近 6 场、5,55x 只母体）：
「5 步全前进」在合名次档只有 **41 只**、总分档 **53 只**（太稀，一屏读不出层次）；
「≥3 步前进且 ≤1 步后退」给到 **395 只 / 625 只**，加上第 4 条幅度门槛后 **369 只 / 489 只**；
而「两轴**都** ≥4 步前进」= **0 只** —— 原因见下面那条 Y 轴的实测口径。
全场中位的净前进幅度是 **0**（一半票在原地或后退），所以"稳步前进"本身是稀有事件，不需要再收紧门槛。

## 6. 不许破的纪律

1. **判据只住三处，页面零判据**：四档 = `sign(X)/sign(Y)`，写侧 `app/compute/scoring.py::quadrant_of()`（`:284-306`，调用点 `:396`）；两轴语义与合成式 = `duanxian/quant.py::QUADRANT_AXES`（`:54-60`）；四档人话 = `QUADRANT_MEANING`（`:46-51`）；中文标签 = **库里数据** `config.setting.quadrant_labels`（seed `05_seed.sql:1206`）。页面上唯一像判据的那一下是 `window_entry_quadrant !== quadrant` 才加 `≠`/黄字（`Quadrant.tsx:119-120`）——那是同一行里两个字段比一下，不是新口径。历史事故记在 `scoring.py:297-301`：第一版 Q2/Q3/Q4 全排错、代码自洽、测试不拦，"页面上会把该回避的票标成持有"。**别在页面另写一套四档含义。**
2. **两套象限不得互译**（`Quadrant.tsx:177-182` + `vr/app.py:564-566` + `quant.py:64-66`）：不许加"Q1≈判对+赚钱"的对照表、不许把四格按 `Q1..Q4` 命名复用 key。`entry_quadrant` 那句 caveat 明说界面别去"对齐"当日档与入口档。
3. **缺数是 `—`，不是 0**：`dash()`（`datastate.ts:60-66`）、`num()`（`qd.ts:351-353`）；后端出口 `_plain/_num/_int` 把 NaN/Inf 折成 `None`（`quant.py:97-119,196-208`），整包必须能过 `json.dumps(allow_nan=False)`。象限为空的票**一格都不进**（`:87-88`、`:369-370`），四格相加 ≠ 全市场票数；`—` 不许写成 0 分/0%/0 天。
4. **分布与筛后行数不许混成一个数**：`distribution` 是未过滤全场、`filter.rows_returned` 只影响 `rows`（`quant.py:401-402,497-499`；页面 `:82` note + `:84` 只筛本地 rows）。
5. **上限必须说出口 —— 这一条现状是破的**：后端 `limit=200` 与 `rows_returned=200` 相等就是"被截断"，`倍量形态` 那屏对此有专门的黄字（`VolumeDouble.tsx:115-121`，读的是 `d.filter`），而本屏**从不读 `filter`** ⇒ 屏上只有一句「本次交出 200 行」（`:135`），没有"这是前 200 名、不是全部满足条件的票"。要么把那句补上，要么不许把 200 行读成"市场只有这些票"（实测全场 5,558 只、Q4 一只都进不了榜）。前端 60 行渲染上限那句（`:135`）也不许删。
6. **排序键必须等于格子里读到的字段**：`sortKeys.test.ts:86-90` 钉住 `x_quality / y_env / oper_value / rank_in_market / point_count` 五键、并禁止短名（`sortKey="x"` 之类）复活；`useSort` 缺数永远最后（`:63-77`）；**排序在 `.slice(0, 60)` 之前**（`:114` 与 `useSort.ts:10-11`）。"窗口"那一列读两字段而只按 `point_count` 排，是**有意**的（列头 title 已声明），别顺手改成复合键。
7. **缓存要自己声明自己**：五个全库聚合一小时算一次（`_agg` `:143-178`），`cached_aggregates` 那句年龄必须随数据交出（`_cache_caveat()` `:327-339`，只报 >1 秒的）；`refresh=1` 的清理范围**只有** `quadrant` / `entry_quadrant_null_share` / `coverage:` 三个前缀（`:407-410`），扩大或缩小都要同步那条测试盯的 spy 序列。不许把 age 删了让旧值冒充此刻。
8. **措辞归属**：`caveats` / `note` / `labels_source` / `null_coverage.why` / `reason` 全是后端句子，渲染层只允许剥成对 `**`（`agent.ts:62-65`、`datastate.ts:36-38`），不许改写、不许缩短（`DataPanel.tsx:95-99`）。渲染后纯文本里 `**` 计数为 0 是硬闸。
9. **第二块的数据不进 AI prompt**（`attribution.py:28-29`、`:179-183`、`server.py:1236-1237`）：这条有测试盯着 docstring 字样，改注释等于拆闸。
10. **页面自写口径只有两处，要认出来**：`:107-108/:110-111` 两个列头 title，和说明卡前两段 `:172-182`。它们**没有后端出处**；改它们必须同步 `QUADRANT_MEANING/QUADRANT_AXES`（`:46-60`）与 `attribution.py:171-172`，否则两处各说一套。
11. **自检在册表**（`System.tsx:50-69`）：`/quant/quadrant` 在（`:55`，`slow: true`），`/risk/attribution` **不在** ⇒ 第二块整块坏了，系统配置那一页仍是绿的。新增能力行要连 `where` 一起给。
12. **不可用要分层措辞**：404＝接口没实现、5xx＝实现了但坏了、`available:false`＝实现了但这次没数、超时＝慢（`probe.ts:34,49-54,83-91` + `datastate.ts:42-53`）。四种在屏幕上必须是四种样子，混成一句"暂无数据"就是当年三天没落库藏住的原因。
