# 量化选股 · 异动筛查（`/spike`）

用户 2026-10-13 深夜点名的新功能：「在量化选股倍量形态里做一个新的功能叫异动筛查，第一大功能是复盘
最近两个月盘中**有过瞬间冲高 5 个点以上、或者冲到涨停**的股票，接下来走势分别怎么样，
按最近一天冲高的**时间顺序**排。」这一屏就是那句话的落地。判据与阈值只住
`app/compute/intraday_spike.py` 一份，页面一块都不重算。

## 一、这一屏回答什么

| 问题 | 在哪一块 | 数出自哪 |
|---|---|---|
| 这一天盘中冲上去的票有哪些、几点冲的、冲得有多快、之后守没守住 | 下面那张**事件名单**（默认按高点时刻升序 = 用户点名的时间顺序） | `analytics.intraday_spike` |
| 这类形状接下来一天/三天/五天历史上长什么样 | 上面那张**复盘统计表**（32 个档 × 次日均值/中位/上涨占比/p10/p90/后5日） | 事件表 join 日线现算 |
| 同一窗口里**随便一只票**的次日长什么样 | 统计表钉在第一位的**同期基线**行 | 日线全市场现算 |
| 哪些天还没回算（0 条不等于没冲高） | 表头日历 + caveat `spike_not_computed` | `analytics.intraday_spike` 的场次清单 |

## 二、判据（母体与四把尺子）

母体（用户选定的「水平＋速度组合」）：

```
日内最高较前收 >= 5 个点  且  （任意 15 根连续分钟线内拉升 >= 4 个点  或  触及涨停价）
```

- 只按水平（>=5 个点）实测 2026-08-14~10-13 是 **19,588 条 / 37 场 = 平均每天 529 只**；
  加速度这一刀后 **2026-10-13 实测 430 条**（区间 237~488）。加这一刀不是为了凑小榜单，
  是因为「慢涨一天、收盘还在高位」与「一瞬间拉起来被打下来」在统计上是两批票，混在一起
  会把下面三把真正有区分度的尺子稀释掉。
- **触及涨停价** = `high >= limit_up - 0.005`；**封住** = `abs(close - limit_up) <= 0.005`。
  用 0.5% 容差会把接近板算成封住（10 元票差 5 分），已实测否掉。
- **封住分钟数** = 收在涨停价上的分钟根数，就是用户问的「上影线到了涨停价，保持在那里多久」的那把尺子。
  **开板段数** = 由非封转成封的次数，>=2 就是「开了又回封」。
- **峰值后 5 分钟回撤** = 峰值之后 5 根里最低收盘 ÷ 日高 − 1。

四把尺子的实测（2026-08-14~10-13 两个月日线 + 本机有分钟线的场次，下同）：

| 尺子 | 最好的一档 | 最差的一档 | 同期基线（次日上涨） |
|---|---|---|---|
| 幅度 | 收盘封住涨停 **51.0%**（+1.14%） | 触板没封住 **36.3%**（−0.97%） | 46.0% |
| 承接（峰值后 5 分钟） | 守住 **40.0%**（−0.46%） | 回撤 1~3 个点 **33.1%**（−1.21%） | 37.9%（9 场窗口） |
| 速度 | 慢拉 <4 个点 **37.6%** | 急拉 >7 个点 **33.9%**（−1.31%） | 同上 |
| 时刻 | 高点在 10:00 前 **36.9%** | 高点在 13:00~14:30 **32.7%** | 同上 |

两把**没有**区分度的尺子（页面上有列但不给"信号"徽章，免得把噪声读成规律）：

- 收盘回落深度：39.3 / 40.3 / 40.9 / 44.8 / 43.0%，无单调关系 —— 「回落越深越危险」不成立；
- 全天在均价线上方占比：36.0 / 35.3 / 35.2%，三档一样 —— 「回落不破均价线=试盘」看不出。

## 三、表与写链

- 表 `analytics.intraday_spike`（DDL `app/db/sql/32_intraday_spike.sql`，**实跑并回验过 43 列**、
  主键 `(security_code, trade_date, spec_version)`）。一行 = 一次事件，同日多峰 v1 不切。
- `spec_version = spk-1`，读侧每条语句都带版本条件。
- 写侧 `app/compute/intraday_spike.py`：纯判据（`qualifies` / `spike_tags` / `minute_metrics`）与取数分离，
  单测全打在纯函数上。取数姿势是先按日线筛候选（一天约 500 只），**只查这批票的分钟线**（约 10 万根），
  实测单日 18 秒（还是在 c16 正往 `stock_minute` 灌数时测的，平峰更快）。
- 每日加工段第 **11** 步 `spike`（**链共 41 步**，10-18 现读 `len(e1_fill_all.STAGES)`；序号会随加步漂，认步名），入口
  `python -m app.compute.intraday_spike --date <日> --recent 1`；回算
  `--since 2026-08-14 --skip-done --max-minutes 30`。
- **缺分钟线不静默**：当天 `stock_minute` 整场没入库 ⇒ 速度那一刀判不了，事件按水平档收，
  `minute_available=false` + `missing='minute_bars'` 一起写；`refresh()` 记 `degraded`、退出码 3，
  台账与页面明写「这一天分钟线没入库」，**绝不说成「这些票没冲高」**。
- **重算一场 = 先删这一场这一版本，再 upsert**（10-15 晚补）。这张表"一行 = 一次事件"，而事件集合会随分钟线到没到变多变更少：只 upsert 不清场，上一次半截计算留下的行就永远在表里。实测案底 —— 17:44 那场在分钟线缺失时写了 224 条（整批 `minute_available=false`），补跑后真事件 218 条，那 6 条不是"今天的读数判不了"，是半截计算的残留；`count(*) filter (where not minute_available)` 会把它们算进今天的缺数。空批同样清场。
- **次日/3 日/5 日不入表**：读侧用 `lead(pct_change)` 与 `exp(sum(ln(1+涨幅/100)))-1` 现算。
  两个坑都踩过：用 `lag` 会把「前一天」当「次日」（所有读数整体错一天）；
  拿 close 自己相除会在除权日把跌算成涨。

## 四、接口

`GET /api/quant/intraday-spike`（`vr/app.py`，信封 `{"data": …}`，异常 502）

| 参数 | 默认 | 说明 |
|---|---|---|
| `date` | 表里最新一场 | 基准交易日 |
| `tags` | 空 | 标签多选（`fast/quick/slow/touched/sealed/held5/late/reopen`），**在库里筛**、拼在 `limit` 之前；认不得的进 `rejected_tags` 并在页面点名 |
| `min_hi` | 0 | 只看最高较前收不低于这个点数的票（同样在库里筛） |
| `limit` | 400 | 交出行数上限；达到上限时页面黄字提示「上面那个数才是全场」 |
| `days` | 43 | 复盘窗口的交易日数（≈ 两个月） |

交出：`rows`（含 `next_pct/next3_pct/next5_pct/has_next`）、`total/sealed/blown/minute_missing`、
`review.baseline`、`review.buckets`（32 档）、`calendar`（每天几条、哪些场还没算）、
`thresholds`、`tag_labels`、`calibers`（口径原文，页面直接渲染）、`caveats`。
不可用时只交 `available:false + reason`，**不带 `rows` 键**。

## 五、界面（`frontend/src/pages/Spike.tsx`）

- 上块是复盘统计表（基线钉在第一行，各档「次日上涨」高于基线绿、低于基线红），
  下块是事件名单，12 列：高点时刻 / 代码 / 名称 / 最高较前收 / 收盘 / 15 分钟拉升 /
  站住分钟 / 峰值后 5 分 / 封住分钟 / 开板段数 / 标签 / 次日。
- **默认排序就是后端交来的时间顺序**（`useTableSort()` 不给初始排序），点列头才接管，
  点列头同时 `cell.clearSelection()`。
- 格子一律走 `useTableCellHighlight` 的 `getCellClass`（行列一起亮）。这一条在开发时踩过：
  格子挂了 `onClick` 却没把 className 走 `getCellClass`，于是列永远不亮、且一行代码都不报错 ——
  `frontend/test/spikeReads.test.ts` 现在钉着这条。
- 缺数一律 `-`（不是 0）；最新一场的次日写**「明天还没走完」**，不写 0 也不写缺数。
- 股票名/代码走 `StockLink` 新标签打开东财行情页；口径文字一律 `plain()` 后再上屏。

  倍量形态页顶部有一条 `盘中怎么冲上去的 · 异动筛查` 的路标（两个入口读各自的表，不共用筛条件）。

## 六、数据现实（都是实查，带日期）

- `market_data.stock_minute` 里 1 分钟线 **2026-10-13 只有 10 个场次**（09-22~10-13，9,546 只票、
  平均 238.0 根/票）。12 根以下的是停牌/次新/盘中长时间无成交，**不是缺数据**。
- 分时量与日线量同源：10-13 全场 1 分钟逐根加总 vs 日线 `volume_shares` 差 **−12 ~ +48 股（≤0.00014%）**，
  原因是分钟线的量按手（100 股）取整；1 分钟按 5 分钟桶聚合与库里 `period=5` 的量/高/低/收
  **逐桶零偏差**（48 桶对 48 根）。
- 本地 vipdoc 的 `.lc1` 里有 **112 个交易日**（2026-04-27 → 2026-10-13）的 1 分钟线，
  `.lc5` 111 个 —— 所以「最近两个月」的时刻/速度/承接三组字段**不出网就能补满**，再往前本地也没有。
- 异动事件表 `analytics.intraday_spike`：**10-14 现查 `spec_version='spk-1'` = 37 场 / 14,531 行，`2026-08-14 → 2026-10-13`**
  （与本档上面那句「08-14~10-13 是 37 场」并查一致）。⚠️ 这里 10-13 深夜那一版写的「10 场 / 3,644 行（09-22~10-13），
  08-06~09-21 那 33 场要等分钟线回补完再算」**已被同晚那批回算作废** —— 分钟线补到 08-14 之后事件表跟着补上了，
  现在复盘统计代表**有数的那 37 场**（caveat 明写的那句仍然吃接口交出的场数）。教训照旧：**场数一律现查，别引用上一版快照**。
- 分钟线入库的自愈缺口（待办）：`app/tdx_client/steps/s9_ingest.py:99` 把 c16 排成非骨干且写
  `--date 当日` —— 一旦某天没跑成，之后每天只取「今天」，缺口永远补不回来。
  改法：`--since 库里最近缺口` + 把 `stock_minute` 缺当天记进覆盖体检。

## 七、不许破的纪律

1. **判据只住一处**：母体、阈值、标签、封住容差全在 `app/compute/intraday_spike.py`；
   接口与页面只读算好的行，`TAG_LABELS` 只有那一份，改标签要一起改。
2. **每个统计档必须与同期基线并排读**。09-22~10-12 那 9 场基线是次日上涨 **37.9%**，
   08-14~10-13 是 **46.0%** —— 同一个「35%」在两个窗口里意思相反。只交档内数字不交基线就是骗人。
3. **缺数 NULL，不写 0**：尤其 `fade_vol_ratio`（峰值在第一根时「峰值前」不存在）、
   `speed15_pct`、`sealed_min`。0 会被读成「回落没人卖」/「没冲高」，方向正好相反。
4. **0 条 ≠ 没有**：某天没算就报「还没算」，别报「这一天没有异动」。三态分开：查询失败 /
   榜没算到这天 / 算了但当天没分钟线。
5. **筛条件拼在 `order by … limit` 之前**，全场那几个数（`total/sealed/blown`）走不带筛选的聚合。
6. **网上那套依赖封单/撤单/盘口/逐笔的判据本机一律测不了**（分钟线只有 OHLC+量+额）。
   页面上的每一句判读都要能在库里数出来，数不出来的不进判据榜。
7. **版本条件不许漏**：主键含 `spec_version`，改判据就升号，旧行留着对账、不与新批并排。
8. 统计底数不够用 `days` 拉窗口，不许为了"看着显著"偷偷合并相邻档位。

curl -s "http://127.0.0.1:8910/api/quant/intraday-spike?tags=held5&min_hi=7" | head -c 400

# 写侧：单日 dry-run（不写库）与回算

python -m app.compute.intraday_spike --since 2026-08-14 --skip-done --max-minutes 30
