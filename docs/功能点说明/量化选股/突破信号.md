# 突破信号（左右两栏：埋伏票 + 已确认突破）

路由 `/volume-breakout`。用户 2026-10-13 要求把这一屏改成**左侧和右侧**：
右栏是原来的突破信号（已经确认的右侧），左栏放「埋伏票」—— 重点关注**各均线都汇集到一起**的横盘股，
而且**看周线、基本每周重心都上移**；另外把「左侧机会一般怎么选」的常见形态一并收进来。

## 一、这一屏回答什么

| 栏 | 一句话 | 什么时候买 |
|---|---|---|
| 左：埋伏票 | 各周期成本挤到一起、横得紧、周线重心还在一档一档抬高，**但还没走出来** | 左侧：买在突破之前，成本低，代价是可能一直横着耗时间 |
| 右：突破信号 | 放量波 → 缩量收敛 → 第一次同时站上 MA60 并放量，**已经确认** | 右侧：买在突破那天，代价是成本已经抬高 |

两栏是两张表、两个接口，各取各的数；基准交易日**可以不同**（各自读自己那张表的最新一场），
所以每一栏自己那一行写着它的基准日，页面上不做"共用一个日期"的假设。

## 二、左栏判据（`analytics.ambush_setup`，判据只住 `app/compute/ambush_setup.py`）

一只票同场可以命中多个类型，用「埋伏类型」那一列区分（顿号连接，严档额外挂一个「严」字角标）。

| 类型码 | 界面名 | 在筛什么（阈值来自 2026-10-12 实测分布，不是抄来的整数） |
|---|---|---|
| `sticky_pull` | 均线汇集蓄势 | MA5/10/20/30/60 极差 < **1.5%**（全市场中位 6.46%、P25 3.87%）+ 20 日高低差/当日收盘 < **11.7%**（P25）+ 周线重心近 6 个完整周里 **≥4 周**抬升，且满 **7 个**完整周 |
| `pullback_ma20` | 回踩 MA20 | 60 日涨幅 > 15%（趋势还在）+ 现价贴 MA20 ±3% + **近 5 场（含当日）均量 < 第 6~60 场均量 ×0.9**（SQL 里 `v5 / v60p`，`ambush_setup.py:272-273,303`。⚠️ 10-14 之前这一句、常量注释与界面悬停都写成"近 10 日均量 ÷ 第 21~60 场"—— 那是三处抄错的同一个口径，已当场对着 SQL 改掉；屏幕上那一格现在读 `app/compute/ambush_setup.py::TYPE_MEANINGS`） |
| `pullback_ma60` | 回踩 MA60 | 同上，踩的是 MA60（±5%）—— 回调更深一档 |
| `obv_bid` | 量价背离吸筹 | 近 20 日「涨日量 − 跌日量」占总成交 > 25%，而 60 日涨幅在 −3%~8%（钱在进、价没走） |
| `dragon_back` | 龙回头 | 最近 60 场内有过放量大阳（涨幅 ≥7% 且量 ≥1.8×）或涨停（量 ≥1.5×），之后横 7~30 天、期间没跌破那根阳线最低价、且缩量、现价在那根阳线收盘 −10%~+12% 以内 |

**严档**＝ `sticky_pull` 三条全过（用户选定的那一档：实测 2026-10-12 命中 22 只，全场 397 只）。
`ambush_score`（0~100）**只为排序**，不是涨跌概率：紧 40 + 周线抬升 25 + 缩量 20 + 箱体位置 15；
缺的那一块从**分母**里剔掉，不按 0 计 —— 0 分会参与排名，于是「没数据」被排成「很差」。

三条不许破的口径：
1. 缺数交 NULL，界面显示 `—`。极差 0% 会被读成「完美粘合」、缩量 0 会被读成「极端缩量」，方向正好相反；
2. 价格一律**后复权**（`close × adjustment_factor`）；只有「突破价」那一列给未复权价（那是人真能成交价）；
3. 周线按 ISO 周分桶，**当前周不足 5 个交易日不计入连升**（2026-W41 只有 2 场、W42 只有 1 场），
   并把这一周有几天一起交出去（悬停里）。⚠️ 「要几个完整周」定的是 **7 不是 8**：
   2026-10-12 那 11 个周桶里有 4 个是国庆切碎的不完整周，定 8 会当场把严档清空（实测严档恒 0 只）。

## 三、右栏判据（`analytics.volume_breakout_signal`，判据只住 `app/compute/breakout_signal.py`）

三段式**时序形态**识别，不是单日统计：

1. 窗口 40 个交易日内有过一波放量：`vol ≥ 前 5 日均量 × 1.8`（`SURGE_MULT`）
2. 之后贴线横盘：连续 ≥ 5 天（`CONVERGE_MIN_DAYS`）`|close/ma60−1| < 5%`（`DEV_THRESH`）
3. 第一个同时满足「站上 MA60 + 放量 ≥ 1.6×（`BREAK_MULT`）」的那天 = `first_break`（买点候选）

三类信号：`first_break` 首破 / `surge_after_shrink` 放量后缩量（观察期）/ `converging` 收敛中（还没突破）。
中文标签**只在计算模块 `TYPE_LABELS` 写一份**，接口按行交出 `signal_type_label`，
列头 `sortKey` 用的就是这个标签 —— 原先排的是 `first_break` 那串英文码，
点「信号类型」列得到的行序读者看不懂（写错的 sortKey 不报错、也不换序，只有点下去才看得出来）。

## 四、接口

| 端点 | 参数 | 说明 |
|---|---|---|
| `GET /api/quant/ambush` | `date` / `limit`(≤800) / `types=a,b` / `only_strict` / `min_weekly_ups` | 信封 `{"data":…}`；类型多选**在库里筛**（`ambush_types && %s::text[]` 拼在 `order by … limit` 之前） |
| `GET /api/quant/volume-breakout` | `date` / `limit`(≤800) / `signal_type` | 同一场筛三类之一，也在库里筛 |

两栏各自交出（口径全部由后端说话，前端不重算、不另写一份）：

- `type_options`：每一类**全场**实有几只 + 中文标签 + 这一类在筛什么（悬停与下拉共用这份）。
  ⚠️ 这条聚合**不带筛选条件、不带 limit**：右栏原先是「把已交出的 150 行数一遍」，
  于是「首破 7 只」读起来像全场只有 7 只，其实那是截断后剩下的行数（全场是 615 只里 7 只首破）。
- `day_total`（+ 左栏 `day_strict_total`）：这一场命中的票数，是**全场**不是本页行数。
- `thresholds`：判据阈值原值。页面上的「< 1.5%」「≥1.6×」全从这里念出来，改一处两边一起改。
- `filter.types_rejected` / `filter.signal_type_rejected` + 同名 caveat：认不得的筛值**不参与筛选并当场点名**，
  静默丢掉等于交一份「看着像筛过了其实没筛」的榜。
- `coverage` / `definitions`（列注释）/ `caveats`：`short_window` 点名 K 线不足满窗的票；
  `ambush_counts_unread` 说「没读到」而不是给 0（0 的意思是这一类今天一只都没有）。
- 不可用时只交 `{available:false, reason:…}`，**不带 `rows` 键**；库里没有这一场就直说没有，不回落到邻近交易日。

## 五、界面

- 容器 `max-w-[1720px]`，`xl:grid-cols-2` 两栏并排（窄屏退回上下堆叠）；每栏各自横向滚动。
  要给两栏更多宽度，把顶栏那条「AI分析」栏收起（收起的 256px 全部还给中间）。
- **两栏各 8 列**（用户选定）：左＝代码/名称/埋伏类型/均线极差/20日高低差/周线抬升/缩量比/埋伏分；
  右＝代码/名称/信号类型/突破倍数/突破价/突破偏离/收敛天数/缩量天数。
  **被砍掉的列进整行悬停**，不凭空消失：左栏悬停给后复权收盘、满窗真实性、箱体位置、60 日涨幅、
  离 MA20/MA60、连升周数、本周几天、最近大阳那根的日期与距今、量价背离度、缺了哪些读数；
  右栏给板块、上次放量日与那波倍数、突破日 MA60、窗口与实有 K 线根数。
- 筛控件挂在 `Panel` 的 `controls` 槽上（**永远渲染**）。原先它们在 `children` 里，而 `children` 只在有数时画 ——
  于是选了「这一场为空的档」之后，下拉和日期框跟着数据一起消失，人卡在自己刚选的那个值上只能刷新整页。
- 每栏一行「这一场命中 X 只（严档 Y 只）｜本页交出 Z 行」；达到取数上限时黄字说明
  「下面看到的不是这一场的全部，上面那个数才是全场」。
- 股票名走东财行情外链（新标签）；点一行高亮整行；空态分「被筛条件筛空」与「链没跑到这一档」两句话。
