## 12. 不许破的纪律

1. **判据只住一处**：点火阈值在 `app/compute/ignition.py::DEFAULTS`（`:82-122`）+ `params()` 三层合成；
   档位与低吸分判据在 `app/compute/sector_trend_signal.py`（`compute_one` `:198`、`_regime` `:303-333`）。
   接口和页面**只读现成结果**（`caveats.single_judge` 就是这条，`quant.py:1286-1287`）。
   屏上那块"逻辑就在屏上"的静态说明（小节 5）是给人读的判据叙述，**不许变成第二套计算**。
2. **缺是「缺」，不是 0**：五要素算不出 → 格子写 `缺`（`SectorHeat.tsx:314`），且 NULL 不参与排名、0 参与
   （`caveats.null_not_zero`）；`dip_score` 只在两档下有值 → `—`；广度那一列**判缺看 `breadth_available`**
   而不是看值是否为空（`:313`）；六分项逐 key 判 null（`:496`）。把"缺"渲染成 0 会让算不出的板块排到前面。
3. **累计类读数不许说成覆盖全窗**：库里 `sessions=2`（2026-10-08~10-09），标题、`calibers.sum_since`/`sum_3m`、
   表底 `CaveatText` 三处都在念"这几场的和"。**措辞已经为这件事改过一次**（屏上标题从
   「2024 年以来累计净流入」变成「覆盖以来累计净流入（库里 N 场：from ~ to …）」）—— 别把它改回去。
4. **母体数与行数不许混**：`universe.rows_today=983`（热度榜母体）、`rows_returned=200`（`limit` 截断后）、
   档位表 `sectors=60`（返回行去重数）与 `active_total=1859`（在册概念+行业）**是四个不同的分母**，
   后端把四个都交出并在 `universe.note`/`caliber` 里各自点名（`quant.py:1067-1073`、`:1314-1321`）。
   页面不许用 `rows.length` 当母体数。
5. **上限要说出口**：热度榜「本次交出 200 行（limit 200）—— 榜是截断的」；累计块每页 50、翻页排全量；
   截面块只渲染前 30 行并明说。`limit` 夹在 1~1000（`vr/app.py:784`/`:839`），截不断就得抬上限重打，别猜。
6. **统计指数只在界面藏、不在取数层删**：`statistical` / `unnamed` 是标记，母体计数含它们
   （删了"藏掉多少行"就不可审计，`quant.py:927-931`）。按钮默认藏 + 实时把藏了多少行写在标签上。
7. **两套判据不相加、两榜不混排**：`heat` 与 `score`（caveat 原句）、`sort=dip`（低吸分降序）与
   `sort=seed`（`position` 升序）分两屏 —— 排序方向由后端两条路给，界面不许自己 reorder（`quant.py:1197-1201`）。
8. **NaN/NaT 不许出门**：出口过 `_num/_int` + 三态布尔（`quant.py:990-999`）；本轮五个 payload 文本内
   `NaN`/`Infinity` 0 次。
9. **`heat_pctile` 与 `heat_rank/universe` 方向相反**（见 11.3）—— 拿 `rank/universe` 当分位喂过热判据
   已经错过一次（369 行误判，`16_sector_trend_signal.sql:54-58`）。屏上凡是"过热"必须旁边带横截面名次。
10. **列注释里的常数不许当现状**：`ignition.term_count` 那句"230 个行业板块"已被实测推翻（实际 296 个、
    只有 1,086 行有广度值），页面只引用当下的 `breadth_reality`/caveat（屏上 `:672-674` 明写这条纪律）。
11. **未来函数不许当实盘序列**：`scope=group_rebuilt` = 以今日名单回算，只给形状；快照天数还要过
    单调性假序列判据（`quant.py:1248-1263`），不合格时红框明说"不能当实盘序列用"。
12. **不替后端说话**：`_NOTE`、`calibers`、`regime_meaning`、`elements.means`、`reasons.why` 一律原句照贴；
    接口没交那条含义时屏上写「后端未交 / 不编」（`:430`、`:479`、`:612`），本文件对应位置也只指路不改写。
13. **URL 上的查询键只认路由函数签名**（10-15 晚补的一条，起因见 §14.1）：本屏的类型按钮曾发 `sector_type=`
    （照抄了视图函数的形参名），而路由收的是 `type=` —— FastAPI 对不认识的键**不报错、直接丢**，
    三个按钮点了半年、榜照旧是全类型截前 200 行。与 `sortKey` 死键同一类：**界面只是"看起来在动"，没有任何一处会红**。
    加了 `sort` 这一档之后更要钉这条：换档请求真要带上 `sort=`，否则两把尺子在屏上是同一把。

## 十四、2026-10-15：热度榜加了第二把尺子（按板块自己指数的当日涨幅排）

接口：`GET /api/quant/sector-heat?sort=heat|pct`（默认 `heat`）。参数只认这两个值，两道闸按顺序生效（10-15 实测）：路由层的 `Query(pattern="^(heat|pct)$")` 先挡，
`curl "?sort=xx"` 回 **422**（`string_pattern_mismatch`，不进函数体）；绕过路由直接调
`quant.sector_heat(sort='xxx')` 才回 `_reject` 那句「sort：只支持 heat…」。
两者都不是「这一场没有数据」—— 一个是"你给的条件我按不了"，一个是"库里没这场"，混成一句会让人去查回填。

- **涨幅 = 板块那条 880 指数自己的 `(今收 − 昨收) ÷ 昨收`**，来自 `market_data.sector_daily.pct_change`。
  **不是把成分股涨幅平均出来** —— 宽成分的概念榜上两种算法能差出一个档。
- `pct_rank` 与 `heat_rank` **两把名次都算**：按涨幅榜时行首那个 `#N` 走 `pct_rank`；
  只算热度名次的榜，切档后会出现"榜按涨幅排、名次却写着热度第几"。
- 换档 = 换一次后端请求（排序拼在 `limit` 之前）。前端点列头只重排已经取回的那一批，
  截断之后的榜在前端排不回来 —— 所以档按钮与列头排序是两件事，界面上分开。
- 母体里当天没有这条 880 日线的板块数交在 `universe.pct_null_today`（2026-10-15 实测 0 个），
  那一格显「缺」不显 0%。
- 同一批还多出 `up_count / down_count / member_count`（板块当日涨/跌家数与成分数）作为两列显示。

实测（2026-10-15 当日，`sort=pct` 前 5）：创业均价 +3.03%、卫浴电器 +2.73%、商用载客车 +2.68%、
电信运营服务 +1.85%、白酒 +1.75%。**同一天的热度榜第一是别的板块** —— 两把尺子本就不该同序。

### 14.1 顺带抓到一条静默缺陷：类型按钮发的参数路由不认（10-15 晚已修）

`SectorHeat.tsx` 那一发 probe 的查询串里写的是 `sector_type`（视图函数 `duanxian/quant.py::sector_heat()` 的**形参名**），
而路由 `quant_sector_heat()` 的**查询形参叫 `type`**，转发时才写成 `sector_type=type`。FastAPI 对不认识的查询键**不报错、直接丢**，
所以那三个「行业／概念／风格」按钮从上线起就没生效过：点了照样发请求、照样转一圈，回来的还是全类型 983 行里截的前 200 行。

实测（10-15 晚，`limit=1000`）：`?sector_type=行业` → **983 行**、`sector_type` 集合是 `{概念, 统计, 行业, 风格}`（等于没筛）；
`?type=行业` → **557 行**、只有 `{行业}`。

与 `sortKey` 死键同一类：**参数名写错不会有任何人报错**，界面只是"看起来在动"。所以这条屏的纪律是
**URL 上的键名只认路由签名，不认视图函数形参名**；改判据时两边都要看一眼。
修法：`SectorHeat.tsx:161` 的 `sector_type: type` → `type`（前端一行，不需要重启后端）。
