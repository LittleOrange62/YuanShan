# 明日展望（`/tomorrow-outlook`）

一句话：把每天 19:00 那一炉「推送任务 ⑩ 明日展望」发出去的两张短名单原样摆上屏，
并把名单里每一只票当天的**全部 35 项技术指标**摊开（能跨票比的那 19 项另给全场名次）。
只说明"明天盯什么、什么算坏了"，不预测涨跌、不给买卖建议。

用户 2026-11-05 的原话是「在量化选股中增加一个明日展望，就是把任务推送 10 里面的内容展示出来，
并针对提到的个股，把这些个股的各类指标全部展示出来」。这一屏不是新判据：
两张榜的选法 11-04 就长在推送那一炉里，11-05 **搬到读侧一处**，两边共用（见 §二）。

页面入口：`/tomorrow-outlook`（导航「量化选股」组，排在「趋势股」之后）
接口：`GET /api/quant/tomorrow-outlook?date=YYYY-MM-DD&expand=true|false&refresh=true|false`
判据与取数：`duanxian/tomorrow_outlook.py`（**一处实现**；`ingest/jobs/push/t10_tomorrow_outlook.py` import 同一份）
参数：`app/intraday/broadcast_config.json` 的那 8 个 `t10_*` 键
措辞：`app/intraday/templates.json` 的 `tomorrow_*`（只在推送那一炉拼句子，屏上读结构化字段）
判读层（纯函数、可单测）：`frontend/src/lib/tomorrowOutlook.ts`　组件：`pages/TomorrowOutlook.tsx`
落库的留痕：`analytics.intraday_broadcast`（`task='tomorrow'`）
隔日表现回溯（6 个月、往后 1/2/3 个交易日、冲高率与全市场基线对照）**不挂本屏**：
11-06 按用户点名挪到「工作空间 → 策略回测」那一屏底部
（见 `docs/功能点说明/个股研究与回测/回测.md` §5.5；表是 `analytics.outlook_pick_daily`），
本屏底部只留一条指路链接 —— 同一个读数挂两处，改天就会长成两个说法。
系统配置自检在册：`/system` → 能力清单「明日展望（推送 ⑩ 的两榜 + 逐票全部指标）」，MCP 台账 `tomorrow_outlook`（C 层）

---

## 一、链路五步

| 步 | 做什么 | 落在哪 | 失败会怎样 |
| --- | --- | --- | --- |
| 1 | 日线、涨跌停池、趋势管线、因子、股性各自加工入库（每日链那 46 步里的若干步） | `market_data.stock_daily`、`analytics.indicator_value`、`analytics.trend_stock_daily`、`analytics.stock_character_daily`、`analytics.limit_up_pool_daily`、`analytics.xy_rank_daily` | 任何一张输入表那天没场次，两张榜**不拿上一场顶**：读侧交 `available:false` 并说最新到哪天 |
| 2 | 19:00 那一炉调 `collect()` → 里面调这里的 `hits_shortlist` / `trend_shortlist` / `top_boards` | 排版后的正文先落 `analytics.intraday_broadcast`（`task='tomorrow'`，`what='tomorrow'`） | 三节全空 ⇒ 一条都不发，只记 `tomorrow_empty`（宁缺毋假）；这一屏的开关**默认关着** |
| 3 | 再发渠道（`--send` 才发；判据是渠道业务码，不是 HTTP 200） | `duanxian/notify.py::send_to` | 未确认时把渠道回体原话记进 `err`，屏上那一格念"未确认：…" |
| 4 | 屏读：`view()` 组装两张榜 + 逐票全部指标 + 今天那条原文 | `duanxian/tomorrow_outlook.py` | 只交 `{available:false, reason}`，**不带 hits/trends 键**；缓存里的失败结果不钉住（补跑完当场能重读） |
| 5 | 页面渲三张表 + 单击交叉高亮 + 双击开个股深度复盘 + 点中一行换标的（共用 `StockDossier`） | `pages/TomorrowOutlook.tsx` | 接口没接上时 `useProbe` 报 `not_wired`，页面老实写「接口尚未实现」 |

## 二、判据（两处调用方、一份实现）

**这一族的第一条纪律：判据只住 `duanxian/tomorrow_outlook.py`。** 两张榜原先长在推送脚本里，
11-05 搬过来后，那一炉用**别名**引用（`_hits_shortlist = TO.hits_shortlist`）—— 用别名而不是包一层薄函数，
那样 `inspect.getsource` 顺着别名拿到的是真 SQL，「股性过滤住在查询层」那条钉子才还指着实际跑的那句话。

### 一、多指标靠前

1. **家族** 9 项（`t10_family`，实测 11-05 在册）：10日涨幅 `chg10`、20日涨幅 `chg20`、20日斜率 `slope20`、
   250日位置 `pos250`、相对板块强度 `rel_sector`、10日日均涨跌 `chg10_avg`、20日日均涨跌 `chg20_avg`、
   成交额分位 `amt_rank`、量比 `vol_ratio`。**为什么没有 MACD 柱**：它的量纲是元，按原始值取 top 会退化成"最贵榜"。
2. 每一项在**每一场**里各自 `rank()` 取当日前 `t10_top_n`（默认 100）名。
3. 当日命中 ≥ `t10_min_hits`（默认 4）项者进榜；排序 = 今日命中项数 ↓ → 近 `t10_window_sessions`（默认 3）场里重复上榜的场数 ↓ →
   XY 合计名次 `analytics.xy_rank_daily.rank_sum` ↑（越小越前，没写名次的排最后）。
4. 最多交 `t10_hits_n`（默认 8）只。每只再补「它最靠前的是哪几项」（按**当日排名**取前 3，中文名读 `config.indicator.name`）
   与今日涨停池的 `consec`／`reason`。

### 二、趋势最正

1. `analytics.trend_stock_daily` 当日 `selected5` 且 `above_ma5` 都成立的票；
2. 连续站上 5 日线天数 ≥ `t10_trend_streak_min`（默认 5）；
3. 排序 = 站上天数 ↓ → 是否 20 日新高 ↓ → 是否封板 ↓，最多 `t10_trend_n`（默认 6）只；
4. 附 250 日位置（读 `indicator_value` 的 `pos250`，不是现算）与当日涨幅。

### 两榜共同的股性闸门（用户 11-04 追加）

在 **SQL 层**只留 `analytics.stock_character_daily.char_level ∈ t10_char_keep`（默认 `['strong']`=股性强）。
事后在 Python 里删会把 `LIMIT` 已经取走的 middle/weak 换成别人，名单语义就变了 —— 所以不许退化成事后删。
`char_level IS NULL`（上市不足 120 场或档位价缺）**照留并点名**"股性判不了"，那一格是 `—`，不是"股性差"。

### 三、明日观察清单

两榜交集（并集计数、交集只念一次）+ 今日封住票里的最高标（≤3 只按封单额排，`limit_up_pool_daily` 的 `lup-1` 批）
+ 「什么算坏了」（趋势榜收盘跌破 5 日线、指标榜前排次日大幅低开无承接）。**观察口径，非预测。**

## 三、逐票全部指标那一块（用户点名的"全部展示"）

一行一只票、一列一项指标。三项读数一次摆齐：值（带单位）、全场名次、该项当日母体只数。

| `config.indicator.output_unit` | 项数（11-05 实测在册 35 项） | 屏上给什么 | 为什么 |
| --- | --- | --- | --- |
| `pct` / `ratio` / `none` | **19** | 值 + 全场第 N 名 + 母体只数 | 量纲跨票可比，"靠前"才有共同尺 |
| `yuan`（MA5~MA250、MACD 三件、均价、中价、250 日最高/最低、ATR14） | **15** | **只给值** | 绝对价格是量纲不是强弱：`ma5` 排全场第 8 名只说明它贵。给名次＝让屏幕说假话 |
| `count`（`chg_rank` 涨幅排名） | **1** | 只给值 | 它本身就是一名，再排一次是把名次当数值排 |

- 名次用 `rank()`（同分同名、下一名顺延），规则文案只引 `duanxian/ranking.py::RULE_NOTE_SHORT`，随 `rank_note` 交出。
- **分母逐项自带**：同一场里各项的母体不一样（11-05 实测 `amp` 5,571 只、`ma250` 5,393 只），
  拿一个统一分母解释所有名次就是假数。分母算的是 `count(v.value) over (...)`（NULL 不进分母）。
- 缺那一行 ⇒ 交不出键 ⇒ 那一格 `—`，并进 `missing_indicators` 点名。**不写 0**（0 会被读成"平盘"或"垫底"）。
- 上限 `MAX_EXPANDED = 40` 只：两榜并集超过它时榜单照全，只把前 40 只的全部指标交出来，并交一条 `expanded_truncated` 硬声明。
- 排序键 `ind.<指标键>.v`：同一列里名次随值单调，所以一把键够用；缺值两个方向都排末尾。

## 四、参数表（能动它的只有配置文件，界面不能改）

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `t10_family` | 上面那 9 项 | 一、的家族 |
| `t10_top_n` | 100 | 每项取前几名 |
| `t10_min_hits` | 4 | 当日命中几项才进榜 |
| `t10_window_sessions` | 3 | "重复上榜"看近几场 |
| `t10_hits_n` | 8 | 一、最多交几只 |
| `t10_trend_streak_min` | 5 | 二、至少站上几天 |
| `t10_trend_n` | 6 | 二、最多交几只 |
| `t10_char_keep` | `['strong']` | 两榜留哪几档股性 |

⚠️ 这一族参数**不在系统配置界面**上（那是推送那一栏的家当，改它等于改每天往群里发什么）。
配置文件读不到时读侧走代码默认值，并当场交一条 `params_unread` 硬声明（屏上留在外面不折）——
静默兜底会让"屏上的门槛"和"19:00 实际用的门槛"分叉。`tests/test_tomorrow_outlook_view.py` 有一条
钉「兜底默认与在册配置逐键相等」，就是为了这条分叉不可能悄悄发生。

## 六、不许破的纪律

1. **判据一处实现**：推送那一炉只 import，不留第二份 SQL。改判据＝两边同时变，这是优点不是风险。
2. **绝对价格不排名次**。`RANKABLE_UNITS` 与 SQL 里那句 `unit in (...)` 同源（常量拼出来），不许两处各写一份。
3. **缺数交 null**：`_num()` 的 `pandas.isna` 闸排在日期判断之前（`pd.NaT` 是 datetime 实例，反了会产出非法 JSON）。
4. **中文档名不抄第二份**：股性三档读后端 `char_level`＋`lib/tomorrowOutlook.ts::charLevelText` 一处映射；
   指标中文名一律 `config.indicator.name`；名次规则只引 `duanxian/ranking.py`。
5. **后端散文字段不许裸 markdown 星号**（`tests/test_tomorrow_outlook_view.py::每一条声明都配了中文标签` 逐条数）。
6. **硬声明留在屏上**：`params_unread`／`hits_session_missing`／`trends_session_missing`／
   `indicator_rows_absent`／`expanded_truncated` 都带 `hard:true`，且 code 属"库不健康"那一族 ⇒ 前端白名单不会折它们。
7. `refresh` 只走这条读路（跳过 15 分钟缓存），**MCP 侧一处都不外露**（`capabilities.HIDDEN_PARAMS`）。
8. 「点中一行 → 换标的」那块单独成 `FocusPane` 组件去订阅选中态，提回页面组件等于每次单击把 35 列那张表整个重协调一遍。
