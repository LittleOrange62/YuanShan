## 新架构下最危险的三件配置类事（2026-09-24 实测排序）

1. **备份与库同存储，且没有任何东西让它保持新鲜。** 不是"无可用备份"—— 那条今天已变：daily 225MB **恢复验证通过**、weekly 全库 608MB 在盘。真正的洞是 dump 落在 `D:\finance\TataPG_backup`，与数据目录 `D:\finance\TataPG` 同一个卷；C: 是**另一块 VMware 虚拟盘**（114 GB 空闲，库本身 11 GB），够用，但两块虚拟盘很可能同宿主存储 → **只防误删和文件系统损坏，不防宿主/存储级故障**，那句"另一块物理盘"要按这个折扣理解。三档备份计划任务一个都没注册，新鲜度只被 `doctor`「数据库备份」项报出来、不拦启动。
2. **`ft_etl`／`ft_admin` 的明文口令。** 实测 `D:\finance\YuanShan` **根本不是 git 仓库**（`git rev-parse` 报 not a git repository），`.gitignore` 里写着 `.env`/`.env.*`/`.local/` 但没有任何东西在执行它。所以"别提交"眼下不是风险，**"别打印"才是**：诊断输出、异常栈、`--json` 原样 dump、会话回报，任何一处 echo 一次口令就永久进档。给到 `ft_admin` 后，同一个泄露面从"能读"升级成"能删库"。
3. **调度无宿主 × 唯一写入方没有第二套口径兜底。** 旧版这条写的是"吸收期双写 + YuanShan 只写 `ys.*` 影子 schema、发 `ft_etl` 时 `REVOKE` 掉它在 `market_data`/`analytics`/`qd` 的写权限只授 `ys`" —— **整套过渡口径已作废，就地改正**：不存在影子 schema，本项目直接生产 `analytics.*` / `market_data.*` 全部正式表；也不存在"双跑对账期"，旧项目已停用。
   同时旧版那句"FT 的调度从一开始就是空的"**是错的**：它那条收盘同步计划任务 2026-09-25 16:05 真跑过并**写进了这套库**（c18/c19/c20 三步 OK），也就是说"两边同时能写同一个库"不是未来的风险而是**已经发生过的事实**，只是当时没人把它当双写看待。
   现在的两个洞因此换成：① **唯一写入方＝没有对手盘**，本项目口径写错就是错了，没有第二套实现能对照出差异，只有 [数据加工/08](../数据加工工作指南/08-跨源口径契约.md) 那种逐条对数与 e2 审计能兜，而 3,789,096 行日线的回滚能力取决于第 1 条；② 挡住旧任务的是 `Disable-ScheduledTask` **一个开关，不是权限闸** —— 重新启用、或直接手动跑旧仓库那份脚本，双写立刻回来；真正的收口是用户删掉那两个参考目录，在那之前别碰那条任务的 Enabled 状态。高频那半（30 秒轮询）仍然没有宿主，见 09 与"待写"的 05。

## 这台机器上要知道的四个环境事实

1. **控制台是 GBK**：任何脚本打印 `✓`/中文都会崩，跑之前设 `PYTHONIOENCODING=utf-8`（或用 `-X utf8`）。
2. **测试基线不是零失败，而且数字自己在漂**：2026-09-24 同一份代码连跑两次得 **21 failed/1061 passed** 与 **17 failed/1065 passed**（旧记录写"15 failed/1021 passed"，已不可复现）。**比失败文件名集合，不比数字**，并且要留全量日志（`--tb=no > .local/pytest_full.log`）；判断有没有引入回归用 `VIBE_PG=0` 复跑对照，不是看有没有红。
3. **`tests/conftest.py` 拦出站网络**：给数据层写测试必须打桩，不能真连库真联网。
4. **免鉴权数据源会被按频率断连**：见 [数据加工/08 §三](../数据加工工作指南/08-跨源口径契约.md)。
