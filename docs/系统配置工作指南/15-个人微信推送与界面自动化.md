# 15 · 个人微信推送（在本机桌面上按键盘的那条通道）

> 用户 2026-10-20 点名：「有没有什么好的脚本或者接口，可以操作电脑本地的微信客户端进行发消息？」
> 选定第一条路线（界面自动化），并逐条圈了流程：
> **「开启微信界面快捷键（可配）→ 全屏微信 → 搜索（默认 Ctrl+F，可配）→ 切换成英文输入并输入内容（可配）
> → 鼠标点击默认的第一个 → 鼠标点击到输入框 → Ctrl+A 全选 → 删除内容 → 粘贴内容 → 回车发送
> → 缩小微信界面快捷键（可配）」**，并且要求
> **「发送的内容可以配置，做成一个单独的功能点，不仅仅你自己用，还可以给其他程序调用」**。

这一条**不是第五个渠道**。隔壁 [14](14-消息推送渠道与定时计划.md) 那四条（邮件 / 企业微信群 / 钉钉群 / 飞书群）
是网络请求；这一条是**在这台机器的桌面上替你按键盘**。两条路的失败形状完全不同，所以配置面、
预检、留痕、措辞都是各写一套的（共用的是内容组装那一份，见 §五）。

## 一、先承认三条实测出来的硬约束（2026-10-20 现场）

这三条决定了整个方案的形状。**它们不是"以后能改好"的技术债，是环境事实**，所以界面上一直写着：

| # | 实测 | 后果 |
|---|---|---|
| 1 | 本机微信是 `D:\Weixin\Weixin.exe` **4.1.8.29**（Qt5 内核）。主窗口认得到（`hwnd`、`class='Qt51514QWindowIcon'`、`title='微信'`），但**前台激活并点击之后 UIA 的子控件数是 0** | 读不到输入框 ⇒ 「点第一个搜索结果」「点输入框」只能靠**按键走过去**或**固定坐标盲点**；被「删除」掉的那段草稿**也读不回来**（没法还原） |
| 2 | RDP 客户端**最小化或断开**时，这个会话既没有渲染表面也没有输入桌面：整屏 GDI 取色 5.6 万个采样点**全为 0**、PowerShell `CopyFromScreen` 报「参数无效」、`GetForegroundWindow()` 回 **0**、`SendInput` 一律回 **`ERROR_ACCESS_DENIED(5)`** | 这条通道**只在有人连着桌面时可用**。无人值守请用它隔壁那四个渠道 |
| 3 | `SendInput` 的 `INPUT` 结构体在 x64 上必须正好 **40 字节**（union 按 `MOUSEINPUT` 取大）。只放 `KEYBDINPUT` 时算出 32 字节 | 现象是「代码看起来完全正确、桌面上什么都没发生」，只回一个 87 错误码。`duanxian/wxpush.py` 里留了 `assert ctypes.sizeof(_INPUT) == 40` 当场拦 |

> 第 1 条有一个**尚未区分的分支**，别当结论背：UIA 读到 0 个控件这件事是在**无桌面**状态下测的。
> 有可能是客户端封死无障碍树，也有可能是没有渲染表面时的连带后果。
> 分辨办法很便宜：坐在远程桌面前（窗口正常显示）再跑一次 `.local/probe/wx_probe3.py`，
> 看 `descendants` 是不是仍然为 0。**在测出来之前，本程按"读不到控件"设计**（这是更保守的那一侧）。

## 二、四个文件的分工

| 文件 | 管什么 | 为什么单独一个 |
|---|---|---|
| `wxpushconfig.py` | 步骤表 `STEP_DEFS`（12 步）、预检闸 `GUARD_DEFS`（7 项）、内容档校验、组合键解析与键码表、读写与留痕 | **只用标准库**：`scripts/manage.py` 在依赖没装时也要能读出"这条通道开没开"。与 `notifyconfig.py`/`netconfig.py` 同形 |
| `duanxian/wxpush.py` | 只读探测、预检、正文组装、**把 12 步展开成动作序列**、真注入 | 纯计划（`build_ops`）与真副作用（`_desktop_apply`）**彻底分开**，见 §三 |
| `vr/app.py` 三个端点 | `GET /api/wxpush`、`POST /api/wxpush`（单键改）、`POST /api/wxpush/send`（对外功能点） | 校验全在配置层，端点不重复一份 |
| `frontend/src/lib/wxpushRules.ts` + `wxpush.ts` + `components/WxPushPanel.tsx` | 判据（纯函数，`node --test` 驱动）/ 取数 / 面板 | 与 `notifyRules.ts`/`notify.ts`/`NotifyPanel.tsx` 同一套切法 |

配置落盘（**不落 PG**，与推送配置同一套规矩）：

```
<ASTOCK_DATA_HOME>/wxpush/config.json      ← 步骤、闸、内容档、默认收件人、谁改的
<ASTOCK_DATA_HOME>/wxpush/history.jsonl    ← 每次发送一行，成败都记，不存正文全文
```

测试注入点：`VIBE_WXPUSH_CONFIG` / `VIBE_WXPUSH_HISTORY`（日常不要设）。

## 三、为什么要有「发送前的检查」这道闸（这一节是本文的核心）

这条通道最常见的失败**不是"发错了"，而是"什么都没发生"**：没有桌面时按键被系统拒收，
没有渲染面时坐标点到的是黑屏，微信没登录时按键打进的是别的应用。
三种情况都不会留下一句话。所以：

1. **`preflight()` 全是只读查询**（找窗口、`GetForegroundWindow`、GDI 采样、空闲时长、冷却、
   总开关、配置合法性）。它挂在 `GET /api/wxpush` 上，**面板每打开一次就现算一遍**，
   所以它绝不允许为了"看看行不行"去注入按键 —— 有一条用例（`test_预检函数本身一个键都不按`）
   把注入原语全换成"一调就炸"来钉这件事。
2. **任何必检项不过 ⇒ 当场拒发**，并把**每一条**检查的实情原样交出去（不是只报第一个失败）。
   界面上就是那一栏「发送前的检查」，逐条写着"现在空闲 1 秒，门槛 10 秒 —— 这台电脑正有人在用，不插队"这种话。
3. **判不了 = 不放行**。`idle_seconds()` 读不到时返回 `None`，预检按"不过"处理，
   绝不降级成"空闲很久"（与配置层"读不到就按关闭运行"同一条取舍）。
4. **主按钮不静默禁用**。「真发这一条」永远点得动；预检没过时**在原地列出还差哪几样，
   并且不发那次注定被拒的请求**（用户 10-19 定的交付纪律）。
5. **每一步注入之前都核对前台窗口就是微信**。中途焦点被对话框或鼠标抢走时立即停手 ——
   因为后面的 `Ctrl+A` / `Delete` / 粘贴会**作用在别的程序的输入框里**，
   那比"没发出去"严重一个数量级。停手时结果里写着"停在第几步"。

七道闸本身都可以关（`GUARD_DEFS`），但**默认全开**，并且每一条都写了"关掉之后会付出什么"。

## 四、十二步流程：出厂值与可改的格子

`STEP_DEFS` 是**唯一登记表**：一条描述符 = 面板上的一行 = 执行体里的一个阶段。
加一步只动两处（描述符 + `build_ops` 里那段），界面自动跟上；
忘了接执行体由 `test_步骤表与执行体同集合` 与 `test_十二步各自都有真效果_开着就出现关掉就消失` 判红。

| 步 | 面板上的名字 | 出厂做法 | 可换成 |
|---|---|---|---|
| 1 | 唤起微信窗口 | 先按 `Alt+1`、没起来就直接唤窗 | 只按快捷键 / 只直接唤窗 / 跳过 |
| 2 | 全屏微信 | **保持原尺寸**（默认不做） | 最大化窗口 / 按快捷键 |
| 3 | 打开搜索框 | `Ctrl+F` | 键可改 |
| 4 | 切换成英文输入法 | **不切**（默认不做） | 一次 Shift / Ctrl+Space / Alt+Shift |
| 5 | 输入要发给谁（搜索词） | 粘贴 | 逐字键入 |
| 6 | 选中搜索结果里的第一个 | 按 Enter | 先 ↓ 再 Enter / 点固定坐标 / 跳过 |
| 7 | 点到输入框 | **不做**（默认跳过） | 点固定坐标 / Tab |
| 8 | 全选输入框内容 | `Ctrl+A` | 键可改 |
| 9 | 删掉输入框里的原内容 | Delete | Backspace / **不清** |
| 10 | 把要推的内容粘进去 | 粘贴 | 逐字键入 |
| 11 | 回车发送 | Enter | 键可改 |
| 12 | 收起微信窗口 | 先按 `Alt+1`、没收就直接隐藏 | 只按快捷键 / 只隐藏 / 不收 |

三处对用户圈的口径做了**修正**，理由都在界面上写着，不是偷偷改：

- **搜索词与正文都走剪贴板粘贴**，所以「切换成英文输入」默认关掉。
  粘贴根本不经过输入法，切输入法反而多一个会错的环节（要按你的输入法习惯开回来，那一档留着）。
- **「点击」默认用 Enter / 跳过代替坐标**：这一客户端读不到控件位置，坐标只能人工量；
  坐标点错了**不会报错**，只会点到窗口里别的东西上。所以坐标是可选项而不是默认。
- **第 9 步会在界面上标出「会动你桌上的东西」**：它把人家的**未发草稿**一起删掉，
  而且删完读不回来（没有控件树）。不想冒这个险就选「不清」，那样正文会接在草稿后面。

两条形状上的纪律：

- 坐标存的是**相对微信主窗口左上角的偏移**，不是屏幕绝对坐标（窗口一挪，绝对坐标就点到别的应用上）。
- 组合键只认「若干修饰键 + 一个普通键」，白名单是 `KEYS`/`MOD_VK`；
  写错了存不进去（`ctrl+q` 里 `q` 在白名单内所以能存，`ctrl+bogus` 当场拒）。
  切输入法那一档是唯一允许「纯修饰键」的形状，走 `mods_seq()` 单独展开。

## 五、内容这一层：单独的功能点，别的程序也能调

用户要的是「发送的内容可以配置，做成一个单独的功能点」。落成了两样东西：

**① 内容档（`templates`）** —— 面板上可增删改、可启停，三种来源（界面上只有这三个框）：

| `source` | 名字 | 正文从哪来 |
|---|---|---|
| `text` | 固定文字 | 面板上写的字，支持 `{date}`（本场日期）与 `{now}`（当前时刻）两个占位；**写错占位（如 `{time}`）在保存时就拒**，因为那种串会原样发进微信 |
| `scene` | 用现成内容档 | **直接调 [14](14-消息推送渠道与定时计划.md) 那十七档的同一个组装器** `duanxian/notify.compose()`：同一条「自选股当日明细」在企微/飞书/微信里必须是同一段字，两处各算一遍第二天一定有人说"对不上"。可选格子来自 `notifyconfig.SCENE_KEYS`，前端一份都不抄 |
| `script` | 跑一个本地脚本 | 仓库内的 `.py`，stdout 当正文。路径**解析后必须仍落在仓库里**（`/etc/x.py` 这种在 Windows 上 `isabs` 回 False 的形状也一样被拒），否则这条通道就成了「读任意文件」的口子 |

**② 对外的发送入口** —— 这就是"给其他程序调用"的那一个接口：

```bash
# 先看一遍：后端一个键都不按，只回正文 + 预检逐条 + 将要执行的动作序列
curl --noproxy '*' -s -X POST http://127.0.0.1:8910/api/wxpush/send \
  -H 'Content-Type: application/json' \
  -d '{"to":"文件传输助手","template":"close_note","dry_run":true}'

# 真发
curl ... -d '{"to":"文件传输助手","text":"今晚 21:00 的持仓提醒"}'
curl ... -d '{"scenes":{"watchlist":{"limit":8}}}'     # 临时点一档内容，不建内容档也能发
```

- `to` 不给就用「默认收件人」那一格；两处都空 ⇒ 拒发并说清（这一条必须**指名道姓**）。
- 正文超过「正文长度上限」（出厂 1200 字）⇒ **拒发并说超了多少**，
  而不是发出去半截（客户端的静默截断不告诉你截在哪）。
- 真发送失败（预检拒发 / 中途焦点跑掉 / 注入被系统拒绝）一律 **HTTP 502 + 原因**，
  不返回 200 的"大概发了"。
- `dry_run` 在预检没过时**照样回完整序列** —— 它正是用来看"这台机器现在为什么发不出去"的。

## 六、留痕与措辞的红线

- **状态最多只到 `injected`（按完了）**，永远不是"已送达"。
  这一侧没有任何办法确认那条消息真进了那个会话（没有回执、也读不到消息列表），
  所以返回值里 `delivered` 恒为 `null`，界面上那句"要到自己的手机上看那一条"是硬写的。
- **历史 `history.jsonl` 成败都记**，但**不存正文全文**（只存长度与前 40 字）——
  正文里可能带持仓与账户信息，而这份文件会被贴进会话、进日志。
- **冷却只数真按过的那几条**（`status=injected`）：拒发、预检拦住、`dry_run` 都不占窗口。
  否则"连着试了三次没出去"会把第四次也锁死，那是自己把自己锁死。
- **剪贴板进出都保存/还原**；原内容**不是纯文本时不动它**（覆盖掉你的图片比留一段粘贴文本更坏）。
- 总开关**出厂是关着的**。打开它是一次显式动作，且留痕带来源 IP。

## 七、跑测试的那道缝（这条通道不能像普通模块那样测）

真碰桌面的口子只有两个，都照 `notify._post_json` / `jobs._spawn_stage` 的规矩在 pytest 进程里硬挡：

| 口子 | 挡法 | 绕过它的唯一姿势 |
|---|---|---|
| `duanxian.wxpush._desktop_apply()` | 进程里有 `PYTEST_CURRENT_TEST` 且"这个函数还是默认实现"⇒ 抛错 | 把**真副作用原语**（`_send_key`/`_send_text`/`_send_click`/`_clip_write`/`_window_action`）换成形状正确的假货，再把 `_APPLY_DEFAULT` 比对阵换掉 —— 这样测的是**本体那圈循环**，不是自己写的桩 |
| `duanxian.wxpush.run_script()` | 同一道判据 | 打桩 `run_script` 本身（只验接线） |

红线用例本身传的是**空序列**：万一那道闸被改坏了，也一个键都按不出去，但断言会当场红
（`test_真注入在pytest进程里必须硬挡`）。

跑这一族：

```bash
./.venv/Scripts/python.exe -m pytest tests/test_wxpush_config.py tests/test_wxpush_send.py -q
# 65 条（36 + 29）；只验这一族时约 60 秒，大头是 `import duanxian.notify`（pandas）
```

## 八、边界与还没做的

**这一条通道故意不做的事**：

- 不接收盘链、不接 `notify-push` 那条常驻循环 ⇒ **没有定时自动发微信**。
  理由就是 §一的第 2 条：没人连着桌面时它必然失败，而"到点了却静默失败"是最坏的那种失败。
  要无人值守推送请用 [14](14-消息推送渠道与定时计划.md) 那四个渠道；
  或者把这条通道的手动入口接到你自己的外部触发器上（`POST /api/wxpush/send`）。
- 不做收消息、不做会话监听（那需要能读控件树或有 hook，都不在本程范围内）。
- 不写凭据：这条通道没有 token/URL 要保护，但**默认收件人必须回显** ——
  否则「编辑」一开就是空的，用户改别的字段会把它清掉。

**还没做、但已经知道要做什么的**：

1. 用户坐回桌面前，`.local/probe/wx_probe3.py` 再跑一次，把 §一第 1 条那个分支区分开
   （客户端封死 vs 无桌面连带）。若控件树其实读得到，第 6、7 步就可以改成按控件定位，
   坐标那两格就能退役。
2. **真发一条还没验过**。目前全部证据是：预检在无桌面时正确拒发、`dry_run` 展开出完整 31 步、
   `scene` 档正文真取到 205 字。**没有一次真把消息按进微信**。
   验收方式：连着远程桌面 → 面板「先看一遍」→「真发这一条」发给「文件传输助手」→ 手机上看那一条。
3. 「唤起/收起」那两个快捷键出厂写 `Alt+1`，这是**猜的默认**：要用户真的在微信自己的设置里
   把「打开主窗口」设成同一个键，或者改用「直接唤窗」那一档（不依赖微信的设置）。
