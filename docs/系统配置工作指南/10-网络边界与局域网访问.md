# 06 · 网络边界：绑定地址与局域网白名单

> 管一件事：**这台机器上跑的网页，谁能连进来。**
> 数据对不对、作业跑没跑不在这里（那在 [05](05-调度宿主.md) 与各业务指南）。

## 一、现状（2026-09-28 起）

| 项 | 值 |
|---|---|
| 默认 | **只绑回环** `127.0.0.1:8910`，局域网连不上 |
| 开放方式 | 系统配置页勾「允许局域网内的其他机器访问本机」→ 服务改绑 `0.0.0.0:8910` |
| 谁能访问 | 回环永久放行；局域网来源**必须逐条命中白名单**（IPv4，不支持网段/CIDR） |
| 当前白名单 | `192.168.186.7`（用户 2026-09-28 指定） |
| 配置在哪 | `<ASTOCK_DATA_HOME>\net\config.json`（本机实测 `C:\Users\Administrator\.duanxian-agents\net\config.json`） |
| 唯一读法 | `netconfig.py`（**只用标准库**，`manage.py` 在依赖装好之前就要能读它） |

## 二、为什么这三条是硬规矩

1. **绑定地址在启动那一刻定死，运行中改不了。**
   勾完开关必须重启才换绑；所以页面上同时写「配置要求的绑定」和「进程实际绑定」两个值，
   不一致就明说「已保存，要重启才生效」。只报一个数会让人以为已经通了（或已经关了）。
2. **加白 / 删白是立刻生效的**（每个请求现读一次配置），**不重启**。
   两种生效时机不一样 —— 都写成"重启后生效"，用户就会为一件不需要重启的事去重启。
3. **改这道闸只能在主机上做**（`/api/net` 的写操作只认回环）。
   已经放行的那台机器如果能自己加白，白名单形同没有：客人给自己开门、再把门开给任何人。

## 三、请求要过两道独立的闸

| 顺序 | 闸 | 判据 | 拦下时说 |
|---|---|---|---|
| 先 | 来源 IP（`server.py::_origin_ip_guard`） | `request.client.host` | 「未授权：本机未对该来源地址开放」+ **把对方的地址回显给它** |
| 后 | Host/Origin（`_vr_guard`） | `_ALLOWED_HOSTS` ∪ 本机网卡地址 | 「非法 Host」 |

三条要点：

- **IP 闸覆盖所有路径，静态页面也不例外** —— 白名单外的机器连首页 HTML 都拿不到，不是"页面能看到但接口 403"。
- **只认内核给的对端地址，不看 `X-Forwarded-For`**。那串是客户端自己写的，信它等于把白名单交给对面伪造；本机没有任何反向代理，所以不需要那套信任链。
- **Host 校验必须动态认"本机自己的地址"**：对面敲的是 `http://<本机局域网 IP>:8910`，Host 就是那个 IP。写死在 import 期的集合里，会出现"局域网配置开着、这道无关的校验还拦着"——**拦人的是一道与白名单无关的检查，这是最难查的一种**。这不放松 DNS 重绑定防护（重绑定时 Host 是攻击者域名，两处都不认）。

被挡的来源会留最近 20 条 + 累计次数（`/api/net` 的 `recent` / `total`）。留着它是因为白名单最难查的从来不是"加错了"，而是**"对面到底以哪个 IP 进来"**：跨网段经过一层 NAT 时，本机看到的可能不是你以为的那个地址（本机实测：白名单 `192.168.186.7` 与本机 `192.168.176.68/24`、`2.0.1.6/24` 都不同网段，路由要经 `2.0.1.4`）。

## 四、这台机器的现实：白名单是唯一那道门

**本产品没有登录口令**（`.env` 里没有 `VR_API_KEY`，全代码只有可选的 `authHeaders`）。
所以：

- 加进白名单的机器 = 能看本机全部数据（行情、自选、研究记录、日志类端点），**并能点「立即触发」跑采集与加工**。
- 想挂到域名/公网，必须先给 `VR_API_KEY` 赋值并用 `VIBE_ALLOW_HOSTS` 放行域名 —— 两个都不设就是裸开放。
- `0.0.0.0` 永远进不了白名单（它是绑定地址，写进去等于全开，`validate_ip` 直接拒）。同理拒绝 `127.x`（本来就永久放行）、`255.255.255.255`、IPv6、CIDR。

## 五、开关与操作

| 要做什么 | 怎么做 |
|---|---|
| 图形界面 | 系统配置页 `/system` →「局域网访问」卡：勾选 + 白名单增删 + 现状/被挡记录 |
| 命令行读 | `curl --noproxy '*' -s http://127.0.0.1:8910/api/net` |
| 加白 / 删白 / 开关 | `curl --noproxy '*' -X POST -H 'Content-Type: application/json' -d '{"add":"192.168.186.7"}' http://127.0.0.1:8910/api/net`（把 `add` 换成 `remove` / `lan_enabled` 即对应操作；**一次只改一件事**，多件一起提交会被拒） |
| 换绑定 | 改完开关后重启：`关闭 YuanShan.cmd` → 双击 `启动 YuanShan.cmd` |
| 直接改文件 | 手写 `<ASTOCK_DATA_HOME>\net\config.json`（服务下一个请求就认，但**换绑定仍要重启**） |

启动器（`scripts/manage.py start`）按配置决定 `--host`，并在启动成功那行**照实报**当前绑定与白名单：

```
局域网访问：已开放，绑定 0.0.0.0:8910；白名单 1 台：192.168.186.7
  对面可用：http://192.168.176.68:8910 …
  ⚠ 白名单外的机器一律 403（连页面都拿不到）。对面连不上先查 Windows 防火墙是否放行 8910。
```

`python server.py` 那条路走同一份配置（`netconfig.bind_host()`）—— 只有启动器认配置、另一条路写死回环，就会出现"页面上开着、换个起法其实没开"。

## 六、对面连不上时按这个顺序查

1. **本机能开 `http://127.0.0.1:8910` 吗？** 不能就是服务没起，与局域网无关。
2. **`/api/net` 里 `running_host` 是 `0.0.0.0` 吗？** 是 `127.0.0.1` 就是**勾了没重启**。
3. **对面自己的地址在 `/api/net` 的 `recent` 里出现过吗？** 出现过 → 说明已经连到本机、是白名单没对上（NAT 场景就在这一步现形）；从没出现 → 包没到本机，看第 4 步。
4. **Windows 防火墙**：本机现在 Private/Public profile 是关的，所以不是它拦；但 profile 一旦被启用，`8910` 没有放行规则就会拦（`Get-NetFirewallPortFilter | Where LocalPort -eq 8910` 现在是 0 条规则）。加规则属于系统级改动，要人点头再做。
5. 对面用的是**哪个本机地址**：本机有多个网卡（实测 `192.168.176.68`、`2.0.1.6`、Hyper-V 的 `172.24.176.1`），走错接口就到不了。

## 七、改动这条链时要跑什么

- `tests/test_net_access.py`（23 条）：配置默认关、坏文件按最保守读、非法项点名拒绝、回环永久放行、开关关着时非回环一律不放行、白名单内外各自的表现、**白名单外连静态页面都拿不到**、Host 认本机地址但不认外来域名、被挡记录、`/api/net` 的读权限与"只有回环能写"、**改完一条还能接着改**（POST 的响应字段必须与 GET 一模一样，否则页面上的编辑控件会在改完一次后集体消失 —— 这条是浏览器里实测出来的）。
- 动了中间件就要重启服务；只看代码改了没生效，用 `/api/net` 与 `/api/jobs` 的 `host_loops` 判，别看日志尾部（无 tty 时 stdout 是块缓冲，见 [05](05-调度宿主.md) §六）。
