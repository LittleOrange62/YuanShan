## 二进制格式规格

这是全系统唯一的解析真相来源，实现在 `app/ingest/tdx_binary.py`，并用固定字节样本做单元测试。

### `.day` — 日线，32 字节定长

```python
struct.unpack('<IIIIIfII', chunk)
#             ↓ 依次
# [0] date       uint32   20260825（十进制即年月日）
# [1] open       uint32   单位：分   → ÷100 得元
# [2] high       uint32   分        → ÷100
# [3] low        uint32   分        → ÷100
# [4] close      uint32   分        → ÷100
# [5] amount     float32  单位：元   ← 注意是 float32，且已经是元
# [6] vol        uint32   单位：股   → ÷100 得手
# [7] reserved   uint32
```

**两个历史踩坑点**

1. `amount` 是 **float32 且单位为元**。旧 schema 文档声明"千元"，而代码按元写入 —— 1000× 偏差。新系统字段名直接叫 `amount_yuan`，杜绝歧义。
2. `vol` 是 **股**。旧文档声明"手"，代码按股写 —— 100× 偏差。新字段名 `volume_shares`。

### `.lc1` / `.lc5` — 分钟线，32 字节定长

```python
struct.iter_unpack('<IfffffII', data)
# [0] packed  uint32   高16位 = 当日分钟数(minute of day)，低16位 = 日期序号
# [1] open    float32  单位：元（已经是元，不需要 ÷100）
# [2] high    float32  元
# [3] low     float32  元
# [4] close   float32  元
# [5] amount  float32  元
# [6] vol     uint32   股
# [7] reserved uint32
```

日期序号的解码：旧实现用 `LO_BASE=45881` 对齐 `DATE_BASE=date(2026,8,25)`，并预生成 `lo ∈ [45000,46500)` 的查找表 —— 这是魔法常量，只覆盖到约 2027-08 就会失效。

**新做法**：日期序号是从 1900-01-01 起算的天数偏移（Excel 序列日期同源）。直接算：

```python
EPOCH = date(1899, 12, 30)   # 用固定样本文件标定一次并写入测试
def decode_lo(lo: int) -> date:
    return EPOCH + timedelta(days=lo)

def decode_packed(packed: int) -> tuple[date, int]:
    minute = packed >> 16          # 分钟数，如 9*60+31 = 571
    lo     = packed & 0xFFFF
    return decode_lo(lo), minute
```

标定用 `sh000001.lc1` 最后一条与已知交易日核对，写成断言测试。任何时候锚点错了，测试会立刻失败，而不是等到 2027 年数据静默错位。

### `.tnf` — 股票名称

50 字节文件头 + 360 字节定长记录：

```
offset 0   : 6 字节 ASCII 代码，如 '600367'
offset 31  : GBK 编码名称，读到 \x00 截断
```

拼音索引用 `pypinyin.lazy_pinyin` 生成全拼与首字母，写入 `reference_data.security.pinyin` / `pinyin_abbr`。这套逻辑从 `financeWeb/core/stock_lookup.py` 直接搬，是验证过的。

## tqcenter 接入

端口 17709，JSON-RPC，DLL 在 `D:\new_tdx64\PYPlugins\TPythClient.dll`，**要求 TdxW.exe 在运行**。

| 接口 | 用途 |
|---|---|
| `get_stock_list` | 全量代码表 |
| `get_market_snapshot` | 60+ 字段：PE/PB/总市值/流通市值/EPS/ROE |
| `get_more_info` | 扩展信息 |
| `get_divid_factors` | 分红送配 → 算复权因子 |
| `get_gb_info_by_date` | 股本变动 → 算换手率、流通市值 |
| `get_trading_dates` | 交易日历 → 灌 `reference_data.trade_calendar` |
| `get_ipo_info` | 新股申购 |
| `get_sector_list` / `get_stock_list_in_sector` | 板块与成分股 |

市场代码：`5`=全部A股、`50`=沪深A、`51`=创业板、`52`=科创板、`53`=北交所。这四个板块码正好用来填 `reference_data.security.board`，从而算对涨跌停。

批量调用间隔 20 ms 避免限流（沿用旧文档结论）。

**探活与降级**：同步前先 `socket.connect(('127.0.0.1', 17709), timeout=2)`。连不上则跳过 tqcenter 环节，只做 vipdoc 部分，并在任务结果里标注"参考数据未更新"。绝不像旧 `run_tdx_flow` 那样 `sleep 60` → 轮询 60 次 × 5s → 再 `sleep 30`，最坏 6.5 分钟空等。

## 复权因子

现状 `adjustment_factor` 硬编码 1.0，等于全部数据未复权，所有跨除权日的技术指标都是错的。

正确做法：用 `get_divid_factors` 拿分红送配记录，从最新交易日往前累乘：

```
后复权因子(t) = ∏ [ (前收 + 每股现金红利) / 前收 × (1 + 送股比 + 配股比) ]
```

存在 `market_data.stock_daily.adjustment_factor`，前端按需选择"不复权 / 前复权 / 后复权"。复权计算在查询层做（`repo/quote.py` 提供 `adjust=` 参数），不污染原始数据。

## 同步流程

```
                    ┌─ 交易日判定（reference_data.trade_calendar，非 weekday<5）
                    │
                    ├─ 探活 tqcenter（2s 超时，失败则降级）
                    │
   触发 ────────────┤
                    ├─ 阶段 A: 参考数据
                    │    get_trading_dates → reference_data.trade_calendar
                    │    get_stock_list + .tnf → reference_data.security（含 board/拼音）
                    │    get_gb_info_by_date → reference_data.share_capital
                    │    get_divid_factors  → reference_data.dividend → 算 adjustment_factor
                    │
                    ├─ 阶段 B: 日线
                    │    扫描 {sh,sz,bj}/lday/*.day
                    │    只处理 mtime > 上次批次时间的文件（增量）
                    │    解析 → 契约校验（块4）→ COPY 到临时表 → upsert 主表
                    │    登记 operations.ingest_batch
                    │
                    ├─ 阶段 C: 快照（PE/PB/市值）
                    │    get_market_snapshot 批量，20ms 间隔
                    │
                    ├─ 阶段 D: 分钟线（可选，量大）
                    │    .lc1 / .lc5，按月分区写入
                    │
                    └─ 阶段 E: 就绪标记
                         写 operations.data_ready(trade_date, dataset, row_count)
                         → 触发块2 的加工任务
```

## 增量与幂等

**增量判据**：文件 `mtime` 对比 `operations.ingest_batch.source_mtime`。vipdoc 每日整体刷新，未变的文件直接跳过。首次全量约 116,428 个文件，之后每日只有当日活跃标的的文件被改写。

**幂等**：

```sql
INSERT INTO market_data.stock_daily (security_code, trade_date, ...)
VALUES (...)
ON CONFLICT (security_code, trade_date) DO UPDATE SET
    open = EXCLUDED.open, ..., source_batch_id = EXCLUDED.source_batch_id,
    updated_at = now();
```

同一天重跑任意次结果一致。旧系统第 2 代 ETL 用"逐行 DELETE + INSERT"，慢且在并发下会短暂丢数据。

**批量写入**：解析结果先 `COPY` 进 `UNLOGGED` 临时表，再一条 SQL 合并到主表。比逐行 `executemany` 快一个数量级。

## 代码归属判定

三套现存实现用了三种不同办法（路径判断 / 文件名切片 / 代码前缀），结果不一致，这是 1.8% 行数分歧的来源之一。

新系统**单一判据**：以文件所在市场目录为准（`sh`/`sz`/`bj`），代码前缀只用于判定 `asset_type` 与 `board`：

```python
A_SHARE_PREFIX = {
    'SH': ('600', '601', '603', '605', '688', '689'),
    'SZ': ('000', '001', '002', '003', '300', '301'),
    'BJ': ('43', '83', '87', '92'),
}
INDEX_PREFIX  = {'SH': ('000',), 'SZ': ('399',)}
SECTOR_PREFIX = ('880', '881')     # 通达信板块伪代码，写 market_data.sector_daily 而非 stock_daily
ETF_PREFIX    = {'SH': ('510','511','512','513','515','518','588'),
                 'SZ': ('159',)}
```

`880*` / `881*` 是通达信自定义板块指数，**不是股票**。旧系统一度把它们写进 `stock_daily` 又写脚本删掉（`clean_880.py`）。新系统在解析阶段就分流。

## 数据就绪判定

同步完成不等于数据可用。写 `operations.data_ready` 前必须满足：

| 检查 | 阈值 |
|---|---|
| 当日 A 股日线行数 | ≥ 4,800（当前沪+深+北约 9,482 个标的，容忍停牌） |
| 最新交易日 = 预期交易日 | `reference_data.trade_calendar` 比对 |
| 沪深指数当日存在 | `000001.SH` 与 `399001.SZ` 均有行 |
| 空值率 | `close IS NULL` 比例 < 0.1% |
| 量级抽检 | `amount_yuan` 中位数在 [1e6, 1e10] 区间 |

旧系统 `_check_local_data_for_date` 只查"当日 ≥1000 行"，太松。

阈值不硬编码，存 `config.readiness_rule` 表，可调。

## 时间口径

- 交易日切换以 **15:00** 为界（沿用旧 `get_latest_trade_date` 的合理部分），但必须叠加 `reference_data.trade_calendar` 的 `is_open`
- 分钟线时间戳存 `timestamptz`，时区固定 `Asia/Shanghai`
- 所有日期字段用 PG `date` 类型，不存 `text`。旧系统用 `'20260825'` 字符串并靠 `td[:4]` 切年份，既慢又易错
