# 多智能体直连 PostgreSQL 规范

## 决策：不做 MCP/HTTP 封装层

原方案设计了 MCP 工具集作为智能体的唯一数据入口。**该方案已废弃**，理由成立：

- 锁冲突是当初封装的主要动机，PostgreSQL 的 MVCC 已从根上解决
- 所有智能体与数据库在同一台机器，多一层 HTTP + JSON 序列化是纯开销
- 多一个进程就多一个要守护、要排错、要版本对齐的环节（旧系统 MCP 8765 / Worker 8766 无守护的教训）
- 智能体写 SQL 比调工具更灵活，limit 更少

改为**直连 + 共享库**：

```
  ceo        data_from      coder         tq        FinanceTool 主程序
   │            │            │            │              │
   └────────────┴────────┬───┴────────────┴──────────────┘
                         │  psycopg (本机 127.0.0.1:5432)
                         ▼
              ┌────────────────────────┐
              │   PostgreSQL 17        │
              │   D:\finance\TataPG    │
              │  · 角色权限            │
              │  · CHECK 约束          │
              │  · 触发器审计          │
              │  · 视图 / 物化视图     │
              └────────────────────────┘
```

## 但有个前提必须补上

去掉封装层，就等于**放弃了在应用层做统一校验和审计的机会**。原本靠 MCP 工具拦住的三件事——单位口径校验、写操作审计、权限控制——必须下沉到数据库自己去做，否则就是回到"199 个脚本各写各的"的老路。

所以约束不是消失了，是换了实现位置：

| 原本靠 MCP 层做 | 现在靠什么做 |
|---|---|
| 单位/量级校验 | PG `CHECK` 约束 + `BEFORE INSERT` 触发器 |
| 写操作审计 | `AFTER INSERT/UPDATE/DELETE` 触发器写 `operations.audit` |
| 只读隔离 | PG 角色权限（`ft_reader` 只有 SELECT） |
| 强制 LIMIT / 超时 | 角色级 `statement_timeout` + `idle_in_transaction_session_timeout` |
| 参数化查询 | 共享库 `ftdb` 提供函数，不鼓励手写拼串 |
| 字段口径说明 | `COMMENT ON COLUMN` + `operations.view_field_dict` 视图 |

数据库层的约束比应用层更强：**绕不过去**。应用层校验可以被下一个脚本忽略，`CHECK` 约束不行。

## 角色与账号

| 角色 | 权限 | 给谁 |
|---|---|---|
| `postgres` | 超级用户 | 只做运维，日常不用 |
| `ft_admin` | 库 owner，可 DDL | 迁移、建表 |
| `ft_app` | 全部业务 schema 读写，无 DDL | FinanceTool 主程序 |
| `ft_etl` | `md` / `ref` 写，其余只读 | 同步任务、批量导入 |
| `ft_reader` | 全库只读 | 智能体默认账号、分析脚本、查询台 |

分配建议：

- `ceo`（分析型，引用大量只读查询）→ `ft_reader`
- `data_from`（导入两融数据）→ `ft_etl`
- `coder` → `ft_reader`
- `tq` → `ft_reader`

需要写权限时单独申请，不要一律发 `ft_app`。给只读账号是最省心的默认值：**误删的可能性从源头消失**。

## 写入约定

只读随便查。**写入必须遵守三条**，因为库里有约束，违反会被直接拒绝：

**1. 用 upsert，不用 DELETE+INSERT**

```sql
INSERT INTO market_data.stock_daily (security_code, trade_date, open, high, low, close, volume_shares, amount_yuan, source_batch_id)
VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s)
ON CONFLICT (security_code, trade_date) DO UPDATE SET
    open = EXCLUDED.open, high = EXCLUDED.high, low = EXCLUDED.low,
    close = EXCLUDED.close, volume_shares = EXCLUDED.volume_shares,
    amount_yuan = EXCLUDED.amount_yuan, source_batch_id = EXCLUDED.source_batch_id,
    updated_at = now();
```

**2. 先登记批次，再写数据**

```python
with ftdb.conn(role='etl') as c:
    batch = ftdb.begin_batch(c, source='data_from/margin', target='market_data.margin_daily')
    ...  # 写入，每行带 source_batch_id=batch
    ftdb.end_batch(c, batch, row_count=n, status='ok')
```

没有 `source_batch_id` 的行写不进去（列上有 `NOT NULL`）。这样任何一行数据都能回答"谁、什么时候、从哪写进来的"。

**3. 单位按字段名，不做换算**

字段名自带单位：`amount_yuan`（元）、`volume_shares`（股）、`turnover_rate_percent`（百分数）。看到 `_yuan` 就直接写元，不要 `* 10000`。旧 `sync_vipdoc_to_db.py:127` 的 `amount * 10000.0` 就是这么错的。

## 数据库层的防护实现

### CHECK 约束

```sql
ALTER TABLE market_data.stock_daily
  ADD CONSTRAINT ck_daily_ohlc CHECK (
      low IS NULL OR high IS NULL OR (low <= high
      AND (open  IS NULL OR (open  BETWEEN low AND high))
      AND (close IS NULL OR (close BETWEEN low AND high)))),
  ADD CONSTRAINT ck_daily_price_positive CHECK (
      (open IS NULL OR open > 0) AND (close IS NULL OR close > 0)),
  ADD CONSTRAINT ck_daily_amount_sane CHECK (
      amount_yuan IS NULL OR amount_yuan BETWEEN 0 AND 1e13),
  ADD CONSTRAINT ck_daily_vol_sane CHECK (
      volume_shares IS NULL OR volume_shares BETWEEN 0 AND 1e13),
  ADD CONSTRAINT ck_daily_pct CHECK (
      pct_change IS NULL OR pct_change BETWEEN -100 AND 1000),
  ADD CONSTRAINT ck_daily_not_sector CHECK (
      left(security_code, 3) NOT IN ('880', '881'));
```

`ck_daily_amount_sane` 是单位错误的硬拦截：`amount` 若误按千元/万元写入，超出上限直接报错。`ck_daily_not_sector` 保证板块伪代码进不了个股表（旧系统靠事后 `clean_880.py` 删）。

### 单位一致性触发器

```sql
CREATE OR REPLACE FUNCTION market_data.trg_daily_sanity() RETURNS trigger AS $$
BEGIN
    -- 成交额 / 成交量 = 均价，必须落在当日价格区间的合理倍数内
    IF NEW.volume_shares IS NOT NULL AND NEW.volume_shares > 0
       AND NEW.amount_yuan IS NOT NULL AND NEW.low IS NOT NULL THEN
        IF (NEW.amount_yuan / NEW.volume_shares) NOT BETWEEN NEW.low * 0.5 AND NEW.high * 2.0 THEN
            RAISE EXCEPTION
              '单位口径异常 % % : amount_yuan/volume_shares=% 超出价格区间 [%,%]',
              NEW.security_code, NEW.trade_date,
              round(NEW.amount_yuan / NEW.volume_shares, 4), NEW.low, NEW.high;
        END IF;
    END IF;
    RETURN NEW;
END $$ LANGUAGE plpgsql;

CREATE TRIGGER daily_sanity BEFORE INSERT OR UPDATE ON market_data.stock_daily
    FOR EACH ROW EXECUTE FUNCTION market_data.trg_daily_sanity();
```

成交额除以成交量应等于当日均价。单位错 100 倍或 1000 倍，这个比值一定撞出价格区间。**旧系统如果有这一条，元/千元和股/手两个偏差都活不过第一次写入。**

### 写操作审计触发器

```sql
CREATE OR REPLACE FUNCTION operations.trg_audit() RETURNS trigger AS $$
BEGIN
    INSERT INTO operations.audit(actor, channel, action, target, params, ok)
    VALUES (current_user, 'direct', TG_OP, TG_TABLE_SCHEMA || '.' || TG_TABLE_NAME,
            jsonb_build_object('app', current_setting('application_name', true),
                               'pid', pg_backend_pid()), true);
    RETURN NULL;
END $$ LANGUAGE plpgsql;

CREATE TRIGGER audit_cfg_binding AFTER INSERT OR UPDATE OR DELETE ON config.binding
    FOR EACH STATEMENT EXECUTE FUNCTION operations.trg_audit();
```

挂在配置表和低频表上用 `FOR EACH STATEMENT`（不逐行，无性能负担）。行情大表不挂触发器，靠 `source_batch_id` 追溯。

建议智能体连接时设置 `application_name`，审计里就能看到是谁：

```python
psycopg.connect(dsn, application_name='ceo')
```

### 角色级超时

```sql
ALTER ROLE ft_reader SET statement_timeout = '60s';
ALTER ROLE ft_reader SET idle_in_transaction_session_timeout = '5min';
ALTER ROLE ft_etl    SET statement_timeout = '30min';
```

防止某个智能体挂着长事务把 autovacuum 拖死——这是 PG 环境里最常见的自伤方式。

### 只读保障

```sql
REVOKE ALL ON ALL TABLES IN SCHEMA md, ref, fct, config, ops FROM ft_reader;
GRANT USAGE ON SCHEMA md, ref, fct, config, ops TO ft_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA md, ref, fct, config, ops TO ft_reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA md, ref, fct, config, ops
    GRANT SELECT ON TABLES TO ft_reader;
```

`ALTER DEFAULT PRIVILEGES` 保证以后新建的表自动对只读角色可见 —— 不用每次建表补授权。

## 并发协调

MVCC 解决了读写互斥，但**同一份数据被两个写入者同时刷**仍需协调。用 PG advisory lock：

```python
with ftdb.conn(role='etl') as c, ftdb.advisory_lock(c, f'ingest:stock_daily:{trade_date}'):
    ...
```

拿不到锁就退出并记录，不要死等。对应 SQL：

```sql
SELECT pg_try_advisory_xact_lock(hashtext('ingest:stock_daily:2026-08-25'));
```

事务级锁（`_xact_`）在事务结束时自动释放，进程崩了也不会留下死锁——比自己维护锁表可靠。

## 常用查询速查

```sql
-- 某日全市场涨幅榜
SELECT d.security_code, s.name, d.close, d.pct_change, d.amount_yuan/1e8 AS 成交额亿
FROM market_data.stock_daily d JOIN reference_data.security s USING (security_code)
WHERE d.trade_date = '2026-08-25' AND s.asset_type = 'stock'
ORDER BY d.pct_change DESC LIMIT 50;

-- 最近 20 个交易日
SELECT calendar_date FROM reference_data.trade_calendar
WHERE is_open AND calendar_date <= current_date ORDER BY calendar_date DESC LIMIT 20;

-- 跨年查询（分区表，无需 ATTACH）
SELECT trade_date, close FROM market_data.stock_daily
WHERE security_code = '600367.SH' AND trade_date BETWEEN '2021-01-01' AND '2026-08-25'
ORDER BY trade_date;

-- 评分拆解
SELECT * FROM analytics.view_score_detail
WHERE trade_date = '2026-08-25' AND security_code = '600367.SH';

-- 字段口径字典
SELECT * FROM operations.view_field_dict WHERE column_name LIKE '%amount%';

-- 数据血缘
SELECT b.* FROM operations.ingest_batch b
WHERE b.batch_id = (SELECT source_batch_id FROM market_data.stock_daily
                    WHERE security_code='600367.SH' AND trade_date='2026-08-25');

-- 谁改了配置
SELECT occurred_at, actor, action, target FROM operations.audit
WHERE target LIKE 'config.%' ORDER BY occurred_at DESC LIMIT 50;
```
