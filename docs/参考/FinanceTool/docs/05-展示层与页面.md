## 核心页面 · /review 每日复盘

单页三层下钻，这是整个系统的产品重心。

```
┌─────────────────────────────────────────────────────────────┐
│ 交易日 [2026-08-25 ▾]  [◀ 上一交易日] [下一交易日 ▶]  [导出] │
├─────────────────────────────────────────────────────────────┤
│ 第一层 · 大盘                                                │
│  ┌────────┬────────┬────────┬────────┬────────┬────────┐   │
│  │大盘温度│上涨家数│涨停家数│成交额  │情绪评分│北向资金│   │
│  │  68    │2,847   │  43    │1.12万亿│  +12   │  --    │   │
│  └────────┴────────┴────────┴────────┴────────┴────────┘   │
│  涨跌幅分布直方图 │ 指数走势（沪深创科北）│ 情绪 20 日时序  │
├─────────────────────────────────────────────────────────────┤
│ 第二层 · 板块（点击行 → 下钻第三层）                          │
│  板块热度榜 TOP20：名称 热度 涨幅 广度 动量 成交额 领涨股     │
│  板块轮动热力图（近 10 交易日 × 板块）                        │
├─────────────────────────────────────────────────────────────┤
│ 第三层 · 个股                                                │
│  四象限散点图（X=个股质量 Y=环境共振，四色分区）              │
│  Q1 买入 / Q2 持有 / Q3 试探 / Q4 回避 —— 点击象限筛选下表    │
│  个股表：代码 名称 板块 涨幅 换手 X Y Oper 温度 位置 量比     │
│  行点击 → 抽屉展开 K 线 + 评分拆解                            │
└─────────────────────────────────────────────────────────────┘
```

**评分拆解抽屉**是修正旧系统"评分是黑盒"的关键。展示：

```
Oper 62.4 = 0.40 × X(48.2) + 0.60 × Y(71.9)
                  │                    │
   X 48.2 = 形态 0.25×60 + 趋势 0.25×45 + 位置 0.20×38
            + 筹码 0.20×55 + 量能 0.10×20
                                       │
   Y 71.9 = 板块热度 0.65×78.5 + 大盘情绪 0.35×59.6
```

每一项显示：子分值、权重（来自 `config.binding`）、贡献值、以及产生它的脚本名与版本。这样一旦某个分项异常（比如板块热度恒为 0——旧系统的真实故障），肉眼就能发现。

## 图表规范

统一用 Plotly。

| 图形 | 用途 | 注意 |
|---|---|---|
| K 线（Candlestick）+ 成交量副图 | `/stock` | 支持不复权/前复权/后复权切换 |
| 折线 | 指数、情绪、热度时序 | 双轴慎用，优先分面 |
| 直方图 | 涨跌幅分布 | 固定分箱边界（±10%、±20% 台阶），跨日可比 |
| 散点 | 四象限 | 点大小=流通市值，颜色=象限，hover 显示评分明细 |
| 热力图 | 板块×日期轮动、数据覆盖度 | 色阶固定，不用自适应色阶（否则跨日不可比） |
| 柱状 | 板块排行 | 横向柱，长标签不截断 |

**统一约定**

- 涨=红、跌=绿（A 股习惯，与国际相反，明确固定）
- 所有金额显示带单位后缀（亿元/万元），底层数据永远是元
- 图表标题必须含交易日期，导出的图能独立说明自己
- 空数据显示明确空状态（"2026-08-25 无数据，可能非交易日或未同步"），不是空白图

## Dash 工程约定

沿用 financeWeb 已验证的几条原则，它们是被踩坑换来的：

1. **所有被回调引用的组件必须在初始 layout 中存在**。登录页与主体通过 `style.display` 切换，不是条件渲染。否则回调找不到组件而报错。
2. **每个 Output 只能有唯一 callback**。Dash 的硬约束。
3. **页面模块只暴露 `layout()` 与 `register_callbacks(app)`**，由 `web/app.py` 统一注册。
4. **共享组件集中在 `web/ui.py`**：`page_title`、`panel_card`、`make_data_table`、`stat_card`、`task_status_badge`、`error_alert`、`empty_state`。旧系统这套组件划分是合理的，直接沿用。
5. **表格列宽按内容算，不写固定值**（2026-08-30）。`fixed_rows={'headers': True}` 会把抬头和表体拆成两个 `<table>`，让它们各自自适应宽度就会**错位**，所以宽度必须写死；但"写死"不等于"全站一个 120px" —— `ui.col_widths()` 在 Python 侧按表头文字与该列最长单元格算出宽度（等宽字体：ASCII ≈7.3px、中日韩全角 ≈13.2px，加排序箭头与内边距），夹在 54~300px 之间输出 `style_cell_conditional`。Markdown 链接列按**显示出来的标签**算，不按 `[600519.SH](https://…)` 整串算。实测 `q_watchlist` 15 列从 1,800px 压到 1,317px、`q_score_rank` 12 列从 1,440px 压到 1,013px。

**必须避开的旧坑**

- `web/helpers.py:86` 用了 `dbc.Alert` 但没 import `dash_bootstrap_components` → 必然 NameError。新代码的 CI 里加 `ruff` + `pyflakes`，未定义名字直接构建失败。
- `Interval` 自动刷新覆盖用户输入：旧仪表盘的定时刷新会把用户改过的表单值刷回去。新规则是 Interval 只更新**展示型** Output，永不写回输入组件；用户有未提交编辑时暂停刷新。
- 表格行内按钮忽略行索引：旧 `/software` 页面点任意行的按钮都作用于第一行。新代码统一用 pattern-matching callback（`{'type': 'row-btn', 'index': i}`），并从 `ctx.triggered_id['index']` 取索引。
- 硬编码分页/数量：旧 `submit_sync_until_latest(3)` 把天数写死。所有这类参数走表单或配置。
- 前端不拼 SQL：旧 `web/api_client.py` 多处 f-string 拼 SQL、`helpers.esc` 自述"临时方案"。新前端只调 REST，参数化由 repo 层负责。

## 前端取数

页面 → REST（`/api/v1/*`）→ repo → PG。前端不直连数据库，不写 SQL。

```
GET /api/v1/review/summary?trade_date=2026-08-25
GET /api/v1/review/sectors?trade_date=...&limit=20
GET /api/v1/review/stocks?trade_date=...&quadrant=Q1&sector=...
GET /api/v1/stock/{security_code}/kline?start=...&end=...&adjust=hfq
GET /api/v1/stock/{security_code}/score?trade_date=...   → 含拆解明细
GET /api/v1/screen?preset_id=... | POST /api/v1/screen {conditions:[...]}
GET /api/v1/watchlist/groups | /api/v1/watchlist/{group_id}/enhanced
GET /api/v1/data/ready?start=...&end=...
GET /api/v1/task?state=running
```

**性能约定**

- 复盘页首屏聚合数据走 PG 物化视图（`analytics.mv_review_summary`），同步后刷新
- 分钟线不直接吐给前端，按需降采样后返回
- 大结果集分页，默认 100 行，最大 1000
- 前端 `dcc.Store` 缓存当日数据，切 Tab 不重复请求

## 筛选器 /screen

保留旧 `/watchlist_filter` 已验证的五类条件，语义写清楚：

| 条件类型 | 语义 |
|---|---|
| 数值区间 | 字段 ∈ [min, max]，如 `pct_change ∈ [3, 8]` |
| 排名 | 字段在指定范围内的 TOP N / BOTTOM N |
| 比较 | 字段 A 与字段 B 比较，如 `close > ma20` |
| 连续 | 条件连续满足 N 个交易日，如 `pct_change > 0` 连续 3 日 |
| 归属 | 属于某板块 / 某自选分组 / 某象限 |

条件可存为预设（`config.screen_preset`），可分享，可被 `config.job` 引用做定时筛选并推送。

## 软件管理去哪了

旧 `/software` 页面管理通达信客户端的启动/登录/关弹窗/最小化。这块从主程序移出，理由：

- 4 个功能已被 early-return 禁用（`check_timers`、`minimize_main`、`minimize_all_visible`、`ensure_running_minimized`），但 UI 仍显示永不触发的倒计时 —— **界面在说谎**
- 用窗口高度比例硬编码点击坐标（账号 40%、登录按钮 65%）做自动登录，本质脆弱
- 明文口令硬编码在 3 个 `.ps1` 里
- UI 自动化与数据系统是两个关注点，耦合在一起导致主程序需要 pyautogui/win32gui 依赖

新安排：这套脚本归入 `scripts/tdx_client/`，由 Windows 计划任务独立调度，口令从凭据管理器读取。主程序只在 `/data` 页面显示"vipdoc 最后刷新时间"和"tqcenter 是否在线"两个探测结果，不负责去操作客户端。

## /sql 查询台的安全改造

旧 `/sqlite` 页面实质上是"受限的任意文件读"，且后端 `/api/sql/execute` 只黑名单 `select`/`with` 开头的语句，`ATTACH DATABASE '任意路径' AS x` 可完全绕过库白名单、目录限制和只读限制。

新实现：

- 用 `sqlglot` 解析 SQL 生成 AST，只允许单条 `SELECT`（含 CTE），任何 DDL/DML/`COPY`/`ATTACH`/函数调用白名单外的一律拒绝 —— **语法树判断，不是字符串前缀判断**
- 连接用 `ft_reader` 角色（PG 层面只有 SELECT 权限），即便解析被绕过也无法写
- 强制注入 `LIMIT`，`statement_timeout = 30s`
- 每次查询记 `operations.audit`
- 认证默认开启

## 可观测性

`/data` 与 `/quality` 页面提供：

- **数据覆盖度热力图** — 横轴交易日、纵轴数据集，颜色=行数相对均值的偏离度，缺口一眼可见
- **就绪看板** — 各数据集最新就绪日期与预期交易日的差距
- **血缘查询** — 输入 `security_code` + `trade_date`，反查 `operations.ingest_batch`，回答"这行数据从哪个文件、哪一批来的"
- **任务时间线** — 甘特形式展示当日各任务起止与依赖，定位"为什么评分还没出来"
- **日志检索** — 按 level/模块/时间过滤。日志按日轮转保留 30 天，不再出现 213 MB 单文件（旧 `web_stderr.log` 113 MB、`crash.log` 29 MB，且 `core/logger.py` 在 `__init__` 里开一次文件跨天不切）
