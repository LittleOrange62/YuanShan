# 积木城堡 · 全面可配置化设计

## 一句话原则

**凡是"以后可能要改"的东西，都存在表里，页面上能点。代码只提供积木块，不决定城堡长什么样。**

判断标准很简单：如果一个改动需要改 Python 文件、重启服务，那它就设计错了。

## 反面教材（来自旧系统）

| 想改的东西 | 旧系统要做什么 | 新系统 |
|---|---|---|
| 因子权重从 0.25 改成 0.30 | 改 `factor_engine.py:148`，重启 | `/blocks/因子` 页面输入框改一下 |
| 加一个新评分脚本 | 改代码注册，改前端表单 | 放进目录 → 页面点"扫描" → 填参数 |
| 首页多一张板块图 | 改 `dashboard.py`，加 callback | 页面拖一个卡片进去 |
| 筛选条件加一种 | 改 `watchlist_filter.py` 后端 | 注册表加一行 |
| 同步时间从 16:15 改 16:30 | 改 `scheduler.py` 默认值 | 作业配置改 cron |
| 加一个自定义指标 | 改 `constants.py` + 加计算代码 | 页面上写表达式 |
| 换一个推送渠道 | 改 `ceo/push` 脚本 | 通道注册表加一行 |

### ① config.data_source · 数据源

新增一个数据来源不用改代码。

```sql
CREATE TABLE config.data_source (
    source_key  text PRIMARY KEY,        -- 'vipdoc_day'
    name        text NOT NULL,           -- '通达信日线文件'
    kind        text NOT NULL,           -- file_binary | file_csv | http_json | jsonrpc | db
    locator     text NOT NULL,           -- 路径模板/URL，支持 {market} {code} 占位
    parser_key  text,                    -- 解析器标识 -> app/ingest/parsers 注册
    options     jsonb NOT NULL DEFAULT '{}',
    enabled     boolean NOT NULL DEFAULT true,
    priority    int NOT NULL DEFAULT 100,-- 多源冲突时谁优先
    health_check jsonb,                  -- {"kind":"tcp","host":"127.0.0.1","port":17709}
    note        text
);
```

页面能做：改 vipdoc 路径（通达信换目录不用改代码）、启停某个源、调整多源优先级、配探活方式。

内置源：`vipdoc_day`、`vipdoc_lc1`、`vipdoc_lc5`、`tdx_tnf`、`tqcenter_snapshot`、`tqcenter_divid`、`tqcenter_gb`、`tqcenter_calendar`、`tqcenter_sector`。

解析器（`parser_key`）是代码提供的积木，不可在页面新建——二进制解析必须有测试保证。但**同一个解析器可以被多个源复用**，这就够灵活了。

### ② config.field_spec · 字段口径

块 4 的核心表，同时是"页面能查字段含义"的数据来源。

```sql
CREATE TABLE config.field_spec (
    id          bigserial PRIMARY KEY,
    table_name  text NOT NULL,           -- 'market_data.stock_daily'
    column_name text NOT NULL,
    label_cn    text NOT NULL,           -- '成交额'
    unit        text NOT NULL,           -- yuan|shares|pct|ratio|count|none
    dtype       text NOT NULL,
    value_range jsonb,                   -- 硬性值域，越界=error
    sane_range  jsonb,                   -- 合理量级，越界=warning
    formula     text,                    -- 计算口径，人类可读
    source_key  text REFERENCES config.data_source(source_key),
    display     jsonb NOT NULL DEFAULT '{}', -- {"decimals":2,"scale":1e8,"suffix":"亿"}
    UNIQUE (table_name, column_name)
);
```

`display` 让前端展示格式也可配：成交额想看"亿"还是"元"、保留几位小数、要不要千分位，页面上调。

启动时与 PG 实际列双向比对，缺登记或多登记都报错。

### ④ config.quality_rule · 校验规则

```sql
CREATE TABLE config.quality_rule (
    rule_key   text PRIMARY KEY,
    name       text NOT NULL,
    scope      text NOT NULL,            -- row|table|cross_day|cross_table|score
    severity   text NOT NULL,            -- error|warning|info
    target     text NOT NULL,
    check_kind text NOT NULL,            -- sql_bool | builtin | expr
    check_body text NOT NULL,            -- SQL 布尔表达式 / 内置标识 / 表达式
    threshold  jsonb,
    blocking   boolean NOT NULL DEFAULT false,  -- true=不通过则阻断下游
    enabled    boolean NOT NULL DEFAULT true,
    description text
);
```

页面能做：新增一条 SQL 布尔规则（不写 Python）、调阈值、决定是否阻断下游、临时停用。

例：

```
rule_key   = amount_magnitude_drift
scope      = cross_day
check_kind = sql_bool
check_body = SELECT percentile_cont(0.5) WITHIN GROUP (ORDER BY amount_yuan)
             FROM market_data.stock_daily WHERE trade_date = :d
             BETWEEN :median_20d / 10 AND :median_20d * 10
severity   = error
blocking   = true
```

### ⑤ config.indicator · 指标（页面上写公式）

这是自定义空间最大的一张表。用户在页面上写表达式，系统算出新列。

```sql
CREATE TABLE config.indicator (
    indicator_key     text PRIMARY KEY,        -- 'ma20' | 'my_vol_ratio'
    name        text NOT NULL,
    kind        text NOT NULL,           -- window | expr | rank | crosssec
    expr        text NOT NULL,
    params      jsonb NOT NULL DEFAULT '{}',
    depends_on  text[] DEFAULT '{}',
    output_unit text,
    decimals    int NOT NULL DEFAULT 4,
    builtin     boolean NOT NULL DEFAULT false,  -- 内置的不可删
    enabled     boolean NOT NULL DEFAULT true
);
```

四种 `kind` 覆盖绝大多数需求：

| kind | 含义 | expr 示例 |
|---|---|---|
| `window` | 时序窗口 | `MA(close, 20)`、`STD(pct_change, 60)`、`HHV(high, 250)` |
| `expr` | 同行字段运算 | `(high - low) / pre_close * 100` |
| `rank` | 截面排名 | `PCTRANK(amount_yuan)`、`RANK(pct_change, desc)` |
| `crosssec` | 截面聚合 | `close / MEAN(close BY sector)` |

表达式用受限求值器（白名单函数 + AST 校验，禁止属性访问、import、调用任意函数），**不是 `eval`**。可用函数：

```
MA SMA EMA WMA STD SUM MAX MIN HHV LLV REF DIFF SHIFT
ABS LOG SQRT POW SIGN CLAMP IF AND OR NOT
RANK PCTRANK ZSCORE MEAN MEDIAN QUANTILE COUNT
CROSS SLOPE POLYFIT CORR
```

内置指标（`builtin=true`）：MA5/10/20/30/60/120、BIAS5/10/20、CCI、ATR、MACD/Signal/Hist、量比、振幅、换手率、250 日位置。可以停用、可以改参数，不能删。

用户加一个"20 日振幅标准差"只需在页面填：

```
indicator_key = amp_std20
kind    = window
expr    = STD((high - low) / pre_close * 100, 20)
```

保存后下一次加工作业就会算出这一列，且立刻可用于筛选、图表、评分。

### ⑥⑦⑧ 功能点 / 脚本 / 绑定

已在 [04-调度与策略注册表.md](04-调度与策略注册表.md) 详述。这里补充"积木"视角的关键点：

**功能点（capability）是插槽，脚本是插进去的积木，绑定是插的方式。**

一个功能点可以：
- 绑 1 个脚本 → 直接用它的结果
- 绑 N 个脚本 → 按 `weight` 加权合成（权重归一化，停用一个自动补齐）
- 绑 N 个脚本按 `display_order` 串联 → 上一个的输出是下一个的输入（流水线）
- 同一脚本绑两次不同 `params` → 参数不同的两个变体

页面上的操作全是拖拽和填数：换实现、调权重、A/B 对比、临时停用某个子因子、加一个自己写的脚本。**没有一步需要改代码或重启。**

脚本的 `param_schema`（JSON Schema）驱动前端**自动生成参数表单**——加新策略连前端都不用动。

### ⑩ config.screen_rule · 筛选条件类型

筛选器的"条件类型"本身也是注册表，不是硬编码的 5 种。

```sql
CREATE TABLE config.screen_rule (
    rule_key   text PRIMARY KEY,         -- 'between' | 'topn' | 'cmp' | 'consecutive' | 'belongs'
    name       text NOT NULL,            -- '数值区间'
    param_schema jsonb NOT NULL,         -- 前端表单据此生成
    sql_template text NOT NULL,          -- 带占位符的 SQL 片段
    enabled    boolean NOT NULL DEFAULT true
);
```

内置 5 种（沿用旧系统已验证的语义）：数值区间、排名 TopN、字段比较、连续 N 日、归属集合。

加第 6 种（比如"N 日内出现过涨停"）只需插一行：

```
rule_key     = had_limit_up
param_schema = {"days":{"type":"integer","default":5}}
sql_template = EXISTS (SELECT 1 FROM market_data.stock_daily x
                       WHERE x.security_code = d.security_code
                         AND x.trade_date BETWEEN :d - :days AND :d
                         AND x.close >= x.limit_up - 0.001)
```

`sql_template` 由后端做占位符参数化绑定，不做字符串拼接，且只允许出现在 WHERE 片段位置。新增规则需 `admin` 角色。

用户组合出的条件集存 `config.screen_preset`，可命名、可分享、可被作业引用做定时筛选并推送。

### ⑪ config.chart · 图表

图表类型与配置也是数据。

```sql
CREATE TABLE config.chart (
    chart_key  text PRIMARY KEY,         -- 'kline_vol' | 'sector_heat_bar'
    name       text NOT NULL,
    chart_type text NOT NULL,            -- candlestick|line|bar|hist|scatter|heatmap|pie|table
    data_query text NOT NULL,            -- 命名查询 key 或 SQL（只读校验）
    encoding   jsonb NOT NULL,           -- {"x":"trade_date","y":["close"],"color":"quadrant"}
    options    jsonb NOT NULL DEFAULT '{}', -- 标题/图例/双轴/色阶/分箱边界
    params     jsonb NOT NULL DEFAULT '{}', -- 可暴露给用户的筛选参数
    enabled    boolean NOT NULL DEFAULT true
);
```

页面能做：改配色、切图形（折线↔柱状）、换 X/Y 字段、加参数下拉、复制一个图表改成新的。

统一约定固化在代码里（涨红跌绿、固定分箱边界、固定色阶、空数据明确提示），这些是保证跨日可比的底线，不开放配置。

### ⑬ config.page_layout · 页面布局（拖拽积木）

这是"积木城堡"最直观的一张表：页面由卡片拼成，卡片位置和内容都存库。

```sql
CREATE TABLE config.page_layout (
    layout_id  bigserial PRIMARY KEY,
    page_key   text NOT NULL,            -- 'home' | 'review' | 'my_board'
    slot       int NOT NULL,             -- 顺序
    width      int NOT NULL DEFAULT 6,   -- 12 栅格
    height     int NOT NULL DEFAULT 320,
    card_kind  text NOT NULL,            -- stat|chart|table|score_panel|task_list|markdown|iframe
    card_ref   text,                     -- chart_key / 命名查询 key / 指标 key
    title      text,
    options    jsonb NOT NULL DEFAULT '{}',
    visible    boolean NOT NULL DEFAULT true,
    UNIQUE (page_key, slot)
);
```

页面进入"编辑模式"后：拖动排序、拉宽窄、换卡片内容、隐藏、新建自定义看板（`page_key` 自取）。保存即写表，刷新即生效。

`card_kind` 是代码提供的积木类型（7 种够用），`card_ref` 指向其他注册表的行——积木之间靠 key 组合。

还有一张 `config.menu` 控制导航菜单本身（哪些页面显示、顺序、图标、是否需要权限），这样连"有哪些页面"都能配。

## 页面：/blocks 积木管理中心

所有注册表的统一入口，一个页面十三个 Tab：

```
┌─────────────────────────────────────────────────────────────────┐
│ 积木管理  数据源 字段 数据集 校验 指标 功能点 脚本 绑定           │
│           作业 筛选 图表 推送 布局 菜单                          │
├─────────────────────────────────────────────────────────────────┤
│  [+ 新增]  [导入 JSON]  [导出 JSON]  [恢复默认]  [变更历史]      │
├─────────────────────────────────────────────────────────────────┤
│  表格：key | 名称 | 状态 | 被谁引用 | 最近修改 | 操作            │
│  行点击 → 右侧抽屉编辑（表单由 param_schema/字段类型自动生成）    │
├─────────────────────────────────────────────────────────────────┤
│  编辑抽屉底部固定三个按钮： [校验] [试跑] [保存]                  │
└─────────────────────────────────────────────────────────────────┘
```

四个通用能力，每张注册表都有：

**校验** — 保存前检查：引用的 key 是否存在、表达式能否解析、SQL 能否 EXPLAIN、依赖有没有成环、权重和是否合理。不通过不让存。

**试跑** — 指定一个交易日 + 小范围标的，立刻算给你看，结果只回显不落库。改权重、改指标公式、改筛选条件都能先看效果。

**被谁引用** — 反查依赖。想停用一个脚本，先看它被哪些功能点绑着；想删一个指标，先看哪些图表和筛选在用。避免删出一地空引用。

**变更历史 + 回滚** — 所有 `config.*` 表的写操作由触发器记进 `operations.config_history`（存变更前后的完整行 JSON）。改错了一键回滚到任意历史版本。

```sql
CREATE TABLE operations.config_history (
    id        bigserial PRIMARY KEY,
    occurred_at        timestamptz NOT NULL DEFAULT now(),
    actor     text NOT NULL,
    table_name text NOT NULL,
    row_key   text NOT NULL,
    op        text NOT NULL,             -- INSERT|UPDATE|DELETE
    before    jsonb,
    after     jsonb
);
```

**导入/导出 JSON** — 整套配置可以导出成一个文件。用途：备份、在另一台机器复现、把一套调好的因子配置分享出去。

## 分层：什么能配，什么不能

不是所有东西都该开放。开放过度会变成"页面上能把系统点坏"。

| 层级 | 内容 | 谁能改 |
|---|---|---|
| **锁定** | 二进制解析器、数据库 schema、单位换算规则、涨跌红绿、任务执行引擎 | 只能改代码 + 迁移 + 测试 |
| **受保护** | 字段口径注册表、校验规则、筛选规则的 SQL 模板、DDL 类操作 | `admin` 角色，页面上可改但要二次确认 |
| **开放** | 权重、参数、cron、标的范围、指标公式、图表配置、页面布局、推送 | 普通登录用户，随便改 |
| **个人** | 自选分组、筛选预设、自定义看板 | 各自管理 |

划这条线的理由：**锁定层错了整个系统的数据就不可信**（比如解析器改错，全库数据报废）；开放层错了只影响当次结果，而且有试跑和回滚兜底。

## 落地顺序

不需要一开始就把十三张表都做出来。按"改动频率 × 实现成本"排：

| 优先级 | 注册表 | 理由 |
|---|---|---|
| P0 | ⑥功能点 ⑦脚本 ⑧绑定 ⑨作业 | 用户明确要求的"功能点↔脚本可自定义" |
| P0 | ②字段口径 ④校验规则 | 数据可信的前提，没有它上面全是空中楼阁 |
| P1 | ⑤指标 ⑩筛选 | 日常调整最频繁 |
| P1 | ①数据源 ③数据集 | 路径/阈值变更时立刻用得上 |
| P2 | ⑪图表 ⑬页面布局 | 体验层，前期用固定页面也能干活 |
| P2 | ⑫推送 | 有了结果才需要推 |

P0 完成时系统已经是"积木"了；P1 完成后日常运营基本不用碰代码；P2 是让它变成"城堡"。
