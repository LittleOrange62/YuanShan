## 这是什么

YuanShan 把 A 股短线研究里每天重复的动作收在一台机器上：把行情采下来、把判据算好落进数据库、在本地网页上看榜单和复盘、需要时让 AI 读材料做解释。

**两层拼装，一条边界。** 产品底座是 vibe-astock v1.1.0（Apache-2.0，官方 OpenAI Codex Harness、复盘、辩论、回测、AI 接入都在这一条线上）；本仓库在它之上加了一层**本地数据真资产**：PostgreSQL 库 + `ingest/` 采集作业 + `app/compute/` 判据计算 + `duanxian/*_view.py` 只读读数层。边界是：**页面上榜单里的数字都来自这台机器自己的库**，不在请求时现打外部接口。

数据、程序计算、人工记录和 AI 解读分别呈现。行情与统计不由 AI 生成；AI 用于解释材料、对照不同观点、整理待验证条件。情绪分档是分析框架，不是客观事实，也不能由某一个指标直接推导交易结论。

## 数据从哪来，落到哪

### 采集：本机作业，一条通道一份边界

| 采什么 | 走哪条通道 | 边界（坏了会怎么说） |
|---|---|---|
| 日线 | 通达信本地 `vipdoc/*.day`；第二条腿是登录着的客户端的 TQ 本地接口 | 客户端没在跑就没新数；接口失败点名来源，不冒充全市场 |
| 1 / 5 分钟线 | 通达信 `*.lc1/*.lc5` 盘后下载 | 这条依赖桌面窗口，无人在场的时段会失败；当天没落盘就永久缺那一天 |
| 收盘快照（市值、PE、PB） | 本地快照表 | 缺项交 `NULL`，不按 0 参与排名 |
| 板块日线与成分、板块资金 | 通达信 880 / 881 系列 + 东财板块对表 | `880001~880099` 是市场级统计指数，不是板块，不混进板块榜 |
| 大盘资金流（主力/超大单/大单/中单/小单） | 东财 datacenter 接口 | 一次给回看若干交易日；域名换或不通时点名来源 |
| 个股主力资金流排行 | **新浪，本机唯一一条**（旧东财 push2 通道实测每 5~6 个请求就断） | 报文没有日期字段，**一天不采就永久少一天**，补不回来 |
| 龙虎榜、两融、ETF 份额、分红、股本 | 公开接口 | 逐源记覆盖率与缺日 |
| 财务多期（累计 + 单季） | 同花顺 | 基期近零时源能给到荒谬比率，读侧封顶并交 `NULL`，且**报名字** |
| 快讯 | 30 秒轮询落本地 jsonl | 只落盘，不承诺逐条 |
| 自选 / 持仓名单 | 同花顺 `stockblock.ini` 镜像 | 默认以 ini 为准全量覆盖；未认出的市场号点名而不是静默丢弃 |

**价格口径**：判据一律用后复权价（`close × adjustment_factor`，跨除权日连续），不读日线里那列未复权的 `pct_change`；涨跌幅按**市场场次数**往前数，不按这只票自己的 K 线根数，停牌那天没有行就空着，不拿更早或更晚的一天冒充。

### 每日加工链：一条命令 42 步，算好的东西落表

`ingest/jobs/e1_fill_all.py` 的 `STAGES`（2026-10-22 实测 **42 步**，步数随判据增加而涨，现查为准）：

```text
tdxdl daily snapshot breadth sentiment voldbl breakout ambush volratio startupvol
spike sysentry trendstock boardnode abnormalmove qd_ladder qd_sentiment qd_sector
etf margin lhb fundflow fundflow_rank sectorflow boardlink dividend share financials
fbshape fbdaily quadtrack spikedays indicators scores sectortrend ignition scoretrend
signal flowtrend allocator confluence quality
```

开头几步取数与入库，中间是各榜判据（倍量、突破、埋伏、启动前量能、盘中异动、交易体系三条件、趋势股、板块节点、异动提醒、qd 对照轨……），`indicators` / `scores` / `sectortrend` 是骨干步（下游依赖它们的产出），末尾 `confluence` 把六份榜并成交叉命中榜、`quality` 出质量闸结论。回算与单步补跑都在这一条命令上：`-m ingest.jobs.e1_fill_all --only <步名>`，每一步自己记账（跑没跑、跑了几场、失败原因）。

### 这套榜单为什么可信：四条纪律

1. **先算好落库，页面只读行**。读侧不现算重聚合，所以半年 123 场、672 行的名单一次现算约 8 秒，命中进程内缓存时 0.29 秒交出（今天实测）。
2. **每张判据表主键带 `spec_version`**。口径改版就升版本号、旧行留着可对照，而不是覆盖后无从追溯。
3. **缺数是 `NULL`，不是 0**。不按 0 参与排名（否则「没数据」会被排成「很差」）；界面显示 `—`；探测函数坏了不许兜成空值——空值会被下游写成一句很合理的假读数。
4. **每个数字的口径只写一份**，列头悬停和默认收起的说明框都读那一处；屏幕上不念机器码（内部标识符一律有中文标签）。

### 本机数据现实（2026-10-22 现查）

- PostgreSQL 17 / 库 `financetool`，**7 个业务 schema、221 张基表**：`market_data` 85、`analytics` 54、`config` 24、`ys` 19、`operations` 15、`reference_data` 15、`qd` 9。
- `market_data.stock_daily`：**2021-08-02 ~ 2026-10-21，1,263 个场次，6,452,485 行**。
- DDL 51 份在 `app/db/sql/`，校验和登记在 `operations.schema_migration`（**没有迁移执行器**，实跑姿势见《数据加工工作指南》04）。
- HTTP 路由：`server.py` 55 条，启动时再把 `vr/app.py` 的 138 条 `/api/*` 并进来（`/api/chat` 除外，它由本仓库自己实现）。接口一律 `{"data": …}` 包衣，不可用时老实交 `available:false` 加原因。

## 每天怎么自己跑起来

不用人敲。在册 **12 条常驻循环**，服务启动时起 11 条（盯盘轮询按需：第一次有人订阅实时帧才起）；每条都有开关、时点、台账，在「任务调度」页和 `scripts/jobs.py status` 都能看和改。

| 循环 | 干什么 | 备注 |
|---|---|---|
| 收盘链 | **15:59 起跑**，两阶段：获取段（拉数入库）→ 加工段（那 42 步） | 只在真实交易日跑，判据是行情时间戳自证那一层；段内重试上限 5 次 |
| 失败单步重试阶梯 | 默认 21:00 / 22:00 / 23:00 / 01:00 / 02:30 / 04:20 | **只重试点里失败的步**，时点可增删，用完就放弃并留账 |
| 数据库备份 | 每月 1 号全库 + `pg_basebackup`、周六周日全库、其余核心 schema | 库里是这台机器唯一的真资产；备份带恢复验证 |
| 盘中快照 | 分时 / 榜单槽位 | 过了那个点就永远没有这张快照，补不回来 |
| 快讯采集 | 30 秒一轮 | 停了只是不再新增，已落盘的历史不受影响 |
| 个股资金流（新浪） | 每日一次 | 当天不采就永久少一天 |
| 同花顺自选同步 | ini → 库内镜像 | 默认全量以 ini 为准 |
| 同花顺云端同步 | 启动客户端 → 等 ini 落盘 → 收掉自己起的窗口 | **默认关**：它动桌面上的窗口，第一次要人在键盘前手动演练过才开 |
| 通达信看护 | 探测客户端在不在跑、收赖着的进程、按阶梯判「全不全」后关窗 | 只探测；自愈动作另有闸 |
| 覆盖体检预计算 | 把首屏那些重聚合提前算好落缓存 | 没有它首屏要现场等几十秒 |
| 消息推送 | 每 60 秒扫一遍计划表，到点按选中的内容发飞书 / 钉钉 / 企微 / 邮件 | 内容复用页面上那些读数块；机器人回 HTTP 200 不等于送达，按回体判 |
| 盯盘轮询 | 3 秒一帧的实时快照与异动 | 按需起，没人盯盘的夜里本来就不该在 |

另有两处兜底：Windows 计划任务 `YuanShan-KeepAlive8910` 负责服务挂了拉回来（看门狗只启动、不杀进程）；`scripts/manage.py doctor` 有 **17 项检查（9 项硬失败 + 8 项只报告）**，其中「常驻循环完整性」直接读上面那张注册表，所以页面、体检、台账是同一份清单——**一条循环写着但没接线，会被体检点名**，而不是安静地假装在跑。

动界面、出网、消耗额度这三类动作一律有确认框或默认关；判据「没跑成」必须出声，不许兜成一句合理但假的读数。

## 复盘与回测

**复盘**按已有涨停样本整理情绪、资金、题材、龙虎榜和龙头跟踪五个分项，再汇总依据与待验证条件。选择目标交易日后生成，可以选尚未生成报告的日期；页面区分所选日期、当前报告的交易日和生成时间，不会把已有报告的日期冒充新选择。各路取数显示当前类别，单路等待上限 90 秒并受整场剩余时间约束，超时或取消会清理对应进程；生成失败保留旧稿，同日重新生成保存新版本，补做较早日期不会把最新报告倒退。新报告可展开「查看依据」，数字展示与比较由程序处理，AI 解释受引用校验约束。

历史场次随时能看：读取的是当时的定稿记录与已保存快照，错过的历史盘中时点不能靠当前行情补造。旧稿保留原样，不因升级自动获得新的校验结论。

**回测**用于检查明确的历史规则：输入条件 → AI 整理可执行范围 → 用户确认 → 确定性引擎计算 → 本地报告。AI 不替用户决定当前如何交易。报告按支持范围披露市场规则、数据区间、费用、成交与未成交原因，零成交也如实显示；没有数据或暂不支持的条件会说明限制，不用模拟结果伪装实测结果。

**历史统计不等于收益**：按已有涨停样本观察的次日表现存在选择偏差，样本统计不能当成实际可成交收益；按结果筛过的分组里那些「率」是同义反复，只有回到不筛结果的母体才谈得上预示。历史表现不能保证未来结果。

交易日志是持仓与已实现结果的基础（自选是手动观察列表，不是另一份账）；没填写风险边界的持仓单列，已知部分不冒充完整账户风险。行情缺失显示为不可用，汇总注明不完整，不把缺行情算成资产归零。

## 快速开始

环境要求：Python 3.10+（推荐 3.12）、Node.js 22+（含 npm）、PostgreSQL 17（本机端口 5432，库名 `financetool`）。首次准备环境需要联网下载依赖。

Windows 10/11 双击 `启动 YuanShan.cmd`，或在仓库根目录的 PowerShell / CMD 里：

```powershell
py -3 -X utf8 scripts/manage.py setup
.venv\Scripts\python.exe -X utf8 scripts/manage.py doctor
.venv\Scripts\python.exe -X utf8 scripts/manage.py start
```

macOS / Linux 可双击 `启动 YuanShan.command`，或分步 `sh scripts/setup`、`sh scripts/doctor`、`sh scripts/start`。`manage.py` 只有四个子命令：`setup`（装依赖 + 构建前端）、`doctor`（体检）、`start`（起服务）、`auto`（供计划任务调用的无界面启动）。

默认地址 `http://127.0.0.1:8910`。换端口在 `start` 后加 `--port 8911`。停止用 `scripts/stop.py`（**先 `--dry-run` 预览会打到谁**：它会按启动器 → 看护树 → 端口占用者的顺序收，绝不按镜像名批量杀）。

**网络边界**：绑定地址与来源白名单的唯一来源是 `netconfig.py`，配置落在 `<ASTOCK_DATA_HOME>/net/config.json`（`lan_enabled` + `allowlist`），不落 PG。默认只监听回环；勾选局域网访问后**必须重启才生效**（绑定地址在启动时决定），白名单是那道唯一的门（本项目没有 API key）。改边界只能从回环改——能被加白的那台机器自己给自己加白，这道闸就等于没有。

数据库连接与凭据走 `.env`（`FT_DSN_ADMIN` / `FT_DSN_APP` / `FT_DSN_ETL` / `FT_DSN_READER` 四只角色，读写分离；跑长查询用 reader，它有 60 秒语句超时兜底）。写库语句必须显式走 etl 角色。**`.env` 里是口令，不要提交、不要贴进日志或截图。**

源码更新前停止服务并备份下节列出的数据；更新后重新运行 `setup` 与 `doctor`。改完前端后 doctor 的「安装与源码一致」必然转红——那是指纹闸，重跑 `setup` 就复绿，不是功能坏了。

## 接入 AI

网页的 AI 入口共用「AI 探索」里测试保存的来源与模型。页面显示来源不等于当前账户仍能调用，以连接测试和任务结果为准。

| 接入方式 | 当前实现与验证边界 |
|---|---|
| Codex 订阅 | 产品专用 ChatGPT 授权与隔离引擎；已有真实登录、连接及业务运行记录，模型可用性受账户额度限制 |
| Claude 订阅 | 本机官方 CLI 接入，已有真实复盘与辩论记录；需要自己的安装、登录和有效订阅 |
| WorkBuddy / CodeBuddy | 使用本机 CLI 登录；上游本次仅实测 macOS WorkBuddy 内置 CodeBuddy CLI 2.137.1 的连接、受控工具、普通对话与单日完整复盘流程 |
| OpenAI API | 使用用户自己的配置；不以订阅测试代替 API 实测 |
| new-api 网关 / OpenAI 兼容模式 | 面向只有 Chat Completions 的端点：本机后端在回环上把引擎的 Responses 请求改写成聊天调用，再把流式结果与工具调用还原回 Responses。可以是本机或内网 IP 的明文 http（页面会提示这不加密），公网地址仍要求 HTTPS。服务商密钥只发给本机后端，不进引擎子进程 |
| DeepSeek / MiMo / 智谱 / Kimi / 通义 / 硅基流动 / MiniMax / OpenRouter / Groq / Together / 自定义 | 提供可编辑的地址与模型预设；**预设不代表兼容性已验证**，这类地址必须支持 Responses API 与工具调用 |

Agent 默认关闭：普通聊天不启用工具或联网。开启后适用入口才使用它允许的证据或公开数据工具。生成复盘、辩论和回测仍需明确发起，不由开关自动执行。AI 配置没有弹窗，入口都直接进本页。

**「这个不通自动用下一个」默认开启**：同一条来源连续失败 2 次才判定不通并让位，列表顺序就是优先级；切换只发生在下一次任务开始前，已有会话仍锁定它当初的来源。上下文超限、本机存储被禁、后端访问密钥缺失不算来源故障，不因此切换。

页面右侧的「AI 分析」是按需研究通道：每屏可以把自己那一叠读数交给模型解读，材料边界与红线只住一处实现；话术做成「类型 + 可选模板」，可在系统配置里改，但「不给点位、不对个股做前瞻判断」那段是硬约束、删不掉。会话档案存在本地 PostgreSQL 的 `ys` schema（19 张表，2026-09-25 从本机 SQLite 迁入；旧库文件原样留作只读备份，旁边有 `.migrated.json` 记下搬了多少行）。分类是确定性关键词规则、不调用模型，规则上线前的旧会话显示「未分类」，不回填猜测值。跨会话的记忆/召回尚未实现，且既有裁定是只供用户自己检索、不注入 prompt。

**本机构建的密钥风险（发版前必读）**：`frontend/src/lib/ai-access.ts` 的 `LOCAL_GATEWAY` 预填了内网网关的地址、模型与密钥，「接入 AI」打开即预选该来源。**密钥会随 `npm run build` 进入 `frontend/dist` 的静态 JS 文件**，任何能读到该文件（包括局域网访问 8910）的人都能拿到它。分享源码、提交仓库、或把服务暴露到回环以外之前，请把 `LOCAL_GATEWAY.key` 清空再构建。

所有网页 AI 来源均附加研究约束；普通聊天与报告路径对明确交易建议进行检查，证据回答另有引用和数字核对。这些检查能减少越界与错引，**不构成完整语义正确性保证**。产品不输出投资决策、买卖建议或仓位指令。

## 数据与隐私

| 数据 | 默认位置与注意事项 |
|---|---|
| **PostgreSQL 业务库**（行情、判据、榜单、质量闸、作业台账） | 本机 `financetool`；备份策略见上一节，**这是这台机器唯一不可再生的资产** |
| Agent 会话、任务、证据账本 | `~/.vibe-astock-agent/`，可用 `ASTOCK_AGENT_HOME` 改根目录 |
| 复盘、版本、交易日志与原始归档 | `~/.duanxian-agents/`，可用 `ASTOCK_DATA_HOME` 指定绝对路径 |
| 市场资料、盯盘缓存、作业配置与状态、网络边界配置 | `~/.vibe-astock-agent/market-data/`（`VR_DATA_DIR` 可单独指定）；作业配置与状态在数据根下 `jobs/`，**不放 `.local/`** |
| 通达信本地文件（日线/分钟线来源） | `.env` 的 `FT_TDX_DIR` 指向客户端安装目录 |
| 自选真源 | 同花顺 `stockblock.ini`（本机文件，界面里那份是它的镜像） |
| 研究记录、界面状态 | 当前浏览器站点的 localStorage——**库的备份不含它**，换浏览器或清站点数据会丢，要留就导出 |
| 开发日志与运行诊断 | 仓库 `.local/`，不进版本控制，也不随备份走 |

这些位置不由一个开关统一迁移：改 `ASTOCK_DATA_HOME` 不会自动搬走浏览器数据。分享日志前检查个人信息；不要将私人记录、API key 或登录文件提交到仓库。本地网页仍需要联网取数；使用远程 AI 时，问题、所选材料和必要上下文会发送给用户选择的供应商——不能把「本地保存」理解为「所有计算都离线」。

## 验证范围

以下全部是 **2026-10-22 在本机实测**的读数，不是承诺：

```bash
.venv/Scripts/python.exe -X utf8 -m pytest tests backtest/tests research_data/tests -q --tb=no
node --test frontend/test/*.test.ts          # 从仓库根跑；从 frontend/ 里跑等价写法是 test/*.test.ts
npm --prefix frontend run build              # tsc -b && vite build，类型错在这一步就拦
.venv/Scripts/python.exe -X utf8 scripts/manage.py doctor
```

- 后端全量：**3,294 passed / 8 skipped / 16 failed**（用时约 20 分钟）。这 16 条是本轮基线名单，不是新问题：`test_subscription_bridge` 8 条、`test_core_logic` 3 条、`test_agent_access` / `test_full_audit_fixes` / `test_sysboard` / `test_intraday_spike` / `test_startup_quadrant_track` 各 1 条（多为计时、子进程、读源码那族的偶发项）。**判是否回归只认失败名字集合逐条比对，不认红数本身**；名字集合与基线一致才算干净。
- 前端：**737 条全绿**（含导航、路由、口径展示规范、排序键、说明框不套折叠、屏幕上不念机器码那类文档型断言）。
- 体检：**17 项，9 项硬失败参与退出码，8 项只报告**（备份新鲜度、当日数据到位、采集作业、收盘链开关、界面动作待人工、常驻循环完整性等）。
- 端到端：接口用 `curl` 实打并检查响应体能被 `JSON.parse`（出现 `NaN` 说明出口清洗漏了字段）；页面用浏览器逐列点击实测排序、逐屏数渲染后纯文本里的裸 `**`、双击跳转实测。

上述结果不代表所有供应商、所有 Windows 实体机型、Linux 全流程或连续完整交易日都已验收；不代表任何收益承诺。已知的本机边界包括：分钟线在无人时段可能失败、个股资金流缺日不可回补、板块成分表没有时点（拿今天的名单回看历史就是未来函数，因此不能作为判据）。
